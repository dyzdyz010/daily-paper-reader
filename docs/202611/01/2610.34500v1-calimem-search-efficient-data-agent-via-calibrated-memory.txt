## ABSTRACT 

Data curation is a first-order design choice in machine learning, yet tailoring training data to a downstream model and task remains costly in labor, expertise, and compute. Datasets are therefore often processed through fixed pipelines and reused across applications. We show that this assumption is fragile: across 55 dataset–model tasks spanning biological domains, the same curation recipe can help one model while hurting another. Effective curation must adapt to the down-stream setting, motivating automated search over data recipes. We first build an agentic system that searches for curation policies at deployment, improving data utility via test-time curation (TTC) . Although achieving performance gains, its search is driven largely by recent feedback and remains local. Adding persis-tent memory helps the agent retain evidence across iterations and reveals a deeper problem: it forms claims that extend beyond the conditions in which they were ob-served, sometimes abandoning an entire strategy after a single unsuccessful trial. To address this problem, we introduce C ALI MEM , a calibrated-memory agentic loop that requires the agent to predict the outcome of each proposed policy before executing it. Comparing this prediction with the observed result gives the agent a 

reality check on the claims behind its proposal. It uses the prediction error to retain supported claims, revise mistaken ones, and specify the conditions under which a conclusion holds. This makes the agent’s beliefs testable, reduces overgeneral-ization, and supports more effective long-horizon exploration. Across biological and LLM post-training tasks, C ALI MEM consistently outperforms fixed curation baselines and published methods, and exceeds full-data training by up to 19.4%. Code is open-sourced 1.

## 1 INTRODUCTION 

How a training set is constructed determines what a model learns and how efficiently it learns it. Data curation has accordingly grown beyond cleaning into a broad design space: removing redundant or low-value examples, selecting data for targeted capabilities, and setting the mixture of sources (Lee et al., 2022; Xie et al., 2023a; Xia et al., 2024; Wu et al., 2024; Chen et al., 2026). Tailoring these choices to a downstream model and task, however, demands expertise and repeated training runs. In practice, datasets are often processed through fixed pipelines and reused across applications. Such pipelines support consistency and reproducibility, but a curation choice that benefits one down-stream setting need not benefit another .This limitation is particularly evident in biological data, where data preparation commonly follows established workflows for single-cell transcriptomics (Luecken & Theis, 2019; Heumos et al., 2023; Luecken et al., 2022), protein variant-effect prediction (Notin et al., 2023), and non-coding variant-effect prediction (Marin et al., 2024). These workflows establish useful standards, but they do not establish which curation choices best serve a particular downstream application or model. On one batch-integration dataset, for example, a recipe ranks 1st for cVAE (a variational autoencoder that conditions its decoder on the batch label) but 11th for MMD-AE (an autoencoder trained with a distribution discrepancy penalty between batches (Figure 1a). Averaged across recipes, standard curation performs no better than selecting a random subset of the same size. Effective curation there-fore calls for searching for a policy suited to the downstream setting. The potential reach of such search extends beyond biology: data selection and mixing also shape language-model pretraining, instruction tuning, and vision-language training (Xie et al., 2023a; Xia et al., 2024; Wu et al., 2024). Generalist coding agents can carry out machine-learning experiments end to end (Chan et al., 2024; Karpathy, 2026; Rank et al., 2026), making data curation a natural target for automated search. Following the propose–evaluate–revise setting of Curation-Bench (Kang et al., 2026), we build an agent that searches for curation policies at deployment, improving data utility via test-time curation (TTC) . Given a candidate data pool, a selection budget, and a fixed training and evaluation pipeline, it proposes a policy, trains on the selected subset, observes the evaluation score, and decides what to try next. The agent improves data utility, but its trajectories are strongly driven by recent feedback. It often changes one policy setting at a time and uses the latest score change to choose its next move (e.g., Table 1). This local search can miss interactions among choices and underuse evidence accumulated earlier in the trajectory. To help the agent learn from its full trajectory, we add persistent memory (Shinn et al., 2023). The memory records executed policies and their outcomes as evidence, alongside the agent’s claims about what that evidence means. Retaining these claims makes a deeper failure mode visible: the agent frequently states conclusions substantially beyond what its experiments warrant. For exam-ple, adding class rebalancing to a confidence-filtered policy lowers performance, and a memory-only agent concludes that rebalancing does not help (Figure 2). The experiment establishes only that this particular combination failed under the tested conditions. It does not explicitly rule out rebalanc-ing with a different filter, setting, or policy; though, the broad claim persists in the agent’s belief essentially prevents the agent from revisiting the strategy. We introduce C ALI MEM , a calibrated-memory loop that subjects such claims to an empirical reality check . Before executing each proposed policy, the agent predicts its outcome from the evidence and claims in memory. After evaluation, it compares the prediction with the observed score. This gap reveals when the agent’s understanding of a policy was mistaken, even if the policy itself improved performance. The agent then retains supported claims, revises mistaken ones, or limits them to the conditions under which they hold. In the rebalancing example, an unexpected loss directs attention to its interaction with the confidence filter rather than ruling out rebalancing altogether. The resulting claims are more carefully qualified and provide a stronger basis for long-horizon exploration. We evaluate C ALI MEM on the 55 biological dataset–model tasks and on LLM post-training tasks. It improves agentic search, outperforms fixed curation baselines and published methods, and, in the strongest setting, exceeds full-data training by up to 19.4%. Our contributions are threefold: (i) we show that standard curation recipes have sharply different effects across downstream models and tasks; (ii) we identify local feedback-driven search and overgeneralized memory claims as limita-2Preprint tions of agentic curation; and (iii) we develop C ALI MEM , which uses predictions and their errors to keep the agent’s claims grounded in observed evidence. 

## 2 RELATED WORK 

Data curation. Filtering and deduplication (Lee et al., 2022), target-aware sample selection (Wang et al., 2025a; Xia et al., 2024; Wu et al., 2024; Ivison et al., 2025), and optimization of data-source mixtures (Xie et al., 2023a; Ye et al., 2025; Liu et al., 2025a; Chen et al., 2025; 2026) all im-prove training data; see Albalak et al. (2024) for a survey. A recurring lesson is that there is no context-free “best” data: selection rankings change with pool, budget (Ivison et al., 2025), and com-pute (Muennighoff et al., 2023; Goyal et al., 2024). The same dependence appears in scientific workflows. Preprocessing choices in single-cell pipelines (e.g., normalization, feature selection) in-teract and shift downstream results (Vieth et al., 2019; Germain et al., 2020; Luecken et al., 2022). This dependence motivates test-time curation (TTC) : the agent searches the policy space against the downstream pipeline at deployment rather than committing to one recipe in advance. 

Agents for machine-learning research and data work. Large language model (LLM) agents in-creasingly carry out iterative machine-learning experimentation, from bounded machine learning tasks to open-ended research engineering (Huang et al., 2025a; Chan et al., 2024; Wijk et al., 2025; Rank et al., 2026). Agents have also been applied to discovering dataset problems, data standard-ization, web collection, and general data-science workflows (Huang et al., 2025a; Thirukovalluru et al., 2025; Zhang et al., 2026a). Closest to us, Kang et al. (2026) place a generalist agent in a fixed train–evaluate loop for data refinement; Du et al. (2026) broaden autonomous data engineering with tree-structured search and global memory. We take the curation loop itself as given and focus on a complementary question: what does an agent learn about the response of one downstream pipeline over a long search trajectory, and when should it trust what it has learned? 

Memory, self-improvement, and predictive agent state. Persistent-memory methods allow agents to accumulate reflections, experiences, and reusable strategies without changing model weights (Shinn et al., 2023; Zhao et al., 2024; Suzgun et al., 2026; Zhang et al., 2025b). Har-ness optimizers instead evolve prompts or workflows from execution feedback (Khattab et al., 2024; Yuksekgonul et al., 2024; Zhang et al., 2025a). Our scaffold is fixed; what evolves is the agent’s be-liefs about the target task. Predicting before acting connects to model-based agents (Gu et al., 2025; Gkountouras et al., 2025; Richens et al., 2025) and verbalized belief states (Singh et al., 2026). Unlike confidence calibration (Geng et al., 2024), the calibrated object is the set of empirical claims used to choose the agent’s next intervention. Appendix A extends this discussion. 

## 3 CALI MEM : C ALIBRATED MEMORY FOR AGENTIC DATA CURATION 

We build C ALI MEM in three steps, each motivated by a failure observed in the previous one: a basic agent that implements the curation loop (Section 3.2), a persistent memory that lets it use its whole trajectory (Section 3.3), and a calibration step that checks the claims in that memory against measured outcomes (Section 3.4). 3.1 PROBLEM FORMULATION : THE DATA CURATION LOOP 

An automated data-curation agent operates through an iterative propose–evaluate–revise loop (Kang et al., 2026). The agent is given a candidate data pool D, a selection budget B, and a fixed training and evaluation pipeline. At iteration t, it proposes a data policy πt, a program that selects a subset of exactly B examples from D subject to task-specific validity constraints, such as a minimum number of examples per class or per batch (Appendix B.1). The downstream model is trained on this subset under the fixed pipeline and measured on the evaluation split, which produces the score yt = S(πt).

The agent observes yt and proposes the next policy πt+1 . After t iterations, the trajectory 

Ht = {(π1, y 1), . . . , (πt, y t)} (1) holds all the empirical experience available to guide subsequent search. We write π⋆t for the incum-bent , the best policy in Ht, and y⋆t = max i≤t yi for its score. In the default setup, the agent builds on the incumbent: a change is kept if it improves on y⋆ and reverted otherwise (as shown in Table 1). 3Preprint Every run starts from the same seeded random subset as π1 and is allotted T iterations, each costing one full training run; the quantity of interest is y⋆T .

Test-time curation. We refer to this search as test-time curation (TTC): rather than preparing the data once with a fixed recipe, compute is spent at deployment, by retraining the fixed downstream model, to find the subset that serves that model best. The trade is particularly favorable in scientific domains such as biology, where new data come from costly experiments while many downstream models are relatively convenient to train (Appendix B.1). In this context, extracting more utility from an existing pool is then far cheaper than enlarging it. Because the pipeline is fixed, a difference in score between two iterations is attributable to the change in the data policy. 3.2 BASIC AGENT : LOCAL , REACTIVE SEARCH 

We first implement the loop with a basic agent. It receives the goal, the budget, and the commands to submit a subset and to run training and evaluation, together with a minimal protocol that asks it to read its previous results before each move; which policies to try, and how to revise them, is left to the agent. Applied to test-time curation in both the biological and the LLM post-training domains, the basic agent already improves on the random starting subset and, in the biological domains, matches or exceeds the best human-designed recipe chosen separately for each subtask (Basic agent rows of Tables 12 and 13). Its trajectories, however, are dominated by recent feedback. A curation policy consists of a selec-tion strategy , such as allocating the budget across perturbations in proportion to their size, and the 

parameters that implement it, such as thresholds, counts, and weights. Once the agent has found a plausible strategy, it typically holds it fixed and spends its iterations adjusting one setting at a time. Second, a sign describes a move at one point of the policy space, yet the agent records what it learns as a general conclusion; yet whether an effect depends on the other settings, or reverses outside the range tested, cannot be read from a sign. 3.3 HOLISTIC SEARCH VIA PERSISTENT MEMORY 

The basic agent’s exploration is driven by its most recent result and overlooks patterns that its earlier iterations already reveal. Following work on persistent memory for LLM agents (Shinn et al., 2023; Zhang et al., 2025b), we give the agent an external memory to explicitly record what it has tried, what it has measured, what it has concluded, and which it consults before choosing each new policy. 

Evidence and claims. The agent keeps a persistent memory Mt = ( Et, Ct), updated after every iteration and read in full before each decision. The evidence Et records facts: the policies executed so far with their scores, {(πi, y i)}i<t , and facts measured about the pool and the pipeline, such as class counts or batch sizes. The claims Ct record the conclusions the agent draws from this evidence, such as which settings interact, where an effect reverses, and which directions are spent, and are rewritten after each result, Ct

> (πt, y t)

−−−−−→ C t+1 . The next policy is thus informed by the whole memory rather than only local feedback. Compared to the basic agent’s log that records what was tried, the claims record what the agent currently believes it means. For example, in one cell type annotation task, the agent revisited the number of input genes across non-adjacent iterations, reducing it from the default 2,000 to 1,684 at iteration 5 and later increasing it to 2,191 at iteration 10. Because both deviations lowered the score, the memory consolidated these observations into the claim that 2,000 genes was already the best (Appendix C.3). Writing the claims down also makes the agent’s beliefs inspectable, and reading them reveals a second problem. In memory, a conclusion becomes a claim that is read before every later decision, so an overbroad claim steers the rest of the run. Figure 2 (left) illustrates how an overgeneralized conclusion can restrict subsequent exploration: the memory accurately records the performance decrease, but the agent interprets this result as evi-dence that rebalancing is generally ineffective. This conclusion extends beyond the tested configura-tion. Once retained in memory, it guides subsequent decisions and prevents the agent from revisiting rebalancing, potentially excluding configurations that could improve performance. 3.4 CALIBRATED MEMORY : PREDICT , THEN CALIBRATE 

To reduce overgeneralization, C ALI MEM requires the agent to predict each proposed policy’s score from the evidence and claims in memory before evaluation. After evaluation, it compares the pre-dicted and observed scores and uses the discrepancy to reassess the supporting claims. The intuition is that a performance change indicates whether a policy helped, while a prediction error indicates 5Preprint whether its effect matched the agent’s expectations. The agent revises the claims accordingly and uses the updated memory to guide subsequent search. 

1. Predict before evaluation. Before executing policy πt, the agent records a point prediction 

byt, the evidence and claims supporting it, and an outcome that would challenge those claims. This record is fixed before evaluation: byt = bS(πt | Et, C t).

2. Two diagnostics from one evaluation. After observing yt, the agent records (i) the signed pre-diction residual (i.e., prediction error) : rt = yt − byt. A positive residual indicates that the outcome exceeded the prediction; a negative residual indicates that the prediction was too optimistic. We also record (ii) the observed changes relative to the incumbent: ∆t = yt − y⋆t−1. The diagnostics answer different questions. ∆t determines the keep-or-revert decision, subject to the validity checks. The residual rt measures the discrepancy between the expected and observed score. Their incumbent-relative directions show whether the proposal crossed the improvement boundary as expected. A policy can therefore become the new incumbent while still producing a substantial prediction miss. 

3. Revising the claims. The agent uses the recorded prediction, outcome, diagnostics, and sup-porting evidence to rewrite its claims in natural language. The interpretation of residual magnitude is left to the agent: Agreement with a prediction is evidence about the tested configuration, not inde-pendent validation of every claim used to justify it. Conversely, a discrepancy prompts reassessment but does not by itself identify the cause: the agent must consider the executed policy, the available observations, and possible variability in the measured outcome. As a result, with C ALI MEM , the claims in memory carry the conditions under which they were observed, as in Figure 2 (right), and a failed variant narrows a mechanism instead of closing it.

## 5 UNDERSTANDING CALI MEM ’S SEARCH BEHAVIOR 

The main results show that C ALI MEM finds stronger policies with the same experimental budget. We next investigate why. First, we test whether its calibrated memory generalizes beyond summa-rizing past experiments by asking it to predict the outcomes of curation interventions it has not yet seen (Section 5.1). Second, we ablate persistent memory and prospective prediction to isolate their contributions (Section 5.2). Finally, we compare the adaptive policies found by the agent with fixed biological curation recipes to understand where adaptation provides its advantage (Section 5.3). 5.1 DOES THE MEMORY PREDICT UNSEEN CURATION INTERVENTIONS ?We test whether C ALI MEM ’s memory captures reusable structure rather than merely summarizing past experiments. After iteration k, we freeze the memory and give it to a fresh agent, which predicts the scores of policies executed later in the original trajectory without seeing their outcomes. The other domains show the same two patterns (Appendix E).

5.3 COMPARISON WITH FIXED BIOLOGICAL CURATION PIPELINES 

Figure 8 breaks the fixed-recipe comparison down to individual recipes. The same classes of inter-vention (quality filtering, balancing, stratification, coverage, difficulty-based selection) help in one setting and hurt in another, so no recipe in our set transfers uniformly across datasets and models. In aggregate (Table 12), the mean recipe is below full data in most domain, and even a per-task oracle closes only a small part of the gap. Test-time curation searches beyond this fixed menu: the agent alters thresholds and allocations, combines mechanisms, changes representations, or writes new policies in response to the measured pipeline. Notably, many of its strongest policies build on the same heuristics (Appendix B.2). Their value is conditional on the downstream model and on interactions with the rest of the policy–the search supplies the adaptation a fixed recipe cannot. 

Finding: The limitation of fixed curation is not a lack of useful heuristics, but a lack of adaptation. Standard biological pipelines contain valuable prior knowledge, yet their effects vary across downstream models. Test-time curation turns those heuristics into a searchable policy space, and C ALI MEM uses calibrated memory to explore that space more reliably. 

## 6 CONCLUSION 

Data curation is usually done once, with a fixed recipe, and reused. Across 55 dataset–model tasks in biological domains, we found this practice non-ideal: the same recipe helps one frozen model and hurts another, and averaged over recipes it is no better than a random subset of the same size. We therefore treated curation as agentic search carried out at deployment against the fixed down-stream pipeline, test-time curation. A basic agent already improves on every fixed baseline. Adding persistent memory lets it use its whole trajectory and exposes a deeper failure: claims that reach beyond their evidence and steer the rest of the run. C ALI MEM makes every claim answerable by requiring a prediction before each experiment and writing the prediction error back into the claims. The resulting agent substantially improves on the basic agent in 47 of 48 models, exceeds full-data training by up to 19.4%, and reaches the basic agent’s final score in a third of the iterations or fewer. 

Limitations and future work. 1. Noise in single-run feedback. Each iteration is a single training run, so the score the agent reacts to, and the prediction error it learns from, carry run-to-run noise. 2. 

9Preprint 

Cost of test-time curation. Test-time curation exchanges computation for data utility. Our budgets are practical in the settings studied here, but they would be expensive for substantially larger models or training recipes. Cheaper proxy models, early stopping, learned surrogates, and adaptive alloca-tion of the budget could all reduce the cost. A natural extension is an agent that predicts and decides 

which experiments are worth paying for . 3. From curation policies to scientific hypotheses. Con-necting the agent’s empirical claims to explicit hypothesis testing, uncertainty-aware experimental design, and review by domain experts is future work, and it matters most where curation decisions guide the acquisition of new experimental data. 10 Preprint

## ETHICS STATEMENT 

All datasets used in this work are public research benchmarks used under their released terms: the deep mutational scanning assays of ProteinGym, the non-coding variant sets distributed by BEND (ClinVar, an IGVF reporter assay, and GRASP against 1000 Genomes), the scIB single-cell atlases, the PerturBench screens, and the Tülu 3, LESS, and OpenCodeInstruct instruction-tuning pools. ## A EXTENDED RELATED WORK 

Data selection, mixing, and biomedical pipelines. Example-level methods select training data using deduplication (Lee et al., 2022), importance resampling toward a target distribution (Xie et al., 2023b), gradient-based influence for instruction or vision-language tuning (Xia et al., 2024; Wu et al., 2024), representation-based scores (Ivison et al., 2025), or pruning metrics motivated by data scaling (Sorscher et al., 2022). Mixture methods estimate how performance responds to source proportions, sometimes from smaller proxy runs and sometimes during training (Xie et al., 2023a; Ye et al., 2025; Liu et al., 2025a; Chen et al., 2025; 2026). Filtering decisions also interact with available compute: repeating a small high-quality pool can change the relative value of adding less-filtered data (Muennighoff et al., 2023; Goyal et al., 2024). Benchmarks and integrated pipelines support systematic comparison and deployment of curation methods (Mazumder et al., 2023; Gadre et al., 2023; Penedo et al., 2024; Chen et al., 2024); see Albalak et al. (2024) for a survey. In computational biology, quality control, normalization, and harmonization are essential to com-parable analyses (Luecken et al., 2022; Heumos et al., 2023; Notin et al., 2023; Peidli et al., 2024). Vieth et al. (2019) evaluate thousands of single-cell analysis pipelines, while pipeComp (Germain et al., 2020) studies preprocessing choices and their interactions. These studies concern analysis pipelines; our controlled recipe grid instead evaluates how training-subset choices transfer across datasets and downstream models while holding subset size fixed. It shows that the tested standard recipes average no better than random subsets. 

Agents for machine-learning research and data work. Coding agents are evaluated on machine-learning competitions, research-engineering tasks, and language-model post-training (Huang et al., 2024; Chan et al., 2024; Wijk et al., 2025; Rank et al., 2026). Scaffolds structure their search as trees or populations (Jiang et al., 2025; Liu et al., 2025b; Yang et al., 2025; Li et al., 2024), reuse expert cases (Guo et al., 2024), or iteratively modify and evaluate training scripts (Karpathy, 2026; Cai et al., 2026). Agents also support broader scientific workflows (Lu et al., 2024; Yamada et al., 2025; Schmidgall et al., 2025; Jansen et al., 2025; Gottweis et al., 2026; Mitchener et al., 2025) and are tested on experimental design and model revision (Jansen et al., 2024; Gandhi et al., 2025; Wainrib et al., 2026). On the data side, work addresses dataset-issue detection, table cleaning, data collection, and general data-science tasks (Huang et al., 2025a; Qi et al., 2024; Ma et al., 2025; Zhang et al., 2026a; Seedat et al., 2025; Luo et al., 2026). Curation-Bench studies policy execution under a fixed training interface (Kang et al., 2026); DataMaster combines data discovery and refinement with tree-structured search and shared memory (Du et al., 2026). Our focus is how an agent interprets its own curation experiments over a long trajectory. 

Memory, belief states, and scientific hypotheses. Agents preserve experience as verbal reflec-tions (Shinn et al., 2023), distilled workflows (Zhao et al., 2024; Wang et al., 2025b), reusable skills (Wang et al., 2024), evolving playbooks (Suzgun et al., 2026; Zhang et al., 2025b), or struc-tured reasoning memories (Xu et al., 2025; Ouyang et al., 2026). Surveys examine memory’s role in longer-horizon agent learning (Gao et al., 2026; Huang et al., 2026; Ren et al., 2026). ABBEL makes a natural-language belief state the agent’s compact representation of earlier observations and studies errors in updating that state (Lidayan et al., 2025). In scientific discovery, HEP maintains evidence-linked hypotheses and belief probabilities (Takahara & Mizoguchi, 2026), while POP-PER designs sequential falsification tests for measurable implications of a hypothesis (Huang et al., 2025b). These works make belief maintenance and evidential support explicit; they also make clear why simply recording an agent’s conclusions does not establish that those conclusions apply in a new setting. Behavioral evaluations of scientific agents likewise report failures to use evidence and revise beliefs consistently (Ríos-García et al., 2026). ForecastCompass provides a particularly relevant comparison: it uses resolved forecasts and retrospective analysis to revise reusable factor and reasoning memories for future forecasting tasks (Chang et al., 2026). C ALI MEM operates in a different decision loop. Its forecast concerns the validation score of the curation policy the agent is about to execute; the subsequent error tests the policy-conditioned claims used to propose that experiment. Work on language-model calibra-tion provides further motivation to check stated judgments against outcomes (Kadavath et al., 2022; Tian et al., 2023; Xiong et al., 2024). Here, “calibrated memory” refers to this prospective check 26 Preprint and claim revision; it does not imply a guarantee of calibrated predictive probabilities or formal hypothesis-testing error control. 

Harness optimization and model-based prediction. Prompt and harness optimizers improve agent behavior across tasks through textual gradients, reflective evolution, architecture search, or self-modification (Khattab et al., 2024; Yang et al., 2024; Yuksekgonul et al., 2025; Agrawal et al., 2026; Hu et al., 2025; Zhang et al., 2025a; 2026b; Novikov et al., 2025). C ALI MEM holds its scaf-fold fixed and updates its understanding of one downstream curation task during a run. Model-based agents instead simulate the consequences of candidate actions before acting (Sutton, 1991; Chae et al., 2025; Gu et al., 2025; Yu et al., 2025; 2026). Empirical scaling laws and Bayesian optimiza-tion likewise use earlier measurements to predict expensive training outcomes (Kaplan et al., 2020; Hoffmann et al., 2022; Li et al., 2025; Bjorck et al., 2025; Snoek et al., 2012). C ALI MEM also pre-dicts an outcome, but uses the discrepancy after execution to update the written, conditional claims that determine where the agent searches next. 

## B EXPERIMENTAL DETAILS 

The science experiments cover three biological domains, each with its own data type: protein sequence and functional data, genomics, and single-cell transcriptomics. We tested five common tasks in these domains, including protein variant effect prediction (Notin et al., 2023), non-coding variant effect prediction (Marin et al., 2024), cell type annotation (Abdelaal et al., 2019), batch integration (Luecken et al., 2022) and perturbation response prediction (Wu et al., 2025). Each task combines several datasets with several models, giving 55 dataset–model tasks in total. In each task, the agent selects 50% of the pool. The LLM post-training experiments include general instruction tuning , selecting 10,000 rows from the Tülu 3 (Lambert et al., 2024) or LESS mixture (Xia et al., 2024) to fine-tune OLMo-2-1B or Llama-2-7B, and code instruction tuning , selecting 10,000 rows from OpenCodeInstruct (Ahmad et al., 2025) to fine-tune Qwen2.5-Coder-1.5B. Every task is run under two agentic pipelines, Basic agent and C ALI MEM . We test three agents with both agentic pipelines: Claude Code driven by Opus 4.8, Sonnet 5, or Haiku 4.5; Codex driven by GPT-5.3-Codex or GPT-5.6 Sol; and OpenHands driven by Qwen3.5-397B-A17B, an open-weight model. The agents are initiated from the same-seeded random subset, counted as the first iteration, and run 15 iterations in biology and 10 in the LLM post-training track. Each task is scored by several metrics. For biological tasks, we report the task’s primary metric from major benchmarks, averaged over the dataset–model pairs for LLM post-training, we report the mean score over each model’s fixed benchmark suite. OLMo-2-1B is scored on MMLU (Hendrycks et al., 2020), GSM8K (Cobbe et al., 2021), BBH (Suzgun et al., 2023), TruthfulQA (Lin et al., 2022), and IFEval (Zhou et al., 2023). Llama-2-7B is scored on MMLU and BBH. Qwen2.5-Coder-1.5B-Instruct is scored on HumanEval+ and MBPP+ (Liu et al., 2023). The number reported is the best score reached within a run. Models. Each method outputs an embedding of the evaluation cells. B.2.1 COMMON PROTOCOL 

Budget and floors. The harness accepts only submissions of exactly target_rows rows, half the training pool rounded to an integer (Table 2), and the package validator rejects at evaluation time any subset that violates the domain’s composition floors. The protein floors are at least 30 distinct residue positions and 10 distinct substituted amino acids. The non-coding floors are at least 100 positives, 100 negatives and 5 chromosomes, with the chromosome floor capped at the number of chromosomes in the training pool (one for eqtl_grasp ). Annotation requires at least 3 cells per cell type, and integration at least 10 cells per batch and 5 per cell type. Every recipe therefore first reserves a set of rows that satisfies the floors and then fills the rest of the budget according to its rule. 34 Preprint 

Filter, allocation and ranking recipes. Apart from random , each recipe is one of three kinds. A 

filter marks rows as eligible (for example by a QC threshold, a GC-matching rule or a de-duplication rule), and the budget is drawn uniformly from the eligible rows. If fewer eligible rows than the budget remain, the shortfall is drawn uniformly from the excluded rows ( filter-then-fill ), and the numbers of eligible and filled rows are recorded with each artifact. An allocation distributes the budget over strata (positions, classes, batches or geometric-sketch boxes) by water-filling. Each stratum receives an equal or weighted share, capped by its size and by any recipe-specific cap, and the remainder is redistributed until the budget is met. A ranking orders rows by a score and keeps the highest-ranked rows up to the budget. The fill seed determines which rows are drawn within a stratum or an eligible set and breaks ties between equal scores. 

Seeds and scoring. Every recipe is materialized with five fill seeds, and the random subset with ten further seeds (fifteen draws in total) to provide the random-search reference. Each artifact is scored with the frozen model on the evaluation split through the same entry point that the agents use. As in the main results, a submission that fails a validity guard (for example the open-set guard requiring that at least half of the cells of known types are not rejected as unknown) is scored 0. Recipe statistics are five-seed means, and the “best recipe per subtask” entry in Table 12 is the best five-seed mean among the twelve recipes of each dataset–model pair. 

Derived quantities. Recipes that need a representation use the same representation for every frozen model in a domain. For the variant-effect domains these are the mean-pooled embeddings of ESM-2 (35M parameters) and DNABERT (6-mer) that the embedding-based models use, read from each package’s per-sequence embedding cache. For single-cell data they are the first 50 principal components of the scaled expression of the 2,000 highly variable genes flagged in each object. ## F DISCOVERED CURATION STRATEGIES 

Within our experiments, the agent has discovered multiple strong policies by itself that significantly improved baseline performance. In this section, we illustrate some of the strongest policies discov-ered by the agent as examples. F.1 BIOLOGY 

The first case is a C ALI MEM run of Claude Opus 4.8 on the CYP2C9 deep mutational scanning (DMS) assay ( cp2c9_human ). The agent selects 1,868 of the 3,736 single amino-acid substitution variants in the training pool. The downstream model is a ridge regressor with fixed hyperparameters on frozen ESM-2 embeddings, trained on the selected variants and evaluated on the validation split. 

POSITION -STRATIFIED SELECTION SPANNING SUBSTITUTION SEVERITY (CYP2C9) 

Starting rule. A DMS assay measures the functional effect of every single amino-acid substitution of a protein (Fowler & Fields, 2014), so training under a fixed budget requires choosing which substitutions to keep. The card’s rule is stratified sampling with residue positions as strata: every position is represented instead of a few positions being sampled exhaustively, and within each position the selected substitutions are spaced along an amino-acid distance scale, from conservative (physicochemically similar) to radical (dissimilar) replacements. The training set therefore shows how strongly the effect at each position de-pends on how chemically different the replacement is (substitution severity). The budget is split across positions in proportion to their number of measured variants (proportional allocation). The card does not specify which distance to use. 

What the agent found. The agent identified two issues that the card’s description had left open. First, the choice of distance matters: spacing substitutions along BLOSUM62 substitution scores (Henikoff & Henikoff, 1992) or Miyata distance (Miyata et al., 1979) performed at the level of a random 50% sub-set, whereas Grantham distance (Grantham, 1974), which combines composition, polarity and volume, improved on it. Second, proportional allocation left 40 of the 287 positions with a single selected substi-tution; a position with one substitution provides no within-position contrast, so the rationale of the rule does not apply there. The agent also found that the spacing must be computed within each position’s own severity range: using severity thresholds shared across all positions brought performance back to the random-subset level. 

Final policy. The policy uses Grantham distance, spaces substitutions within each position’s own severity range, and enforces a minimum allocation of two substitutions (one conservative, one radical) at every position with at least two measured variants. The budget for these reserved slots is taken from the positions with the largest allocations, and the remaining budget is allocated slightly super-proportionally to the number of measured variants per position. The number of positions with a single selected substitution fell from 40 to 8, and each of those 8 has only one variant in the pool.

The second case is a run of the same model on the PTEN DMS assay ( pten_human ), with an MLP regressor on the same frozen ESM-2 embeddings; the agent selects 2,194 of 4,387 variants. 

NOISE FILTERING BEFORE COVERAGE -BASED SELECTION (PTEN) 

Starting rule. Coverage-based selection chooses a subset that spans the model’s input space, a criterion related to core-set selection (Sener & Savarese, 2018). The pool is partitioned into regions of the ESM-2 embedding space and the budget is filled round-robin across regions, so the training set covers the space the model must generalize over instead of concentrating where the assay sampled most densely. 

What the agent found. On its own, this rule performed below random selection. Round-robin filling over-samples sparsely populated regions of the embedding space, and in this assay those regions contained the least reliable measurements rather than the most informative substitutions. Coverage selection cannot distinguish a variant that is atypical because it is chemically distinctive from one that is atypical because its measurement is noisy, so a rule meant to broaden the training set spent much of the budget on noisy labels. 

Final policy. The agent filtered noisy variants before applying coverage selection, in the spirit of cross-validated filtering of mislabeled training data (Brodley & Friedl, 1999). Each variant was scored by its prediction error under a model fitted on variants at other residue positions (an out-of-fold residual); within each bin of assay score, the 25% of variants with the largest errors were removed; and the same coverage selection was then applied to the remaining variants. Neither step was modified; only their order was new. Coverage selection improved performance only when applied after filtering. 

Results. Spearman’s ρ on the validation split: Full training pool (no curation) 0.359 Random 50% subset 0.338 Coverage selection only 0.319 Residual-based filtering only 0.390 Agent’s final policy (filter, then cover) 0.403 

The filtering fraction mattered sharply rather than gradually: removing the worst 15% of each bin instead of 25% lowered ρ to 0.345, consistent with coverage selection concentrating on the noisy variants that remained. 

The third case is single-cell cell-type annotation across sequencing protocols (pbmc_crossprotocol ). A protocol is the experimental method used to capture cells and prepare sequencing libraries. In a C ALI MEM run of Claude Sonnet 5, the agent selects 4,082 of 8,165 cells to train a linear classifier with fixed hyperparameters. The training pool contains 10x Chromium v2 and v3 cells, and the classifier is evaluated on cells from a protocol absent from the pool (inDrops). 

CROSS -PROTOCOL MARGIN SCORING WITHIN STRATIFIED QUOTAS (PBMC) 

Starting rule. Margin-based selection ranks each cell by its classification margin, the classifier’s score for the cell’s annotated label minus its highest score among the other labels, computed by a classifier fitted on the training pool, and fills the budget from one end of the ranking. Keeping high-margin cells gives lower-variance estimates of where each cell type lies in expression space, at the cost of the ambiguous cells near the boundaries between types. 

What the agent found. When the margin comes from a classifier fitted on the same pool it ranks, it reflects how well a cell fits its own sequencing protocol. A cell can receive a high margin from protocol-specific technical signal rather than from its cell type (datasets from different technologies carry batch-specific systematic variation (Tran et al., 2020)), and that signal does not transfer to an unseen protocol, so the ranking favors the cells least likely to remain informative at evaluation. In a comparison within the training pool, margins from classifiers fitted on a different protocol gave a macro-F1 of 0.929, against 0.918 for margins computed within the same protocol. 

Final policy. Each cell was scored by classifiers fitted without its protocol (leave-one-protocol-out scor-ing), and each protocol × cell-type quota was filled with its highest-scoring cells. The final score averages two such scores, each standardized (z-scored) within protocol: one derived from the calibrated class pos-terior and one from distances to the class centroids, both from the same held-out-protocol fits. F.2 LLM The strongest policy produced in the language-model track came from a C ALI MEM run of Claude Sonnet 5 on the LESS mixture, in which the agent selects 10,000 of 270,679 rows to fine-tune Llama-2-7B and is scored on the mean of MMLU and BBH. The agent implemented RDS+ (Ivison et al., 2025) and mapped the method’s degrees of freedom over several iterations, and then identified a defect in the method itself and wrote the variant below, which is the run’s best policy. 

A VARIANT OF RDS+ WRITTEN BY THE AGENT 

The published method. RDS+ selects by cosine similarity in a cached embedding space. Every pool row, and every query point drawn from the target evaluations and written in the format those evaluations use, is encoded as a position-weighted mean of the last hidden layer of the model about to be fine-tuned. The budget is then filled by round-robin over the query points, each taking its nearest unselected row. The cost is one forward pass over the pool, reusable across budgets. 

The problem the agent found. The similarity that ranks candidates is a similarity of surface form rather than of what a row teaches. Query points formatted as the benchmarks format them, and in particular the multi-step reasoning traces used for BBH, are closest to the pool’s chain-of-thought rows, which consequently dominate nearly every ranking and absorb most of the budget. The two human-written, open-ended sources in the pool are almost entirely excluded: no query point resembles an open-ended exchange, so similarity cannot surface those rows however much the model needs them to follow an instruction and lay out an answer. The agent’s diagnosis was that one ranking is being asked to settle two decisions of different kinds, the allocation of the budget across sources and the choice of rows within a source, and that it is informative only about the second. 

The agent’s variant. The variant separates the two decisions. A fixed share of the budget is reserved for each under-selected source and filled by the same round-robin restricted to that source’s candidates, before the unrestricted round proceeds over the remainder. The rows admitted this way are still the nearest available rows of their source to a query point rather than random draws from it, and the embedding, the query set and the ranking are untouched. Similarity continues to order rows within a source; it no longer determines the allocation across sources.
