## 摘要
跨多个会话为用户服务的大语言模型（LLM）智能体必须在每个请求中选择少数进入有限上下文窗口的存储记忆。这一选择在很大程度上决定了智能体能否正确回答，并且它在 Web 规模下对每个请求都会执行。该选择面临三个挑战：存储量大且不断增长、每个请求的成本预算，以及需要全部证据的多会话问题。许多记忆系统为每段历史构建笔记或图谱时需要数百到数千次 LLM 调用，而且每个系统都是独立设计，因此难以判断哪个组件带来了准确率。这些挑战与推荐系统的特性相似，因此我们将智能体记忆形式化为带预算的推荐列表（slate）推荐：将请求视为用户，存储记忆视为物品，上下文窗口视为推荐列表。这一形式化将记忆系统放入推荐级联的统一设计空间中，并把准确率分解为各阶段所控制的完整性。在这一思路指导下，我们提出 AgentMemRec，它借鉴推荐系统中的候选生成、学习排序和推荐列表构建，并在不进行任何 LLM 调用的情况下选择记忆。在 LongMemEval 的多会话问题上，AgentMemRec 的准确率比 A-Mem、HippoRAG 2、DynamicRAG 和 T-Mem 等记忆与上下文选择方法高出 10 到 31 个百分点。它的表现与每个查询进行 64 次调用的 LLM 重排序器相当，但服务成本低 3.2 倍；在 LoCoMo 上，它在写入时无需任何 LLM 调用即优于 Mem0 和 Zep。该分解将增益归因于推荐列表更频繁地包含全部证据，因此推荐系统设计为 LLM 智能体的长期记忆提供了有效且高效的基础。

## Abstract
Large language model (LLM) agents that serve users across many sessions must choose, for every request, the few stored memories that enter a limited context window. This choice largely decides whether the agent answers correctly, and it runs on every request at Web scale. This selection faces three challenges: a large and growing store, a per-request cost budget, and multi-session questions that need all of their evidence. Many memory systems build notes or graphs with hundreds to thousands of LLM calls per history, and each is designed on its own, so it is unclear which component yields the accuracy. These challenges mirror the properties of recommendation, so we formalize agent memory as budgeted slate recommendation, with the request as the user, stored memories as items and the context window as a slate. The formalization places memory systems in one design space of recommender cascades and factorizes accuracy into the completeness that each stage controls. Guided by it, we propose AgentMemRec, which adapts candidate generation, learning to rank and slate construction from recommender systems and selects memories without any LLM call. On multi-session questions of LongMemEval, AgentMemRec outperforms memory and context-selection methods, including A-Mem, HippoRAG 2, DynamicRAG and T-Mem, by 10 to 31 points of accuracy. It matches an LLM reranker that makes 64 calls per query at 3.2 times lower serving cost, and on LoCoMo it outperforms Mem0 and Zep without any LLM call at write time. The factorization attributes the gains to slates that more often hold all of the evidence, so recommender-system design offers an effective and efficient foundation for the long-term memory of LLM agents.

## 1. 论文的核心问题与整体含义

- **核心问题**：大语言模型（LLM）智能体在跨多个会话为用户服务时，必须在每次请求中从长期记忆中挑选少量记忆放进有限的上下文窗口。这个选择直接决定回答是否正确，并且每次请求都要执行，成本必须可控。
- **三大挑战**：
  - 记忆存储规模大且持续增长（例如 LongMemEval-M 中单个问题对应约 500 个会话、150 万 token，而回答模型只能读取约 2700 token）。
  - 每次请求都有成本预算，用 LLM 对全部记忆打分会导致调用量随存储规模和流量线性增加。
  - 价值是在整个上下文级别体现的：跨多个会话的问题需要所有证据都被选中，缺失一个证据会造成严重准确率下降。
- **研究动机**：现有记忆系统通常用 LLM 构建笔记、图谱、时间层次等结构，每段历史需要数百到数千次 LLM 调用，但各组件对准确率的贡献不清晰，也缺少统一的设计框架。
- **整体含义**：作者观察到记忆选择与推荐系统高度相似——请求相当于用户、记忆相当于物品、上下文窗口相当于受预算约束的推荐列表。因此将智能体记忆形式化为“预算约束下的列表推荐”，用推荐系统级联设计的视角统一分析记忆系统，并提出一个零 LLM 调用的记忆选择方法。

## 2. 方法论

- **形式化定义**：将记忆选择建模为 budgeted slate recommendation：
  - 请求 \(x\) 作为用户；
  - 存储记忆（turns 或记录）作为物品；
  - 上下文窗口作为 slate；
  - 成本为渲染后的 token 数，预算为 \(B\)；
  - 奖励为回答被判断为正确的概率。
- **设计空间**：任何记忆系统都可以表示为四元组 \((\varphi, g, f, h)\)：
  - \(\varphi\)：写入时记忆构建；
  - \(g\)：候选生成/召回；
  - \(f\)：记忆排序；
  - \(h\)：上下文组装/slate 构建。
  不同系统的主要区别在于在哪个阶段调用 LLM。
- **三条理论结果**：
  - **阶段分解**：准确率 \(Acc = a_i + (a_c - a_i) \cdot r_{pool} \cdot r_{rank}\)，其中 \(r_{pool}\) 是池完整性，\(r_{rank}\) 是排序完整性，\(a_c\) 和 \(a_i\) 分别是完整和不完整 slate 上的平均奖励。这解释了哪些阶段决定最终准确率。
  - **归约为逐项排序**：在证据单元独立、奖励只依赖完整性等条件下，最大化期望奖励等价于 0-1 背包问题；若单位成本相等，则按物品为证据的概率降序填充。
  - **填充优于截断**：当奖励随列表扩展不下降时，固定预算的贪心填充至少不差于任意前缀截断。
- **AgentMemRec 方法**（零 LLM 调用）：
  - **候选生成**：融合 BM25 与 bge-m3 稠密检索，使用倒数排名融合（RRF），取前 128 个 turn 作为池。
  - **学习排序**：用 LightGBM 和 LambdaRank 目标训练排序器。特征共 10 个：5 个相关性信号（bge-m3 余弦相似度、全局 BM25/dense 排名对数、融合池位置、bge-reranker-v2-m3 交叉编码分数）；5 个 turn 上下文特征（是否为用户、在会话中的相对位置、年龄/长度对数、与问题的 spaCy 关键词重叠）。
  - **Slate 构建**：按排序顺序贪心填充，加入每个 turn 直到渲染 token 成本达到预算 \(B=2700\)，跳过放不下的 turn，不设置每问题截断。
  - **可选写入时记录**：用 LLM 为每个会话写类型化记录（带日期、实体、引用 turn），作为额外召回通道；相对时间标签可提升 LoCoMo 的时间推理。

## 3. 实验设计

- **数据集与基准**：
  - **LongMemEval-S**：500 个问题，每个问题对应约 50 个会话、10 万 token。
  - **LongMemEval-M**：同样的问题，但每个问题对应约 500 个会话、150 万 token，难度更高。
  - **LoCoMo**：10 段长对话、1540 个评分问题，用于长期对话记忆评估。
  - 主要评测指标为多会话问题（证据跨至少 2 个会话）上的准确率，并按证据会话数 \(\kappa\) 分层报告。
- **对比方法**：
  - 上下文选择器：Adaptive-k、DynamicRAG-8B。
  - LLM 构建记忆：LongMemEval 官方设计、HippoRAG 2、A-Mem、T-Mem。
  - LLM 重排序器 Ref：每个查询对 64 个候选 turn 进行 64 次 LLM 调用后填充。
  - 生产记忆层：Mem0、Zep、MemOS、TiMem、RecMem、HyperMem（部分为复现）。
- **回答与评判**：
  - LongMemEval 使用 Qwen3-32B 和 DeepSeek V4.1 Flash 作为回答模型，GPT-4o 作为官方裁判。
  - LoCoMo 使用 GPT-4o-mini 回答并裁判三次。
- **评估协议**：每个系统为每个问题构建 4 个不同预算（2400–2700 token）的 slate，取平均裁判标签，采用配对百分位 bootstrap 做显著性检验。

## 6. 主要结论与发现

- AgentMemRec 在 LongMemEval-S 和 LongMemEval-M 的多会话问题上，准确率超过所有记忆和上下文选择方法，优势为 10 到 31 个百分点。
- 与每查询 64 次 LLM 调用的重排序器 Ref 相比，AgentMemRec 在大多数情况下达到同等或更高准确率，但服务成本约为其三分之一。
- 在 LoCoMo 上，AgentMemRec 在无 LLM 写入调用的情况下与 T-Mem 复现持平，并优于 Mem0、Zep、MemOS 等生产层。
- 阶段分解表明：**slate 完整性是带来增益的主要因素**。AgentMemRec 的 slate 完整性为 0.94，而 HippoRAG 2 和 A-Mem 仅为 0.50。在双方 slate 都完整的问题上，各系统准确率没有显著差异。
- 逐项排序在 \(\kappa \ge 3\) 或存在“近失误 filler”时开始失效，因为 slate 的组成会影响奖励，提示需要集合级别的排序目标。

## 7. 优点

- **理论清晰**：将记忆选择形式化为推荐问题，给出阶段分解等可验证的定理，使不同系统的贡献可归因。
- **成本极低**：AgentMemRec 在记忆选择阶段零 LLM 调用，仅依赖 BM25、稠密检索和轻量 LightGBM，适合 Web 规模部署。
- **消融扎实**：详细拆解了候选池、排序特征、slate 填充等各阶段对准确率的影响，并验证了理论条件。
- **多回答模型验证**：在 Qwen 和 DeepSeek 两种模型上均表现稳定，降低了结论对单一回答模型的依赖。
- **可迁移性**：排序器在 LongMemEval 训练后可迁移到 LoCoMo，且与域内训练相差不大。
- **公开成本数据**：提供了 GPU 时间、延迟和美元成本对比，对实际部署有参考价值。

## 8. 不足与局限

- **评测覆盖有限**：
  - 主要限于 LongMemEval 和 LoCoMo 两个对话记忆基准，缺乏真实生产日志或多模态数据的验证。
