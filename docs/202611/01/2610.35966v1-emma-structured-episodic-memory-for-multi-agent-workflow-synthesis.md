## 摘要
在专业领域中部署LLM智能体通常需要通用模型所缺乏的细粒度任务特定流程和知识，而参数训练成本高昂且不可解释，手工设计的智能体系统则将成本转嫁给专家劳动。情景记忆在上下文层面进行更新，但单智能体适应难以缓解跨任务干扰，尤其是在多应用导航或数据池分析等复杂任务中。尽管多智能体演化缓解了这一问题，现有方法对更新规则缺乏清晰定义，并依赖骨干模型来决定系统在哪里以及变化多少。这种范围不当的演化使学习遵循骨干模型的结构偏好而非观察到的失败：一个骨干模型积累技能，而另一个则生成智能体。我们提出EMMA（面向多智能体工作流合成的结构化情景记忆），它将多智能体系统的配置（控制器路由记忆、继承通才提示的专家以及逐步程序技能）视为情景记忆。EMMA明确更新所有权和可采纳性：反射器将每个诊断出的失败分配给负责其修正的范围，并在其中提出一个编辑，而独立于骨干模型的守护机制确保每个被接受的编辑都是有范围、增量且有界的。在KramaBench、AppWorld和BBEH上，使用五个骨干模型和四个基线（ACE、GEPA、EvoMAS和ADAS），EMMA在每个基准上都取得了最佳整体性能，比最强基线高出最多32.5%，在不同骨干模型上保持一致改进，并且训练执行次数比最高效基线少17-38%。

## Abstract
Deploying LLM agents in specialized domains often require fine-grained task-specific procedures and knowledge a general model lacks, yet parameter training is costly and non-interpretable, and hand-engineered agent systems shift the cost to expert labor. Episodic memory updates at context level, but single agent adaptation struggles to alleviate cross-task interference, especially with complex tasks such as multi-application navigation or data pool analysis. Although multi-agent evolution alleviates this problem, existing methods lack clear definitions on update rules and rely on the backbone model to decide where and how much the system changes. This ill-scoped evolution makes learning follow the backbone's structural preferences rather than the observed failures: one backbone accumulates skills while another spawns agents. We present EMMA (structured Episodic Memory for Multi-Agent workflow synthesis), which treats the configuration of a multi-agent system (controller routing memory, specialists inheriting a generalist prompt, and per-step procedural skills) as episodic memory. EMMA makes the ownership and admissibility of updates explicit: a reflector assigns each diagnosed failure to the scope owning its correction and proposes one edit within it, and backbone-independent guards keep every accepted edit scoped, incremental and bounded. Across KramaBench, AppWorld and BBEH with five backbones and four baselines (ACE, GEPA, EvoMAS and ADAS), EMMA attains the best overall performance on every benchmark, up to 32.5% over the strongest baseline, maintains consistent improvements across backbones, and uses 17-38% fewer training executions than the most efficient baseline.

## 2. 论文提出的方法论

### 2.1 核心思想

- 将多智能体系统配置视为**三层情景记忆**：
  - **控制器记忆 C**：任务分解与路由规则。
  - **代理池 A**：子代理系统提示，新代理从通才提示继承（`p̃_j = p0 ∥ p_j`），实现通用改进自动传播。
  - **技能池 S**：面向子问题类别的简短程序性步骤，控制器按步分配。
- 训练过程采用**结构化反射 + 守卫更新**：每个失败尝试被定位、分类到具体责任范围（scope），并在该范围内执行**单个有界编辑**，然后重新测试。

### 2.2 关键技术细节

- **逐步合成与溢出分解**：控制器按步规划并分派子任务、代理和技能；若步骤耗尽代理的上下文或轮次，视为“子任务过粗”而非代理失败，通过溢出分解将步骤拆分为更小步骤并重新插入计划。
- **失败范围与动作词汇**（表 1）：
  - `execution_slip`：一次性执行失误 → 仅修订本次任务的计划指令或不变。
  - `agent_behavior`：通用工作习惯失败 → 优化代理提示。
  - `procedure`：某类子问题方法错误/缺失 → 修订或创建技能。
  - `missing_capability`：无代理能完成该工作 → 创建技能（优先）或创建代理。
  - `routing`：分解/分派错误 → 写入控制器记忆或修订计划；溢出时也可创建代理。
- **反射器四步流程**：定位失败步骤 → 分类范围 → 泛化修正（不包含任务特定实体）→ 最小化编辑。
- **骨干无关守卫**（表 10 对比）：
  - 范围–动作兼容性。
  - 提示保留（至少 60% 行保留，仅允许参与代理被编辑）。
  - 内存有界增长（代理池 ≤10、技能池 ≤40、提示/技能字符上限）。
  - 无泄漏（不含参考答案或任务文本逐字片段）。
  - 策略变化（同一层级连续失败 ≤2 次；两次连续溢出必须改变工作拆分方式）。
- **训练循环**（算法 1–3）：单次遍历训练集，每任务最多 K=5 次修订，每次编辑必须通过守卫，编辑后重新运行；任务链结束后更新控制器记忆（≤2 条目）。评估时冻结记忆，不调用反射器。

## 6. 论文的主要结论与发现

- **整体性能**：EMMA 在三个基准的所有骨干上取得最佳平均性能；KramaBench 上比最强基线（GEPA）高 +7.0 准确率，BBEH-mini 上高 +5.8，AppWorld normal 上高 +11.9 TGC / +17.4 SGC，challenge 上高 +6.4 TGC / +5.3 SGC。
- **跨骨干一致性**：EMMA 在 20 个骨干–基准设置中 17 个排名第一，其余 3 个第二；其最弱骨干性能超过所有基线的最弱骨干性能，且在部分基准上超过所有基线五骨干均值。
- **开放权重骨干上的优势**：多智能体搜索基线（EvoMAS、ADAS）在开源骨干上性能急剧下降（ADAS 在 DeepSeek v3.2 和 Kimi-K2.5 上未发现优于手写种子的程序），而 EMMA 保持稳定，优势随骨干变弱而扩大。
- **训练效率**：EMMA 训练执行次数最少，比最高效基线少 17–38%，表明每次编辑都是有针对性的修正而非推测性重构。
- **消融发现**：学习技能池贡献大于学习代理池，但代理池仍带来额外增益；训练时情景学习显著优于测试时反思或自演化，验证了从已验证训练失败中学习的迁移价值。

## 7. 优点

- **方法层面**：
  - 将多智能体配置明确建模为三层情景记忆，提供了清晰的更新所有权和粒度。

  - 代理继承机制实现通用改进的自动传播，避免重复。
  - 溢出分解将资源耗尽视为子任务过粗而非代理失败，使系统能在长任务中保持稳健。
- **实验层面**：
  - 覆盖三个差异较大的基准、五个骨干（闭源 + 开源）、四个竞争基线，评估全面。
  - 提供训练执行次数对比和消融实验，展示效率与机制贡献。
  - 案例研究具体展示了训练产物如何跨任务迁移，增强可解释性。
- **结果层面**：
  - 取得一致且可观的性能提升，尤其在开放权重骨干上表现出强鲁棒性。

## 8. 不足与局限

- **未完全消除骨干差距**：EMMA 缩小但未完全消除不同骨干家族之间的性能差距，强反射器与较弱执行器组合仍存在扩展空间。

- **单次遍历训练**：仅进行一个 epoch、固定任务顺序，可能受顺序效应影响；未探索多轮或多 epoch 是否更优。
- **统计严谨性不足**：未报告多次随机种子下的均值和方差，无法判断性能差异是否显著。
