## 摘要
上下文窗口已经增长了一千倍，但编码智能体在每次会话开始时仍然没有关于过往工作的记忆。它们重新读取文件、重试失败的方法，并忘记几小时前已经确定的根本原因。这不是上下文长度问题，而是记忆架构问题。我们的假设是：编码智能体需要持久的、具备经验感知的仓库记忆，使知识能够从一个会话延续到下一个会话。在真实仓库上的三项测量推动了这一设计。首先，中等规模项目已经超过最大的生产环境上下文窗口，而将知识存储在模型的键值（KV）缓存中所占用的字节数，是将其存储为索引文本的 $10^4$ 到 $10^5$ 倍。其次，在 752 个真实缺陷修复提交中，中位修复会编辑两个文件，而这些文件加上它们的直接导入只占仓库的不到 10%；瓶颈在于选择，而非容量。第三，即便考虑传递导入可达性和测试链接，仍有 47% 的共同编辑文件对在结构上不连通；选择所需的知识必须从历史和经验中挖掘。我们概述了 Stratum，一种与仓库共存的分层记忆，并通过分页安全（page-safe）工具为其提供服务：每个响应都会说明返回了什么、剩余什么以及代价如何。在一百万个节点的存储中进行检索，中位耗时为 1.7 毫秒。在针对八个真实缺陷的多会话实验中，一个继承了先前会话记忆（由不同模型编写）的新智能体，在 24 次试验中有 21 次识别出根因文件，而仅检索基线在 24 次中为 6 次（Fisher $p<10^{-4}$），且中位 token 成本低 4.5 倍。将所有八项调查的记录合并到一个存储中后，成功率仍为 8/8。

## Abstract
Context windows have grown a thousand-fold, yet coding agents still start every session with no memory of their past work. They re-read files, retry failed approaches, and forget root causes they established hours earlier. This is not a context-length problem but a memory-architecture problem. Our hypothesis: coding agents need persistent, experience-aware repository memory, so that knowledge survives from one session to the next. Three measurements on real repositories motivate the design. First, mid-size projects already exceed the largest production context windows, and storing knowledge inside the model's key-value (KV) cache costs $10^4$ to $10^5$ times more bytes than storing it as indexed text. Second, across 752 real bug-fix commits, the median fix edits two files, and these files plus their direct imports amount to less than 10% of the repository; the bottleneck is selection, not capacity. Third, even with transitive import reachability and test links, 47% of co-edited file pairs remain structurally disconnected; the knowledge needed for selection must be mined from history and experience. We sketch Stratum, a tiered memory that lives with the repository and serves it through page-safe tools: every response states what was returned, what remains, and what it cost. Retrieval over a store of one million nodes takes 1.7 ms at the median. In a multi-session experiment on eight real bugs, a fresh agent that inherited a prior session's memory, written by a different model, identified the root-cause file in 21 of 24 trials versus 6 of 24 for a retrieval-only baseline (Fisher $p<10^{-4}$), at 4.5x lower median token cost. With the notes of all eight investigations pooled in one store, success remained 8/8.

- **整体含义**：编码智能体需要的是**持久、经验感知的仓库记忆**，使知识可以跨会话、跨模型延续；记忆应存放在模型外部，以文本和结构化形式与代码仓库共存，而不是保存在 tensor/KV 状态中。

## 2. 论文提出的方法论

### 2.1 核心思想

Stratum 是一个面向编码智能体的分层记忆系统，类比数据库缓冲池：

- **冷层（SSD）**：SQLite 图数据库，存储大规模长期记忆；
- **热层（RAM / 上下文）**：小规模快速工作集；
- **控制器**：根据评分决定哪些节点进入驻留状态，负责预取和逐出。

所有知识以**文本 + 结构化图**的形式存在开发者机器上，而不是模型内部；模型 KV 缓存只保留当前轮次。

### 2.2 三类记忆节点

- **结构记忆**（structural）：文件、API、import / test 边，由解析代码重建；
- **历史记忆**（historical）：共同变更边、设计决策、变动依据，从版本历史挖掘；
- **经验记忆**（experiential）：失败尝试、根因发现、调试记录，由智能体写回。

### 2.3 存储与控制器

- 冷层为 SQLite 图，节点包括源文件、测试、研究笔记、决策、失败记录、根因节点；边类型包括 `imports`、`tests`、`similar`、`sources`、`co_changes`。
- 使用 HNSW 向量索引支持相似性搜索（384 维本地 embedding）。
- 文件监视器在内容哈希变化时重索引，并刷新共同变更统计。
- 控制器对每个节点打分：

\[
S(v) = w_1 G(v) + w_2 C(v) + w_3 H(v) + w_4 P(v)
\]

其中：

- \(G(v)\)：与当前编辑文件的图邻近度；
- \(C(v)\)：共同变更亲和度；
- \(H(v)\)：时间衰减的访问频率；
- \(P(v)\)：显式 pin 优先级。

逐出策略：pinned 节点永不逐出；当前编辑文件的直接邻居保留接口级细节；其他 warm 节点退化为单行摘要；当空闲上下文低于 15% 时，优先逐出最大、最冷的节点，并报告被移除的内容。

### 2.4 九种页面安全工具

智能体通过 MCP 工具访问存储：

- **读取类 5 个**：
  - `tree`：以层级列出存储；
  - `search`：结合 embedding 相似性、关键词匹配和最近性；
  - `get`：按摘要 / API / 全文三种粒度返回节点；
  - `walk`：沿类型化边遍历；
  - `budget`：报告 token 使用情况。
- **写入类 1 个**：
  - `remember`：持久化新知识节点。
- **驻留控制类 3 个**：
  - `pin / unpin`：将节点固定在上下文中；
  - `prefetch`：提前升温节点；
  - `evict`：释放节点。

**页面安全契约**：每个响应都携带内容、分页状态（`page / total_pages / has_more`）、剩余 token 预算和提示；工具绝不静默截断，智能体可以自主决定何时停止加载。

### 2.5 写回与跨会话闭环

任务结束时，智能体通过 `remember` 将所学内容写回存储。下一个会话可由不同模型继承这些记忆，并继续利用。
