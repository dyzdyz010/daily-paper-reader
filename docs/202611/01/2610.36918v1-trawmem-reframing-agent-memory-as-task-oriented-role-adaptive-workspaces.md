## 摘要
大型语言模型（LLM）智能体依赖记忆系统来利用长期交互，但现有系统通常根据记忆与当前查询的相关性来检索记忆，并将其作为上下文证据。然而，相关性本身并不能刻画记忆如何对任务求解做出贡献：同一条记忆在不同任务中可能发挥不同作用，例如直接支持答案，或者连接到语义相关性较弱但包含必要信息的互补记忆。因此，我们将智能体记忆系统重新构建为面向任务的角色自适应工作空间，其中记忆根据其面向任务的角色和关系被选择和组织。基于这一视角，我们提出 TrawMem，它将交互历史组织为局部线索，并通过分配角色和联合选择互补记忆来构建面向任务的工作空间。在 LoCoMo 和 MemGallery 上使用四个开源和闭源骨干模型进行的实验表明，相较于代表性记忆系统，TrawMem 持续取得改进，宏 F1 提升了 2.23–3.14 个百分点。在 LoCoMo 上，TrawMem 在 Qwen3.5-9B 和 DeepSeek-V4-Flash 上相较 SimpleMem 分别将 LLM-Judge 得分提高了 4.07 和 4.31 个百分点，同时所需的上下文 token 分别减少了约 12.8% 和 5.1%。

## Abstract
Large language model (LLM) agents rely on memory systems to leverage long-term interactions, yet existing systems typically retrieve memories based on their relevance to the current query and use them as contextual evidence. However, relevance alone does not characterize how a memory contributes to task solving: the same memory may serve different roles across tasks, such as directly supporting the answer or linking to complementary memories with weaker semantic relevance but necessary information. We therefore reframe agent memory systems as Task-Oriented Role-Adaptive Workspaces, where memories are selected and organized by their task-oriented roles and relations. Based on this view, we propose TrawMem, which organizes interaction histories into local threads and constructs task-oriented workspaces by assigning roles and jointly selecting complementary memories. Experiments on LoCoMo and MemGallery with four open- and closed-source backbones show consistent improvements over representative memory systems, with macro-F1 gains of 2.23-3.14 points. On LoCoMo, TrawMem improves the LLM-Judge score over SimpleMem by 4.07 and 4.31 percentage points on Qwen3.5-9B and DeepSeek-V4-Flash, respectively, while requiring approximately 12.8% and 5.1% fewer context tokens, respectively.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体在长时间交互、个性化助手、连续任务等场景中需要记忆系统来保存和利用长期交互历史；随着交互历史增长，上下文窗口成为瓶颈，且完整历史重处理开销大，因此需要外部记忆系统。
- **现有问题**：目前主流的智能体记忆系统（如 Mem0、A-MEM、LightMem、SimpleMem 等）通常**按记忆与当前查询的相关性进行检索**，并将检索结果作为上下文证据。  
- **核心观察**：相关性本身并不能刻画一条记忆在任务求解中的**角色**。同一条记忆在不同任务中可能发挥不同作用：
  - 直接支持答案（anchor）；
  - 作为连接其他弱相关但必要记忆的“桥梁”（bridge）；
  - 仅提供背景上下文（context）。
- **整体含义**：论文将智能体记忆重新定义为**“面向任务的角色自适应工作空间”**，即记忆不是被动等待检索的记录集合，而是针对当前任务临时组织起来的信息组合。该方法强调记忆的**任务导向角色**和**互补信息选择**，而非单纯的相关性排序。

## 2. 论文提出的方法论

TrawMem 将记忆使用划分为两个阶段：

### 阶段 1：从原始记忆到局部线程

- 将交互历史 \(D=\langle u_1,\dots,u_T\rangle\) 中连续记录按事件组织为**局部线程** \(T_j=(a_j,L_j)\)，其中：
  - \(L_j\) 是原始记录序列，保留细节、顺序、来源和时间信息；
  - \(a_j\) 是 LLM 生成的简洁摘要，作为线程头（thread head）和检索入口。
- 使用向量编码线程头 \(h_j\) 和每个记忆单元 \(e_v\)。
- 将相邻线程和语义相近线程连接起来，构建**线程图 \(G_H\)**，以支持跨线程信息联合使用。

### 阶段 2：从线程邻域到任务工作空间

1. **定位任务上下文**  
   - 对查询编码 \(z_q\)，计算线程初始得分，并通过线程图传播得分，获得任务相关邻域 \(H_q\)，收集候选记忆单元集 \(U_q\)。

2. **任务导向角色分配**  
   - 定义任务角色需求分布 \(\delta_q\)，以及单元在任务下的软角色权重 \(\rho_q(v)\)（角色包括 anchor、bridge、context 等）。
   - 通过可学习矩阵 \(A\) 和依赖需求的映射 \(M(\delta_q)\)，结合单元的关系特征 \(f_q(v)\)，得到**角色适应性得分** \(\phi_q(v)=\delta_q^\top\rho_q(v)\)。

3. **角色引导的工作空间组装**  
   - 在候选集 \(U_q\) 上构建局部图，定义从线程头到单元的成本 \(C_q(T_j,v)\)，组合路径距离、查询亲和度 \(\alpha_q(v)\) 和角色适应性 \(\phi_q(v)\)。
   - 使用**子模函数最大化**选择互补记忆子集：
     - 目标 \(J_q(S)\) 包含覆盖期望、角色覆盖、查询亲和度和线程覆盖率四项；
     - 每一项均具有递减边际收益，因此 \(J_q\) 是单调子模函数；
     - 贪心迭代选择边际增益最大的单元，最多 \(B_q\) 步，满足 \(1-1/e\) 近似保证。
   - 最终按原始顺序组装选中的单元及其线程头，形成工作空间 \(W_q\) 提供给答案模型。

## 7. 优点

- **新颖视角**：将记忆从“检索相关记录”提升到“根据任务角色组织工作空间”，抓住了现有系统忽略的记忆角色差异问题。
- **两阶段组织**：局部线程 + 线程图保留了事件连续性、来源顺序和跨线程关系，有利于多跳与时间推理。
- **角色显式建模**：用可学习的角色需求和关系特征计算角色适应性，支持锚点/桥接/上下文等不同角色识别。
- **子模覆盖选择**：通过子模最大化选择互补记忆，避免重复和冗余，提升信息密度。
- **实验全面**：两个基准、四个骨干、六个消融变体、多类敏感性分析，结论稳健。
- **可解释性**：提供案例研究，展示工作空间如何覆盖 gold source 并支持答案生成。
- **实际效率权衡**：给出上下文长度、检索延迟和可调深度 \(H\)，具有工程参考价值。
