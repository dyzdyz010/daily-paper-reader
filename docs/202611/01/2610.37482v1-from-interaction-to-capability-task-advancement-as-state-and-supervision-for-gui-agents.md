## 摘要
GUI 记忆应保留过去动作的结果，并学习可复用操作。这在长程工作流中十分困难，因为智能体必须跨应用使用信息，且有用操作与失败尝试相互交织。我们提出任务推进记忆（TAM），将任务推进定义为经验证的任务进度，既支持当前任务执行，也学习可复用操作。在执行过程中，任务推进状态表示经验证的任务进度如何改变剩余目标，使智能体能够跨应用基于先前成果继续推进。每个任务结束后，推进监督识别并抽象产生经验证的局部结果的交互。所学操作保留所需输入、预期结果与验证条件之间的关系。这保留了成功任务和失败任务中局部成功的操作。在 MobileWorld 仅 GUI 任务上，仅使用推进状态就将成功率从 12.0% 提高到 28.2%。完整 TAM 相较最强评估基线在任务成功率上相对提升 17.6%，并将每个已解决任务的生命周期 token 减少 38.7%。在 SPA-Bench 上，TAM 在单应用英语 Level 3 设置中取得了最先进的任务成功率。

## Abstract
GUI memory should preserve the results of past actions and learn reusable operations. This is difficult in long-horizon workflows, where agents must use information across applications and useful operations are interleaved with failed attempts. We introduce Task Advancement Memory (TAM), which defines task advancement as verified task progress, and supports ongoing task execution and learns reusable operations. During execution, Task Advancement State represents how verified task progress changes the remaining goals, allowing the agent to build on earlier achievements across applications. After each task, advancement supervision identifies and abstracts the interactions that produced a verified local result. The learned operations preserve the relation between required inputs, expected outcomes, and verification conditions. This retains locally successful operations from both successful and failed tasks. On MobileWorld GUI-only tasks, Advancement State alone raises success from 12.0% to 28.2%. Full TAM achieves a 17.6% relative gain in task success over the strongest evaluated baseline and reduces lifecycle tokens per solved task by 38.7%. On SPA-Bench, TAM achieves state-of-the-art task success in the single-app English Level 3 setting.

## 1. 论文的核心问题与整体含义

- **研究背景**：GUI 智能体需要完成跨屏幕、跨应用的长程工作流。例如，在日历中确认会议后，还要依据已读到的会议时间通知参与者。
- **核心问题**：长交互历史中混杂着已完成工作、失败尝试和无效绕路，智能体难以判断任务已推进到哪一步，也难以把过去的成功操作复用到新任务。
- **现有方法的不足**：
  - 基于轨迹、工作流或技能的记忆往往绑定历史动作序列，界面变化后难以适应。
  - 仅以任务最终成功/失败作为反馈，会丢失失败任务中的局部成功，也可能保留成功任务中的无效尝试。
- **论文含义**：提出 **任务推进记忆（TAM）**，以“经验证的任务进度”作为统一记忆单元，同时支持在线执行与离线学习，使智能体既能利用已获取信息继续推进，又能从局部成功中抽象出可复用操作。

## 2. 论文提出的方法论

- **核心思想**：将“任务推进（task advancement）”定义为 GUI 观察确认某个先前未解决的需求被满足——或是获取了所需信息，或是达成了所请求的结果。每次推进都会减少仍需完成的工作，称为“任务约简（task reduction）”。
- **任务需求图**：任务初始化时，由 LLM 编译器将指令解析为需求图 \(Q=(V,E_Q)\)。节点 \(V\) 是需要获取的信息或需达成的结果，边 \(E_Q\) 表示依赖关系；每个需求有证据规则 \(V_q\)，用于判断其是否被满足。
- **任务推进状态（Task Advancement State）**：
  - 状态 \(S_t\) 记录每个需求的状态、已知值和证据。
  - 当需求从未解决（UNRESOLVED）变为已建立（ESTABLISHED），并满足验证条件时，记为一次推进 \(\text{Adv}(q)\)。
  - 已满足的需求从剩余工作中移除，但结果仍保留在状态中供后续需求使用。
  - 定义 **推进前沿** \(F_t=\{q\in U_t:R_q\subseteq K_t, S_t\models \gamma_q\}\)，即输入已齐备、分支条件成立且尚未完成的需求集合，用于指导下一步行动。
  - 状态更新区分草稿、尝试和确认结果：文本输入是草稿，点击保存是尝试，界面出现确认证据才接受为结果。
  - **证据缓存**保存源截图或裁剪，用于在源界面离开近期上下文后恢复信息。
- **推进监督（Advancement Supervision）**：
  - 每个推进都产生一个候选交互片段；任务结束后，LLM 审查器根据证据判断局部结果是否成立，并选择真正有助于该结果的步骤。
  - 学习到的操作称为 **推进算子（Advancement Operator）**：
    \[
    \kappa = \langle R_\kappa, \Delta_\kappa, V_\kappa, B_\kappa, \Gamma_\kappa, A_\kappa \rangle
    \]
    分别表示入口需求、预期推进、验证条件、对象角色、适用条件和 GUI 实现。
  - 抽象时用角色替换具体值，例如用“origin”“destination”替换具体地名；对象身份保持一致，确保输入、结果与验证目标指向同一实体。
  - 同一输入-结果关系的样本合并为同一算子，但保留不同 GUI 路线作为独立实现。
- **算子复用**：检索时先判断算子能否满足当前前沿需求的输入-结果关系，再检查存储 GUI 路线是否与当前界面兼容。若路线不兼容，仍可提供所需输入、预期结果和验证线索。
- **算法流程**（Algorithm 1）：编译需求 → 初始化状态/缓存/历史 → 循环观察、更新状态、检索证据与算子、采样动作、执行并更新 → 任务结束后回顾候选片段、抽象并固化算子。

## 7. 优点

- **任务中心设计**：以“经验证的任务进度”统一执行与学习，既表示剩余工作，又为可复用操作提供监督信号，概念清晰。
- **跨应用信息保持**：通过对象绑定和证据缓存，使已获取信息在应用切换后仍可用，解决了长程工作流的关键痛点。
- **有效利用失败样本**：从失败任务中保留局部成功操作，扩展了学习材料来源，而非仅依赖任务最终成功。
- **语义与 GUI 路线分离**：算子将“需要什么输入、得到什么结果、如何验证”与具体 GUI 实现解耦，在界面变化时仍可复用任务知识。
- **成本控制良好**：在达到最高成功率的同时，生命周期 token 低于多数基线，说明没有靠堆叠上下文取得性能。
- **消融充分**：清晰展示推进状态、证据缓存和算子图各自的贡献，增强了结论的可信度。

## 8. 不足与局限

- **对模型解释能力的依赖**：任务需求解析、GUI 证据识别和结果验证都依赖 LLM 的模型化解释，在结果线索模糊时可能出错，尤其会影响在线执行和离线学习。
- **评估范围有限**：实验集中在移动端 GUI 和英语任务，尚未扩展到网页、桌面端或多语言场景，限制了跨界面类型的迁移性结论。
- **长期记忆维护未充分研究**：虽然算子图支持累积，但更长任务流和频繁应用更新会带来检索质量和记忆维护成本问题；论文仅在“未来工作”中提及算子修订与淘汰，而未实验验证。

- **硬件与训练成本未报告**：论文未提供 GPU 型号、数量或总推理时间等算力细节，难以评估实际部署开销。
