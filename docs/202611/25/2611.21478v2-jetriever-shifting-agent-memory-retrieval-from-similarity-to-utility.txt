# Shifting Agent Memory Retrieval from Similarity to Utility 

Ruizhe Li, Licheng Zhang, Mingxuan Du, Zhendong Mao 

University of Science and Technology of China (USTC) Contact email: imlrz@mail.ustc.edu.cn Project repository: github.com/imlrz/Jetriever Preprint 18 November 2026 

Abstract. Whether a stored memory helps answer a user’s question often depends on world knowledge rather than surface similarity. Jetriever replaces similarity search with full-pool utility scoring: given a query, it uses Jev—an LLM-derived System One decision model—to score every stored memory for the probability that it is useful to the answer, ranking the memory pool directly by those probabilities. On InMind’s 125 indirect-query tasks, Jetriever places the gold exchange first in 84.8% of cases (versus 1.6% for BM25 and 0.0% for MiniLM with user-turn in-dexing) and reaches 76.0% end-to-end Application, compared with at most 16.0% across published retrieval and memory systems. A controlled 20-question compar-ison disentangles recognizing implicit evidence from ranking it properly: Jev and Qwen3.5-9B both recover 90% of gold exchanges within the top 50 (versus 30% for the BERT-based decision model Laya), yet at rank 1 Jev reaches 85% while Qwen3.5-9B drops to 40%. On a dimension-proportional random sample of 60 MemoryAgentBench questions, Jetriever raises the four-dimension average from 44.3% (ReFind) to 55.4%, at a mean retrieval cost of $0.00834 per InMind query and $0.03103 per MAB query. Together, these results show that effective utility retrieval hinges on combining broad world knowledge, calibrated ranking proba-bilities, and affordable full-pool evaluation.

1 Introduction 

Agent memory systems have largely inherited their retrieval objective from document search: given a query, fetch stored records whose words or em-beddings resemble it. When a question explicitly names the relevant enti-ties or events, textual similarity works remarkably well—so well that lexi-cal BM25 or raw-dialogue RAG routinely matches or outperforms elaborate graph- and summary-based memory systems [2, 3, 4, 5]. InMind exposes where that assumption collapses [1]. A stored remark that the user has a nut allergy is critical when they later ask for a macaron recipe, even though

Bridging the two requires knowing that macarons are made with almond flour; similarity search leaves that mem-ory behind, and an answer-stage LLM cannot reason over evidence that retrieval never surfaces. Placing an LLM upstream of the retriever to rewrite or expand queries does not break this bottleneck [6, 3], because the agent would have to guess ev-ery relevant hidden association before seeing what is actually stored. While the space of hypothetical associations is effectively unbounded, a user’s ac-tual memory store is finite. Jetriever exploits that asymmetry: instead of inventing search queries, it evaluates every stored memory directly against the question for whether it contributes to a good answer. Making full-pool utility scoring work requires a scorer with broad world knowledge, cali-brated probabilities that separate decisive evidence from loosely related history, and low enough cost and latency to evaluate hundreds or thou-sands of candidates per query. We build Jetriever on Jev, an LLM-derived System One decision model trained via reinforcement learning for cali-brated decisions (RLCD) to return structured probabilities without autore-gressive text generation [7, 8]. Across three sets of experiments, we evaluate both end-to-end retrieval performance and the mechanism behind it. On InMind’s 125 indirect-query tasks, Jetriever lifts rank-1 gold-exchange recall from near zero under BM25 and MiniLM to 84.8%, bringing end-to-end personalized Application to 76.0% against an 84.0% oracle upper bound. A controlled 20-question comparison against a ModernBERT decision model ( Laya )[13] and a post-trained generative LLM ( Qwen3.5-9B ) [14] isolates why both pretraining scale and decision calibration are essential: world knowl-edge governs whether implicit evidence is recognized within the top 50, whereas probability calibration governs whether it rises to rank 1. Finally, on a stratified 60-question sample of MemoryAgentBench [2], Jetriever outperforms ReFind across all four competency dimensions at an average retrieval charge of roughly one to three US cents per query. 

2 From similarity to utility 

For years, agent memory architectures and memory benchmarks have co-evolved around a search-engine view of relevance. Most benchmarks test explicit fact recall, state updates, or entity-linked multi-hop questions in which the prompt itself supplies clear lexical or semantic anchors [2]. Under those conditions, surface similarity is hard to beat. In ReFind’s six-subtask evaluation, single-shot BM25-RAG achieves a 48.8% macro-average—ahead of every dense retriever in the comparison—and agentic BM25 search over raw chat logs reaches 58.2% [3]. Wang et al. observe the same pattern in a broader RAG scaling study [4], while Bao et al.’s RAW-RAG indexes unprocessed dialogue with dense retrieval and cross-encoder reranking to outperform structured memory systems in six of seven settings across four benchmarks [5]. Whenever the decisive memory shares words or entities with the user’s question, similarity retrieval is already strong.

The trouble begins when a memory’s value lies in its utility to the answer rather than its textual resemblance to the query [1]. Knowing that a user is allergic to nuts changes how an assistant should respond to “Any mac-aron recipes?” because macarons typically use almond flour. Knowing that there are lilies in the living room matters when the user asks about adopt-ing a cat because lilies are lethally toxic to cats. In both cases, query and memory share neither vocabulary nor surface topic; the link lives entirely in world knowledge. InMind quantifies how severely current systems fail this test: across its 125 indirect-query tasks, giving GPT-5-mini the target memory directly in context yields an 84.0% Application score, whereas six representative memory architectures reach at most 14.4% end-to-end (and naive embedding RAG at most 16.0%) [1]. Modern LLMs already know how to connect the dots once both pieces appear in the prompt; the failure happens earlier, when retrieval leaves the decisive memory behind. Putting an LLM into the search loop does not resolve this bottleneck ei-ther. Agentic frameworks such as A-RAG [6] and ReFind [3] let an LLM formulate keyword or semantic queries iteratively. Yet before querying the index, the agent sees only the user’s request. Upon seeing “I’m think-ing of getting a cat,” it would have to spontaneously hypothesize “lilies” or “toxic houseplants”—alongside allergies, lease clauses, travel habits, ex-isting pets, and countless other latent hazards—before a similarity index could return the lily conversation. The space of world-knowledge associa-tions is open-ended, and no small budget of query expansions can cover it. What is intractable in query space, however, becomes tractable in memory space: we cannot enumerate every hypothetical hazard in the world, but we can inspect every memory we have actually stored. 

3 Why a decision model? 

> THREE THINGS
> Remember these three. We test each of them in the experiments.

Evaluating stored memories directly against a query turns retrieval from index lookup into per-candidate judgment: given query q and memory mi,would knowing mi materially improve the answer? For full-pool scoring to succeed as a retriever, the underlying scorer must satisfy three require-ments simultaneously—a combination that neither BERT-era classifiers nor conventional generative LLMs offer. 

Broad world knowledge. Recognizing that a nut allergy bears on macarons, or that household lilies bear on adopting a cat, requires open-domain factual knowledge that appears in neither the query nor the stored turn. Bidirectional encoders and lightweight cross-encoders built on BERT-scale backbones [17, 18] are fast and straightforward to finetune, but they lack broad world knowledge. Only models built upon large-scale language-model pretraining carry enough factual breadth to bridge un-stated associations across arbitrary everyday domains. TypeSafe’s System One model Jev is adapted from a pretrained LLM foundation [7, 8], re-taining open-world knowledge while repurposing the model from text generation to bounded judgment. 

Calibrated ranking probabilities. World knowledge allows a model to 

recognize useful evidence, but retrieval over hundreds of conversational 

> 3

turns is a ranking problem. Real chat histories contain many turns that touch on related themes or look loosely plausible. When an instruction-tuned chat LLM is asked whether a candidate memory is helpful—or read out via answer-token probabilities—conversational post-training and ten-dencies toward sycophancy and over-agreement [12] often push its scores toward permissive endorsements or poorly separated middle-range proba-bilities. If dozens of tangentially related turns receive high or nearly tied scores, the truly decisive memory gets crowded out of the top-k window. Jev is trained via RLCD specifically so that its output probabilities track empir-ical likelihoods rather than conversational preference [7], producing sharp separation between decisive memories and plausible background chatter. 

Affordable full-pool scoring. Scoring every stored candidate eliminates premature similarity filtering, at the price of making N model evaluations for a store of N memories. Running an autoregressive chat LLM hun-dreds or thousands of times per user query is prohibitively slow and ex-pensive. Jev dispenses with free-form token generation altogether: a re-quest supplies context and evaluates bounded decision primitives—multi-way selection ( Choice ), ordinal rating ( Score ), or binary probability ( Noul )— using parallel output sampling [8, 9]. Because each call returns a compact probability without chain-of-thought or autoregressive decoding, exhaus-tive evaluation across hundreds or low thousands of memories becomes practical both in latency and in cost. 

4 Jetriever 

Jetriever is deliberately minimal. Rather than compressing conversations into summaries or entity graphs at write time—where details whose future relevance cannot yet be foreseen are easily lost—it retains raw dialogue units and performs exhaustive utility scoring at read time. Given a query q

and candidate memories {m1, . . . , m N }, Jetriever evaluates each pair (q, m i)

independently via Jev’s binary Noul primitive, which returns the calibrated probability s(q, m i) ∈ [0 , 1] that a natural-language criterion holds [9]. On InMind, we query Noul with the criterion: “Does this memory chunk contain personal information needed to give a correct, personalized response to the user query, including indirectly relevant information? Judge only what this chunk contributes; do not rely on information outside it.” On the broader MemoryAgentBench suite, we ask whether the candidate contains information needed to answer the query correctly, covering both directly stated facts and necessary supporting context. Jetriever then ranks the entire candidate pool directly by s(q, m i):

> 5.1.1 Benchmark and setup

InMind serves as both our motivating failure case and our primary test of utility retrieval [1]. Each of its 125 indirect-query tasks plants a personal fact into a 47-session multi-turn history (followed by 38 distractor sessions) and later poses a natural request whose connection to that fact hinges on world knowledge rather than shared vocabulary. In our retrieval evaluation, every method ranks the exact same pool of 241 user–assistant exchanges per query: 240 background exchanges plus one injected gold exchange. Jetriever scores each complete exchange via Jev. As matched similarity controls, we evaluate BM25 (lowercased alphanu-meric tokenization, k1 = 1 .2, b = 0 .75 ) [16] and MiniLM ( all-MiniLM-L6-v2 ,normalized cosine similarity, 256-token limit) [19, 20], indexing either the user turn alone (to strip assistant boilerplate) or the full exchange.

Calibrated probabilities govern top-1 ranking. Recognizing that the gold exchange matters somewhere in the top 50, however, is very different from ranking it first. Among 241 historical turns, plenty of background exchanges look loosely relevant or plausibly helpful to a user’s question. Because Qwen3.5-9B’s token probabilities are not calibrated to separate

Both models possess the world knowledge to see why the gold exchange is rele-vant; probability calibration determines whether that exchange actually reaches the answerer at small k.

6 Discussion 

6.1 Why System One decision models fit retrieval 

Section 3 argued that full-pool utility retrieval demands broad world knowledge, calibrated ranking probabilities, and low per-candidate cost— three properties tested empirically in Section 5 and summarized in Table 5. BERT-scale classifiers are cheap and produce sharp decision boundaries on narrow tasks, yet lack the open-world knowledge required when rele-vance hinges on unstated facts. Generative chat LLMs possess that world knowledge, but incur autoregressive overhead and produce uncalibrated token probabilities that struggle to push decisive evidence above plausible distractors. By distilling or adapting an LLM foundation into a non-generative, calibration-trained System One model, Jev hits the operating point where full-pool utility ranking works. Stepping back, the three retrieval paradigms ask fundamentally different questions. Similarity search asks which stored text sounds like the query .Agentic query expansion asks which hidden connection an LLM can guess before looking at the store . Jetriever asks whether each stored memory actu-ally changes how the query should be answered . Whenever personal context

6.2 Scaling limits 

Jetriever’s obvious constraint is linear scaling: scoring N memories takes 

O(N ) decisions per query. At the scales studied here—hundreds of ex-changes in InMind and roughly a thousand conversations on average in MAB—high concurrency keeps retrieval within a few cents and seconds. For lifelong agents accumulating tens or hundreds of thousands of turns, however, naive per-pair API calls will eventually grow too costly and too slow. 

6.3 Toward lighter decision models with world knowledge 

When faced with O(N ) scaling, the reflexive retrieval-engineering instinct is to reintroduce a cheap BM25 or embedding pre-filter ahead of the scorer. For utility retrieval, however, that shortcut defeats the entire purpose of the system: any implicit memory whose connection lives in world knowl-edge will be silently discarded by a similarity first stage before the deci-sion model ever sees it. Keeping full-pool utility scoring intact therefore points toward a more fundamental model-design challenge: building sub-stantially lighter, faster System One decision models that still retain broad world knowledge .Figure 1 illustrates the tension clearly: shrinking from Qwen3.5-9B to 

Qwen3.5-4B already erodes implicit recall, and dropping to the 421M-parameter Laya encoder loses most of it. Closing this efficiency–knowledge gap—through compact LLM-derived decision architectures, open-weight RLCD-style calibration training, and precomputed memory represen-tations that amortize encoding across incoming queries—is the most promising path to scaling full-pool utility retrieval to lifelong agent mem-ory.

7 Conclusion 

ONE LINE 

Find the memory that matters to the answer, not just one that sounds similar. 

Jetriever shifts agent memory retrieval from matching surface text to scor-ing downstream utility over the entire memory pool. Powered by Jev, this simple design recovers implicit-association memories on InMind that lexi-cal, dense, and agentic memory baselines miss, improves multi-competency performance over ReFind on MemoryAgentBench, and keeps per-query re-trieval costs in the cent range. Controlled comparisons further show why world knowledge alone is not enough: while both an ordinary LLM and Jev recognize implicit evidence within a wide shortlist, calibrated decision probabilities are what place the decisive memory at rank 1. Pushing full-pool utility scoring to much larger lifelong stores should not mean retreat-ing behind similarity filters, but developing lighter, faster System One de-cision models that carry broad world knowledge at a fraction of today’s com-pute.
