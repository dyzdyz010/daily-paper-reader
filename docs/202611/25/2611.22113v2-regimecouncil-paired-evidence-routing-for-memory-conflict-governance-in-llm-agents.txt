# ABSTRACT 

Alongside memory storage and retrieval, a fundamental challenge in long-term LLM agent systems is how the agent should act when stored memories conflict with an evolving world. Facts often go stale without explicit deletion, so the conflict surfaces before the store is refreshed: delayed feedback shows that acting on one outdated record hurt, but not whether suppression should stay on that fact (a local policy ) or extend to other stored facts (a global policy ). Existing systems hard-code one of these scopes at design time. We formulate this online choice, under hidden validity and delayed feedback, as memory conflict governance , and propose RegimeCouncil , a lightweight router that keeps both scopes as advisors and arbitrates between them without retraining the LLM. Each memory-assisted response is scored against a no-memory anchor , by off-path paired comparison or by inverse-propensity estimation from the executed action alone. A Local Advisor 

tracks only the queried fact, a Global Advisor pools recent outcomes across the store, and an asymmetric Meta Governor follows Local by default, switching to Global only when pooling yields a strictly positive recent utility margin. We prove that using delayed outcomes escapes the prompt-only regret floor, that neither fixed scope suffices alone, and that this margin gate switches within bounded time. On LongMemEval streams, historical drift in TempLAMA and TAQA, delays 

τ ∈ [1 , 96] , and sparse or bandit feedback, with Qwen3-30B-A3B and GPT-4o, RegimeCouncil outperforms the better fixed scope in all 30 held-out settings—by 

5.2–7.3 points on disagreement episodes and +27 .9 points over standalone cold-start fallback under clustered shifts—while cutting harmful stale-memory use at microsecond overhead. 

# 1 INTRODUCTION 

Long-term memory enables language agents to personalize decisions across extended interactions (Park et al., 2023; Packer et al., 2023), yet users’ circumstances, preferences, and external facts inevitably change over time. Alongside deciding what to store and how to retrieve it, determining how an agent system should act when stored memories conflict with an evolving reality is therefore a fundamental problem in agent memory (Maharana et al., 2024; Wu et al., 2025; Hu et al., 2026). Existing memory frameworks largely treat conflict resolution as an explicit write-time operation— overwriting or re-ranking an entry once a timestamped correction or replacement value is explicitly provided (Chhikara et al., 2025; Rasmussen et al., 2025). In deployed assistants, however, stored facts routinely go stale silently without manual deletion, while store updates may await asynchronous consolidation or arrive as negative feedback without stating every replacement value. Consequently, memory conflicts frequently surface before the memory store is refreshed, when delayed downstream feedback—such as a user complaint, a thumbs-down, or a failed task—reveals that acting on a stored record hurt. While recent LLM memory architectures advance storage, compression, and retention (Packer et al., 2023; Chhikara et al., 2025; Rasmussen et al., 2025; Zhou et al., 2026; Zhang et al., 2026; Kang et al., 2026b;a), they implicitly fix one of two opposite sharing scopes when adapting memory use from past outcomes—which we define as a local policy and a global policy (Figure 1, bottom). A 

local policy confines each outcome to the single queried attribute, as in per-item utility updates (Zhang et al., 2026) or isolated record updates (Chhikara et al., 2025; Rasmussen et al., 2025): it avoids cross-fact interference under isolated changes, yet leaves correlated stale attributes active after broader shifts—repeating stale-memory errors one attribute at a time—and offers no guidance on unseen attributes. A global policy , by contrast, pools recent outcomes across all stored facts via a shared confidence gate or recency window: it halts correlated failures rapidly and warm-starts unseen facts, yet lets errors on a few volatile attributes disable valid, stable memories. Deciding online whether a memory conflict reflects isolated per-fact drift or a store-wide shift—under hidden validity and delayed feedback—is a fundamental sequential decision problem we term memory conflict governance .To solve this problem without retraining the LLM or adding user-facing latency, we propose Regime-Council , a lightweight three-module router. First, an anchor-referenced scorer isolates whether memory helped or hurt on each revealed episode by comparing the memory-assisted answer against a no-memory anchor —supporting both off-path paired evaluation and unbiased inverse-propensity estimation from executed-action-only bandit feedback. Second, two advisors operate at complemen-tary scopes: a Local Advisor tracks the latest revealed outcome on the queried fact alone (either abstaining conservatively on local ties to minimize harmful exposure, or deferring ties to global evidence as RegimeCouncil-TD for long-delay cold-start coverage), while a Global Advisor pools recent outcomes across all stored facts. Third, an asymmetric Meta Governor follows the Local Advisor by default and switches to the Global Advisor only when global pooling accumulates a strictly positive counterfactual utility margin over recent revealed episodes. Each module is directly grounded in a formal guarantee: delayed outcome replay is necessary to escape the constant regret floor of prompt-only gates (Proposition 1); neither fixed scope suffices alone, motivating dual advisors (Proposition 2); and margin-gated arbitration switches within bounded decisions under feedback delay τ (Proposition 3). 2Our main contributions are threefold: (1) Problem and architecture: We formulate memory conflict governance and introduce RegimeCouncil , an O(1) -time online router supporting both paired and bandit feedback at roughly 2.3 μs per decision and zero added critical-path LLM calls. (2) Theoretical guarantees: We establish an observation-only regret floor, linear-regret separations against both fixed scopes, and finite-time switching bounds under delayed feedback (Propositions 1– 3). (3) Comprehensive evaluation: Across LongMemEval update streams (16- and 54-fact pools) and real historical chronologies on TempLAMA and TAQA with Qwen3-30B-A3B and GPT-4o, RegimeCouncil outperforms the better fixed scope in all 30 held-out settings ( 33 ,792 episodes), maintains consistent gains across multi-step delays ( τ ∈ [1 , 96] ), sparse/noisy/bandit feedback, and clustered shifts ( +27 .9 points and 59% fewer harmful exposures than standalone cold-start fallback), while ablating any module reduces accuracy by 2–7 points. 

# 2 RELATED WORK 

Long-term agent memory and knowledge updates. Agent memory systems extend context via tiered storage, retrieval, and temporal knowledge graphs (Park et al., 2023; Packer et al., 2023; Chhikara et al., 2025; Rasmussen et al., 2025), learned compression or item-level utility reweighting (Zhou et al., 2026; Zhang et al., 2026), and budgeted retention (Kang et al., 2026b;a). Benchmarks such as LoCoMo, LongMemEval, and MemoryAgentBench identify outdated facts and knowledge updates as a primary failure mode over multi-session dialogues (Maharana et al., 2024; Wu et al., 2025; Hu et al., 2026). However, standard evaluations expose explicit timestamps in the prompt so a recency-aware reader can spot the latest write directly, and existing memory systems fix their feedback scope at design time—updating either the single accessed record (Zhang et al., 2026; Chhikara et al., 2025; Rasmussen et al., 2025) or a global retrieval gate. We instead address silent staleness before store consolidation, dynamically arbitrating between fact-local and store-wide feedback scopes online. 

Non-stationarity and feedback sharing scope. Concept-drift detectors, non-stationary bandits, and strongly adaptive online learners handle changing environments by discounting older observations along a single stream (Gama et al., 2014; Besbes et al., 2014; Cheung et al., 2019; Daniely et al., 2015; Jun et al., 2017). Multi-fact agent memory induces structured non-stationarity across K keys: facts may drift asynchronously (where cross-fact pooling causes interference) or shift in correlated clusters (where pooling accelerates recovery). Rather than tuning a single forgetting window, RegimeCouncil maintains both a per-key window and a store-wide pooled window and selects the governing scope online. 

Expert advice and partial observability. Switching-expert algorithms track changing best predic-tors over time (Herbster & Warmuth, 1998; Daniely et al., 2015), while POMDPs formalize decision making when latent state is hidden from the current observation (Krishnamurthy et al., 2016; Jin et al., 2020). Generic expert-tracking rules treat experts symmetrically without exploiting relational key structure or per-query baselines. RegimeCouncil instead pairs memory against a no-memory anchor to cancel query-difficulty variance (directly or via inverse-propensity bandit estimates) and applies an asymmetric Meta Governor that defaults to the unbiased Local Advisor, granting Global overrides only when cross-key pooling earns strictly positive recent surplus.

# 4 EXPERIMENTS 

We evaluate RegimeCouncil (abbreviated RC, with RC-TD denoting its tie-deferral variant; §3.3) along four questions: (1) whether online scope arbitration outperforms the better fixed-scope advisor on controlled update streams (§4.1); (2) whether the frozen router transfers to real-world historical drift (§4.2); (3) whether all three modules—and the Meta Governor beyond cold-start fallback—are necessary across asynchronous and clustered regimes (§4.3); and (4) how the router behaves under multi-step delays, imperfect or bandit feedback, and runtime constraints (§4.4). Throughout all experiments, the Local Advisor uses a single-outcome window, the switching threshold is fixed at zero, and the global and arbitration window sizes (32 and 8) are selected once on disjoint development streams and held frozen across every benchmark. Removing any of the three components degrades performance across benchmarks and models (Appendix B.4, Table 7). On Schedule A, removing the Global Advisor lowers full-stream accuracy by 2.0–2.3 points across Qwen and GPT-4o, while removing the Local Advisor lowers accuracy by 3.7–6.0 points and more than doubles harmful stale-memory exposures on GPT-4o (rising from 9 to 19 episodes). Removing the Meta Governor reduces full-stream accuracy by 6.5–6.8 points (17.2–21.8 points on disagreements), with comparable drops of 3.0–7.0 points on TempLAMA and TAQA. We next ask whether the Meta Governor can be replaced by a simpler cold-start fallback that consults the Global Advisor only when the Local Advisor has no decisive signal, while trusting Local otherwise. # 5 CONCLUSION 

We address a fundamental problem in long-term agent memory: governing memory conflicts when stored facts become stale before consolidation. Within this pre-consolidation window, delayed negative feedback cannot be handled reliably by any single fixed sharing scope—fact-local isolation misses cold-start transfer and correlated shifts, whereas store-wide pooling lets volatile attributes suppress valid stable ones. Formulating this challenge as memory conflict governance , we introduced RegimeCouncil, an anchor-referenced router that combines a Local Advisor, a Global Advisor, and an asymmetric Meta Governor across paired and bandit feedback modes. Theory and experiments on LongMemEval, TempLAMA, and TAQA show that RegimeCouncil consistently outperforms 9fixed-scope policies, symmetric trackers, and standalone cold-start heuristics under multi-step delays and imperfect feedback at microsecond cost, pointing toward multi-scope governance in broader tool-using agents.

Local sparsity. Present a sequence of distinct keys, each visited once, all sharing a common positive memory advantage dt = +1 . On a fresh key the conservative Local Advisor has an empty per-key window and defaults to the anchor, incurring a constant per-step gap. Once the first outcome is revealed, within τ steps, the Global Advisor’s pooled sum is strictly positive and transfers the shared advantage to every subsequent new key. Repeating over T distinct keys yields linear loss for Local relative to Global. The two streams are disjoint in the failure they induce: the first makes pooling biased, the second makes isolation uninformative. No single fixed scale is therefore uniformly sufficient. This appendix details how the delayed-feedback streams are constructed, how completions are scored, and how performance breaks down across individual settings referenced in Section 4. B.1 ITEMS AND CACHED ANSWERS 

The primary confirmatory set consists of 16 LongMemEval knowledge-update questions (Wu et al., 2025) whose initial and updated answers were manually audited, selected deterministically via SHA-256 hash from audited items containing temporal cues prior to any router evaluations; the full 54-key audited pool is evaluated in Table 2 and Appendix B.6. To enforce decision-time unobservability (Assumption 1), we apply a deterministic lexical filter that strips explicit temporal pointers (such as currently, now, previously, and no longer) identically across all items without altering facts or adding distractors. Each key thus presents a colliding observation consisting of two unordered memory records and a question with no recency cue. For each key and model, we cache three completions once: answering without memory (the no-memory anchor), answering with the old snapshot, and answering with the updated snapshot. At episode t, ut, 0 scores the no-memory answer against the currently valid ground-truth answer, and 

ut, mem scores the answer produced from the currently committed snapshot (falling back to ut, 0 before the first snapshot commit). A completion scores 1 if normalized strings match (exact or substring match) and 0 otherwise. Caching ensures that every routing baseline observes identical LLM outputs on every episode, isolating routing decisions from generation variance. B.2 HIDDEN SCHEDULE AND DELAY
