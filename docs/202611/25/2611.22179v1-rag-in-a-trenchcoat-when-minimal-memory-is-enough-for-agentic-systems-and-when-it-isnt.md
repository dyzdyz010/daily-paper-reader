## 摘要
智能体记忆研究在检索增强生成之上不断累积提取、取代、反思和图谱合成等原语。然而，我们发现在所测试的记忆基准中，这些原语几乎都不值得其成本：我们通过 BRIDGE 展示了这一点。BRIDGE 是一种刻意最小化的 RAG 记忆，具有链式观察笔记、混合 BM25 与余弦检索以及按时间顺序渲染，在 LongMemEval-S 和 BEAM 上达到与先前 SOTA 在 bootstrap 置信区间内的同等水平，并在 EverMemBench 上在匹配 reader 的条件下比最佳记忆基线高出 5.7-6.3 分。它每个查询仅使用约 5-7K 个 reader 提示 token，每次摄取或查询只需一次 LLM 调用。我们认为这种同等水平本身就是结果：标准基准衡量的是记忆检索到什么，而不是记忆在智能体行动时能促成什么。为了检验后者，我们引入了五个对抗性探针（规则应用 +-、模式归纳 风格/程序性、动态多轮），在生成时由一个跨供应商验证链进行评判；其中每个查询只能通过应用一条被记住但查询中从未提及的规则或模式来解决。在 5 个探针 × 20 个场景中，没有任何架构能普遍获胜：原子事实抽取器（LangMem）在规则应用中获胜，而 BRIDGE 的块摘要记忆在模式归纳中获胜。这一结果在四个领域、三种评分器和三种 reader 家族中均成立。每种设计都在对方获胜的地方失败，原因是一个召回基准无法看到的：原子事实抽取器丢弃了所示模式的形式，而块摘要记忆检索到规则但 reader 并未按规则行动，而更突出地呈现规则可以在很大程度上弥合这一差距。区分记忆设计的不是它们检索到什么，而是它们使智能体能够做什么，而这正是智能体记忆应当被评估的内容。

## Abstract
Agentic memory research has accumulated extraction, supersession, reflection, and graph synthesis on top of retrieval-augmented generation. However, we found that almost none of those primitives earn their cost in our tested memory benchmarks: we show this with BRIDGE, a deliberately minimal RAG memory with chained observation notes, hybrid BM25 with cosine retrieval, and chronological rendering, which reaches parity within bootstrap CI with the prior SOTA on LongMemEval-S and BEAM, and beats the best memory baseline on EverMemBench by 5.7-6.3 points at matched reader. It runs at ~5-7K reader-prompt tokens per query, using a single LLM call for each ingestion or query. We argue that this parity is itself the result: standard benchmarks score what memory retrieves, not what memory enables when the agent acts. To test the latter, we introduce five adversarial probes (Rule Application +-, Pattern Induction Style / Procedural, Dynamic Multiturn) judged at generation time by a cross vendor verification chain, where each query can only be solved by applying a remembered rule or pattern it never mentions. Across 5 probes x 20 scenarios, no architecture wins universally: atomic fact extractors (LangMem) win rule application, while BRIDGE's block-summary memory wins pattern induction. This result holds across four domains, three graders, and three reader families. Each design fails where the other wins, for reasons a recall benchmark cannot see: atomic-fact extractors discard the form a demonstrated pattern takes, while block-summary memory retrieves the rule but the reader does not act on it, a gap that presenting the rule more prominently largely closes. What separates memory designs is not what they retrieve but what they enable an agent to do, and that is what agentic memory should be evaluated on.

## 1. 论文的核心问题与整体含义

- **研究背景**：近年来智能体记忆（agentic memory）研究在检索增强生成（RAG）之上不断叠加复杂原语，如原子事实提取、取代/超时知识图谱、反思或反刍、工作记忆缓存、跨会话综合等。每个原语都被视为对朴素 RAG 的必要改进。
- **核心问题**：这些复杂记忆原语是否真的在记忆基准上物有所值？现有基准是否真正衡量了“记忆使智能体能够做什么”，而不仅仅是“记忆检索到了什么”？
- **整体含义**：
  - 作者提出一个刻意极简的 RAG 记忆系统 BRIDGE，在三个标准记忆基准上达到与 SOTA 系统同等或更好的效果，说明**现有召回型基准无法区分记忆设计**。
  - 进一步设计五个对抗性探针（需要智能体在生成时主动应用记忆中从未被请求提及的规则或模式），结果发现**没有一种记忆架构能在所有探针上获胜**，不同设计在不同能力上各有胜负。
  - 因此主张：智能体记忆评估应聚焦于记忆所**使能的行为**，而不是仅评估检索结果。

## 2. 论文提出的方法论

### 2.1 BRIDGE：极简 RAG 记忆
- **核心思想**：在朴素 RAG 之上只添加三个轻量原语，不引入图数据库、取代层、反思步骤、工作记忆缓存或智能体框架集成。
- **摄取（Ingestion）**：
  - 将长期对话按会话划分，使用“自然边界分块”（如会话结束、工具调用结束、主题交换等）或 token 上限（2000 tokens）进行分块。
  - 每块由一个抽取 LLM 生成 XML 标记的观察笔记 `o_{t,k}`，总结优先级、偏好、状态变化、用户原始措辞等；抽取时能看到最近 `W=10` 条先验笔记，实现跨块上下文链。
  - 同时持久化原始文本 `x_{t,k}` 和蒸馏笔记 `o_{t,k}`；笔记用冻结句子编码器嵌入为 `e_{t,k}`。
- **检索（Retrieval）**：
  - 对查询 `q`，计算两个排序列表：
    - 余弦相似度：`s_cos(q,B) = (e_q · e_B) / (||e_q|| ||e_B||)`
    - BM25：`s_bm25(q,B) = BM25_{k1,b}(q, o_B || x_B)`，在笔记与源文本拼接上索引。
  - 各自保留 top-60，用倒数排名融合（RRF）合并，`k_rrf=60`：
    - `s_rrf(q,B) = 1/(k_rrf + r_cos(B)) + 1/(k_rrf + r_bm25(B))`
- **渲染（Rendering）**：
  - 选 top-K=10 个块；其中 top-r=3（按余弦）作为原始文本槽，其余 K−r 块仅显示摘要 `Summary: o_{t,k}`。
  - 将选定块按全局时间顺序 `(t,k)` 升序重排后拼接给 reader。
  - Reader 是单次 LLM 调用，温度 0，wrapper prompt 要求遵守会话日期并主动应用记住的约定。

### 2.2 对抗性探针（Adversarial Probes）
- **设计目的**：测试记忆是否在生成时被**应用**，而非仅被检索。每个探针的请求从不提及它所依赖的记忆。
- **五种探针**（见表 1）：
  1. **RA +（规则应用正向）**：历史中有一条规则作为闲谈出现，请求是规则适用领域的新任务，通过标准是应用该规则。
  2. **RA −（规则应用禁令）**：历史中有一条禁令（如禁用 `eval()`），请求的明显解法是被禁方法，通过标准是避免被禁做法。
  3. **PI-S（模式归纳-风格）**：历史中代码共享从未明说的约定（如错误格式），请求同类新代码，通过标准是遵循约定。
  4. **PI-P（模式归纳-程序）**：历史中四个案例展示相同步骤流程，请求新案例步骤，通过标准是遵循流程。
  5. **DM（动态多轮）**：复用 RA+ 语料，但替换为 5 轮模拟用户对话，评分最终轮和逐轮回归。
- **生成与评分**：
  - 每个场景由强前沿模型生成并存储，所有系统看到相同数据。
  - 评分器在生成时判断生成答案是否遵守场景约束（`applied` / `violated` / `n/a`），通过率 = `n_applied / (n_applied + n_violated)`。
  - 评分器来自与生成器、Oracle、reader 不同的供应商，避免同族偏差。
- **公平比较协议**：所有系统使用相同 reader、嵌入器和评分器；每个基线获得约 100 词 wrapper prompt 说明其原生原语，并按文档推荐进行调谐；BRIDGE 在探针上不修改内部配置。

## 3. 实验设计

### 3.1 标准记忆基准
- **BEAM 100K**：使用 GPT-4.1-Nano reader，与 Vanilla RAG、LIGHT 对比，报告 10 能力均值。
- **EverMemBench**：使用 GPT-4.1-Mini 和 Gemini-3-Flash 两个 reader，与 Full-Context（oracle）和 MemOS（论文最佳记忆系统）对比，报告 9 维度均值。
- **LongMemEval-S**：使用 GPT-4o reader，与 Naive RAG、Zep、Supermemory、EmergenceMem、Oracle 对比，报告 6 类别准确率。

### 3.2 对抗性探针
- **方法对比**：BRIDGE 对比 Mem0、LangMem、Graphiti，并设置强模型 Oracle（完整历史，无检索瓶颈）作为参考上限。
- **场景规模**：原始 5 探针 × 20 场景（软件/基础设施角色）；扩展 87 个场景到三个新领域（临床运营、法律合规、金融运营）；扩展 80 个硬难度场景（RA+ 和 PI-P 的 Level 2、3）。
- **鲁棒性检验**：
  - 评分器：用 GPT-5 和 GPT-4.1-mini 重新评分所有答案（跨供应商）。
  - Reader：替换为 Llama-3.3-70B 和 Qwen2.5-7B，检查符号方向。
  - 重复运行：对四个单轮探针运行 3-4 次。

### 3.3 消融与诊断
- **跨基准原语消融**：在三个标准基准上逐一移除五个原语（先验笔记链、原始文本槽、时间排序、仅 BM25、仅余弦），并做逐类别分析。
- **呈现诊断**：在 RA+ 上保持存储和检索不变，只改变呈现方式（顶部列出“常驻指令”），与通用摘要控制对比。
- **路由诊断**：仅用请求训练/测试分类器，预测需要规则还是模式，准确率接近随机。

## 6. 论文的主要结论与发现

- **标准基准上，极简 RAG 记忆与复杂记忆系统无法区分**：
  - BRIDGE 在 LongMemEval-S 和 BEAM 上与 SOTA 在 bootstrap CI 内持平；在 EverMemBench 上比最佳记忆基线高 5.7–6.3 分。
  - 这说明现有基准衡量的是**检索**，而非记忆**使能行动**。
- **对抗性探针上，记忆设计出现明显分化，且无架构全胜**：
  - 原子事实抽取器（LangMem）在规则应用（RA+、RA-、DM）上获胜；
  - 块摘要记忆（BRIDGE）在模式归纳（PI-S、PI-P）上获胜；
  - Mem0 和 Graphiti 未在任何探针上获胜。
  - 差异巨大：PI-P 上 BRIDGE 领先 LangMem 33 分；RA+ 上 LangMem 领先 BRIDGE 45 分。
- **每种设计为其表征过去的方式付出代价**：
  - 原子事实抽取器在写入时提取事实，但丢失了模式的形式；
  - 块摘要记忆保留形式，但规则混在笔记中未能被 reader 应用。
- **BRIDGE 的规则应用失败源于呈现而非检索**：
  - 规则块在全部 20 个 RA+ 场景中均被检索到，且在 12/13 失败中规则以原始文本到达 reader；
  - 仅改变呈现方式（将常驻指令置于顶部）可使 BRIDGE 从 52.6% 提升到 94.7%，接近 Oracle。
- **路由不能解决问题**：仅从请求无法预测需要规则还是模式，分类器准确率 49–61%，不优于多数类基线。
- **难度扩展**：更难探针（更多填充会话、更少演示、竞争信号）会缩小 LangMem 的规则应用优势，但 BRIDGE 的模式归纳优势在各难度下保持。
- **核心论点**：区分记忆设计的不是它们检索到什么，而是它们使智能体能够做什么；未来记忆基准应评估行为使能。

## 7. 优点

- **重要的诊断性发现**：指出标准基准的盲点，重新定位智能体记忆评估目标。
- **极简基线 BRIDGE**：提供强有力、低成本、可复现的最小基线，要求复杂系统至少应超越它。
- **行为测试探针设计**：五个探针覆盖规则应用、模式归纳、多轮一致性，请求从不提及记忆，更贴近生产环境中的“always-on applied memory”。
- **公平比较协议**：统一 reader、嵌入器、评分器；跨供应商评分减少同族偏差；按文档调谐基线。
- **鲁棒性检验充分**：跨领域、跨评分器、跨 reader、重复运行、难度层次扩展，增强了结论可信度。
- **深入失败分析**：区分检索失败与呈现/行动失败，提供可操作的诊断（呈现常驻指令可弥补差距）。
- **成本透明**：报告 token 和延迟，显示 BRIDGE 比全上下文少 17–154 倍 reader token，具有实际部署价值。

## 8. 不足与局限

- **规模较小**：原始探针每类仅 20 场景，统计功效有限；新增领域单元格仅 4–8 场景，只能解读方向。
- **合成数据**：场景由大模型生成，虽经审计但无法完全替代人工编写；人类评分仅限于作者抽查。
- **评分器限制**：只检查约束是否被遵守，不评估答案其他方面的质量；评分器之间存在分歧（尤其是宽松评分器会把系统推向天花板）。
- **覆盖不完整**：DM 探针仅运行一次，未纳入鲁棒性检查；Oracle 和场景生成器来自同一模型家族；静态输入-输出测试，非真实长期部署、工具使用或用户变化。
- **外部效度**：探针任务偏软件/基础设施，扩展到其他领域但样本小；真实生产环境中的记忆使用可能更复杂。
- **BRIDGE 配置设定**：超参数在标准基准上确定，探针上使用同一配置，未对探针调优，但对基线调谐可能存在不对称。
- **偏差风险**：合成数据可能带有生成器偏见；评分器可能因供应商不同而有系统性偏差；论文未完全消除 LLM 评判噪声。
