## 摘要
小语言模型智能体阅读多跳问题所需记忆的空间有限。相关事实往往分散在记录中，其周围文本消耗了大量空间。我们提出 LMMR，一种学习式多粒度记忆检索方法，同时选择下一个来源以及读取其多少内容。LMMR 将段落和句子片段链接到其原始来源，并在训练期间配对提供相同缺失支持的视图。相关干扰项和重复信息提供对比示例。在推理时，重排序器对每个候选者添加到锚定段落的增益进行评分，选择器在 token 预算内选择证据。在 HotpotQA、2WikiMultihopQA 和 MuSiQue 的 22,398 个官方验证问题上，冻结的 2B 答案模型在 400 token 预算下达到 61.47、43.26 和 30.58 F1。相比查询扩展，提升分别为 3.06、2.14 和 4.55 点，而记忆输入减少 23.1-26.9%。与在同一问题上训练的粗粒度检索器相比，LMMR 还少使用 23.5-27.7% 的输入 token。与该检索器后接 LLMLingua-2 在可比输入长度下相比，F1 增益达到 3.99 点，并在 HotpotQA 和 2WikiMultihopQA 上经 Holm 校正后显著。在 HotpotQA 上评估的所有八个小型答案模型在 F1 和精确匹配上都优于查询扩展和 MMR。

## Abstract
Small language model agents have limited space to read the memory needed for multi-hop questions. Relevant facts are often scattered across records whose surrounding text consumes much of that space. We propose LMMR, a learned multigranular memory retrieval method that selects both the next source and how much of it to read. LMMR links paragraphs and sentence fragments to their original sources and pairs views that supply the same missing support during training. Relevant distractors and repeated information provide contrasting examples. At inference, the reranker scores what each candidate adds to an anchor passage, and a selector chooses the evidence within a token budget. On 22,398 official validation questions from HotpotQA, 2WikiMultihopQA, and MuSiQue, a frozen 2B answer model reaches 61.47, 43.26, and 30.58 F1 under a 400-token budget. The gains over query expansion are 3.06, 2.14, and 4.55 points, while memory input decreases by 23.1-26.9%. LMMR also uses 23.5-27.7% fewer input tokens than a coarse retriever trained on the same questions. Against that retriever followed by LLMLingua-2 at comparable input lengths, F1 gains reach 3.99 points and are significant on HotpotQA and 2WikiMultihopQA after Holm correction. All eight small answer models evaluated on HotpotQA improve over query expansion and MMR in both F1 and exact match.

## 1. 核心问题与整体含义

本文要解决的核心问题是：**小语言模型智能体在回答多跳问题时，受限于输入 token 预算，难以有效利用分散在多个记忆记录中的关键事实**。

具体而言：

- 在现实记忆中，回答问题所需的支持性事实往往只占整段文本的极少部分（可能只有一两句）。
- 对于输入窗口有限的小型答案模型（如 2B 参数），直接整段读取相关记录会迅速耗尽 token 预算，导致真正有用的“第二跳事实”无法进入上下文。
- 论文以 HotpotQA 的一个典型例子说明：查询扩展（Query Expansion）提供了 235 个证据 token，但回答模型错误地给出了“Jack Buck”（父亲的名字），而 LMMR 仅用 122 个 token 就正确回答了“St. Louis Cardinals”（播报的球队）。

整体含义是：**记忆检索不仅要“选哪个来源”，还要“从来源中读取多少”**。通过有监督地学习何时用完整段落、何时用句子片段，可以在不牺牲证据质量的前提下大幅压缩输入，同时提升小模型的多跳问答效果。

## 2. 方法论

LMMR 的核心思想是：**在锚定段落（anchor）的上下文中，联合选择下一个证据来源及其粒度（段落或句子片段），以最大化新增信息量并在 token 预算内完成选择**。

### 2.1 源保持的多粒度记忆表示

每个记忆节点 `n = (p, g, I, x)` 包含：

- `p`：源文档标识符；
- `g`：粒度（粗粒度段落 / 细粒度片段）；
- `I`：原始句子索引和字符区间（用于后续合并和去重）；
- `x`：文本内容。

两个关键粒度：

- **粗粒度节点**：相邻句子的分组；
- **细粒度节点**：单个句子或两个相邻句子（超长句子按字符区间切分）。
- 通过区间信息，不同粒度的视图之间可以相互对齐，保持原始文本和源归属。

### 2.2 条件重排序器（Conditional Reranker）

LMMR 使用一个冻结基座（Qwen3-Reranker 0.6B，LoRA 适配）进行条件评分：

\[
s_\theta(q,a,d) = z_{\text{yes}}(q,a,d) - z_{\text{no}}(q,a,d)
\]

即给定问题 `q`、锚定证据 `a` 和候选 `d`，模型判断该候选是否“提供了回答该问题仍缺失的信息”。同一评分器同时处理粗粒度和细粒度候选。

此外，还有一项目录式重叠惩罚项：

\[
R(a,d) = \frac{|W(a) \cap W(d)|}{|W(d)| + \epsilon}
\]

用于抑制与锚定证据重复的内容。

### 2.3 源一致的粗细对比学习

训练的关键机制是**粗–细视图配对**：

- 若一个细粒度片段 `f` 与其父级粗粒度段落 `c` 都保留了相同的缺失支持句集合，且该集合非空：

\[
f \subseteq c,\quad U(f) \cap G_a = U(c) \cap G_a \ne \emptyset
\]

- 则选取保留该补充支持的最短细粒度视图作为正样本，与父段落配对。

**损失函数**由三部分构成：

\[
\mathcal{L} = \mathcal{L}_{\text{rank}} + \lambda_B \mathcal{L}_B + \lambda_c \mathcal{L}_c
\]

- \(\mathcal{L}_{\text{rank}}\)：排序损失，使正视图得分高于硬负样本和冗余负样本；
- \(\mathcal{L}_B\)：二元监督损失，正样本趋近 1，硬负样本趋近 0；
- \(\mathcal{L}_c\)：平滑 L1 损失，拉近粗、细两个正视图的 sigmoid 得分，实现粒度一致性。

### 2.4 预算约束下的层次选择算法

推理流程（Algorithm 1）：

1. 用冻结的相关性评分器 \(s_0\) 选出最多 \(K_a\) 个粗粒度锚定候选；
2. 若首选得分显著领先，仅使用一个锚点（阈值 \(\tau\)）；
3. 对每个锚点，条件重排序器对所有粗粒度候选打分；再从 top \(K_s\) 个来源中扩展细粒度片段；
4. 最终目标为：

\[
(a^*, d^*) = \arg\max_{a,d} \left[ s_0(q,a) + \alpha s_\theta(q,a,d) - \beta R(a,d) \right]
\]

5. 同时满足 token 预算约束 \(T(\text{Merge}(\{a,d\})) \le B\)；
6. 合并时按间隔去重、恢复句子顺序、加入来源标签，最后输出紧凑证据给答案模型。

该方法计算成本为 \(O(|C| + K_a(|C| + F_s))\)，答案模型仅运行一次。

## 6. 主要结论与发现

- **主结果**：在 400 token 预算下，2B 答案模型在 HotpotQA、2Wiki、MuSiQue 上分别达到 61.47、43.26、30.58 F1，相较 QE 提升 3.06、2.14、4.55 点，同时平均证据输入减少 23.1%、26.6%、26.9%。
- **对比训练匹配粗检索器**：LMMR 在 HotpotQA 保持同水平 F1 的同时，少使用 23.5% 的输入 token；在 2Wiki 上甚至 F1 略高且 token 更低。
- **对比压缩后处理（LLMLingua-2）**：在可比输入长度下，LMMR 领先 2.76 和 3.99 F1（HotpotQA、2Wiki），且经 Holm 校正后显著。
- **跨模型稳定性**：八个 0.8B–4B 的小答案模型在 F1 和 EM 上全部优于 QE 和 MMR。
- **题型增益侧重桥接/组合型问题**：HotpotQA bridge +3.78、2Wiki compositional +4.40、MuSiQue 2-hop +5.50 和 3-hop +4.91，说明 LMMR 的核心优势在于“跨源补链”。
- **支持密度提升**：平均每问题支持密度从 33.47% 提升到 43.75%，大部分删除的是非支持性背景文本。

## 7. 优点

- **多粒度选择与源保持结合**：将粒度决策显式建模为可学习的选择问题，同时保留原始文本和溯源关系，既保证可读性也维护了证据可靠性。
- **训练策略设计巧妙**：使用“同一缺失支持约束”来配对粗细视图，明确监督何时短片段足以替代整个段落。
- **对比学习结构合理**：利用相关干扰项（relevant distractors）和重复信息（redundant negatives）构建对比监督，避免检索器贪恋“相似但无用”的片段。
- **工程上可落地**：算法复杂度可控，答案模型只推理一次；在 Jetson Orin 端侧上实测，验证了小模型 + 多粒度检索在低算力设备上的可行性。
- **评估体系较严谨**：与训练匹配的粗检索器和 LLMLingua-2 进行公平对比，提供统计显著性检验。
- **跨模型、跨数据集适用性**：单一训练的检索器可零样本迁移到两个外部数据集，且对八个不同架构的小模型均有效。

  - 默认 HotpotQA 使用 30 段候选池，而论文中较好的小模型性能部分依赖于该候选池中的高质量段落；相比 Open-domain 设置下的相同模型，数值不可直接对比。
