## 摘要
企业级 LLM 智能体运行在动态环境中，其中基础模型快速演进、工作流频繁更新，且部署需要同时满足准确性与成本要求。我们提出 ARISE（通过迭代自评估进行智能体精化），一种实用的记忆架构，其中智能体的记忆从其自身失败中演化，而无需更新模型权重、工具或工作流逻辑。ARISE 使用模型本身或教师模型对失败进行归因并提出修正。随后，ARISE 将修正保存为可检索的微观记忆，将其整合为宏观规则，并且仅在留出集准确率提升时接受规则更新。在来自 SOP-Bench 和 $τ^2$-bench 的 14 个企业工作流领域中，使用 5 个模型进行实验，采用 Claude Opus 4.6 进行归因和整合的 ARISE-Teacher 在 SOP-Bench 上比基线提高 10.9 个百分点，在 $τ^2$-bench 上提高 5.8 个百分点。ARISE-Teacher 在 $τ^2$-bench 上还比 GEPA 高出 4.5 个百分点，在 SOP-Bench 上高出 1.4 个百分点。当使用部署模型作为其自身的归因器时，ARISE-Self 在 SOP-Bench 上仍能提升 10.0 个百分点。在每任务成本相当（-1.0%）的情况下，ARISE-Teacher 使用的模型调用次数减少 4.0%，输出 token 减少 5.2%。

## Abstract
Enterprise LLM agents operate in dynamic environments where foundation models evolve rapidly, workflows update frequently, and deployments need to satisfy accuracy and cost requirements. We propose ARISE (Agent Refinement through Iterative Self-Evaluation), a practical memory architecture in which the agent's memory evolves from its own failures without updating model weights, tools, or workflow logic. ARISE uses the model itself or a teacher model to attribute the failures and propose corrections. Then, ARISE keeps the corrections as retrievable micro memory, consolidates them into macro rules, and accepts a rule update only if held-out accuracy rises. Across 14 enterprise-workflow domains from SOP-Bench and $τ^2$-bench using 5 models, ARISE-Teacher, which uses Claude Opus 4.6 for attribution and consolidation, gains 10.9 pp over the baseline on SOP-Bench and 5.8 pp on $τ^2$-bench. ARISE-Teacher also outperforms GEPA by 4.5 pp on $τ^2$-bench and 1.4 pp on SOP-Bench. With the deployment model as its own attributor, ARISE-Self still gains 10.0 pp on SOP-Bench. ARISE-Teacher uses 4.0% fewer model calls and 5.2% fewer output tokens at comparable per-task cost (-1.0%).

## 2. 论文提出的方法论

### 2.1 核心思想
ARISE 通过**失败归因 → 微观记忆 → 宏观规则 → 验证门**的离线循环，将失败任务转化为可检索的修正条目和少量宏观规则，并在推理时注入智能体上下文。

### 2.2 关键模块

- **智能体运行时**：
  - 定义智能体 \(A=(p,T,m)\)，其中 \(p\) 为系统提示，\(T\) 为工具集，\(m\) 为部署模型。
  - 输出轨迹 \(\tau\) 和最终答案 \(\hat{y}\)：  
    \[
    (\tau,\hat{y})=A(x; p\oplus R\oplus M(x))
    \]
  - \(R\) 为宏观规则集合，\(M(x)\) 为根据当前任务检索到的微观修正集合；基线方法中 \(R=M(x)=\emptyset\)。

- **失败归因**：
  - 对每个失败任务 \(j\)，归因器（部署模型自身或更强的教师模型）生成一个**带条件的单行修正**：
    \[
    c_j = \text{Attr}(x_j, y_j, \hat{y}_j, \tau_j)
    \]
  - 每个修正格式为 `[WHEN: <具体条件>] <应执行的动作>`，限定其适用范围。

- **记忆适应**：
  - **微观记忆**：由归因器生成的修正按嵌入相似度存储和检索。
  - **规则整合**：每批次后，将新修正与当前规则整合为两个候选：
    - `append` 候选：在现有规则基础上追加 1–2 条新规则。
    - `rewrite` 候选：仅基于新修正重写 3–5 条规则。
  - 每条规则都带 `[WHEN:]` 范围，候选规则数上限为 \(K\)（默认 \(K=5\)）。

- **验证门**：
  - 使用留出验证集 \(D_{val}\) 的准确率决定是否接受规则更新。
  - 规则更新门：
    \[
    Acc_v(R^\star) > Acc_v(R) + \epsilon_m
    \]
  - 微观检索门：
    \[
    Acc_{v,\mu}(R+M) \ge Acc_v(R) - \epsilon_\mu
    \]
  - 其中 \(\epsilon_m = \max(\epsilon_0, C/|D_{val}|)\)，默认 \(\epsilon_0=2\) pp，\(C=50\)，\(\epsilon_\mu=5\) pp。
  - 只有通过验证门的候选才被接受；连续 \(P\) 次未接受更新则停止训练。

- **推理时检索**：
  - 若微观门通过，将任务输入嵌入后，检索最多 \(k\) 个余弦相似度超过阈值 \(\theta\) 的修正（默认 \(k=5\)，\(\theta=0.6\)）。
  - 注入上下文有上限：\(K\) 条宏观规则 + \(k\) 条微观修正。

  - 所有 agent、归因和整合调用温度设为 0。

## 3. 实验设计

### 3.1 数据集与场景

- **SOP-Bench**：
  - 11 个领域，共 1,813 个任务。
  - 每个任务包含 SOP 文档、输入和确定性工具；按行 70/30 划分为训练/测试，评分基于 decision 字段的精确匹配。
- **τ²-bench**：
  - 包含航空、零售、电信三个多轮对话领域，使用官方任务文件和 action evaluator。
  - 本文将该三领域评估称为 \(τ\)。
- **总体**：14 个企业工作流领域，训练数据按 70/30 再分为 iteration 集与 validation 集，测试集仅用于最终评估。

### 3.2 模型与成本

- **5 个模型**：Claude Opus 4.6、Sonnet 4.6、Haiku 4.5、DeepSeek v3.2、Qwen3-32B，均通过 Amazon Bedrock 调用。
- **成本**：按 API 公开价格计算（如 Opus 5.50/27.50 美元每百万输入/输出 token）。

### 3.3 对比方法

- **Baseline**：原始 prompt。
- **ExpeL**（Zhao et al., 2024）与 **Reflexion**（Shinn et al., 2023）：使用部署模型重实现。
- **GEPA**（Agrawal et al., 2026）：使用 Opus 4.6 作为反射模型，温度 1.0。
- **Macro**：仅使用 ARISE 的归因 + 整合 + 验证门，但不存储/检索微观记忆。
- **ARISE-Teacher**：Opus 4.6 负责归因与整合。
- **ARISE-Self**：部署模型自身完成归因与整合，无更强模型辅助。

### 3.4 评估指标

- **准确率**：任务成功率；SOP-Bench 采用 decision 字段精确匹配，τ²-bench 采用 action evaluator。
- **效率**：输入/输出 token、模型调用次数、每任务成本（美元）。
- **可靠性**：τ²-bench 上的 pass^1、pass^4 等指标。
- **显著性检验**：分层配对 bootstrap（10,000 次重采样）。
