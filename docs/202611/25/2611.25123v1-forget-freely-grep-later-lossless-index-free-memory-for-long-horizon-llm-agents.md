## 摘要
长时程 LLM 智能体常常超出其上下文窗口，迫使其丢弃后续可能需要的信息。现有上下文管理策略依赖摘要、掩码或结构化记忆，需要在未来需求未知时就决定保留什么或如何检索。然而，这些方法可能引入有损压缩，可能丢弃未来任务所需的细节。为解决这一局限，我们提出 GrepMem，一种简单、无损且免索引的记忆机制，由两个组件构建：智能体完整历史的仅追加纯文本日志，以及用于按需回忆的正则表达式搜索工具。与结构化记忆系统不同，GrepMem 无需嵌入、检索索引、记忆提取或额外模型。我们在五种上下文管理策略下用强化学习训练 Qwen3.5-9B，并在多问题研究会话、长流回忆和智能体轨迹问答上评估。GrepMem 在 ContextBench 上达到 95-97% 准确率，而有损基线最高仅为 21%；在 BCP-Multi 上比 SUPO 的摘要方法高 8.8 个百分点。GrepMem 能有效扩展到越来越长的输入流，同时在全部五个评估任务上保持在准确率-令牌成本帕累托前沿。我们的结果表明，纯文本日志加 grep 为长时程智能体记忆提供了一种简单但有竞争力的方法，无需复杂结构化记忆基础设施。

## Abstract
Long-horizon LLM agents often exceed their context windows, forcing them to discard information that may be needed later. Existing context management strategies rely on summarization, masking, or structured memory, requiring decisions about what to preserve or how to retrieve it before future needs are known. However, these methods can introduce lossy compression, potentially discarding details needed for future tasks. To address this limitation, we introduce GrepMem, a simple, lossless, and index-free memory mechanism built on two components: an append-only plain-text log of the agent's complete history and a regular-expression search tool for on-demand recall. Unlike structured memory systems, GrepMem requires no embeddings, retrieval index, memory extraction, or additional models. We train Qwen3.5-9B with reinforcement learning under five context management strategies and evaluate on multi-question research sessions, long-stream recall, and agent-trajectory question answering. GrepMem achieves 95-97% accuracy on ContextBench, versus at most 21% for lossy baselines, and outperforms SUPO's summarization by 8.8 percentage points on BCP-Multi. GrepMem scales effectively to increasingly long input streams while remaining on the accuracy-token-cost Pareto frontier across all five evaluation tasks. Our results show that a plain-text log and grep provide a simple but competitive approach to long-horizon agent memory, without requiring complex structured memory infrastructure.

- **核心问题**  
  能否在保持工作上下文精简的同时，保留完整历史并支持按需精确召回，而不依赖复杂的结构化记忆或检索索引？

  本文提出 **GrepMem**，主张“自由遗忘，稍后 grep”：用仅追加的纯文本日志无损保存完整交互历史，用正则表达式搜索工具按需召回。结果表明，简单、无损、免索引的记忆机制即可在多个长时程任务上取得强竞争力，挑战了“必须构建复杂记忆基础设施”的假设。

## 2. 方法论

- **核心思想**  
  GrepMem 将智能体的**有界工作上下文**与**持久化无损历史日志**分离：
  - 工作上下文通过摘要压缩，支持持续推理；
  - 持久化日志保存全部交互细节，任何被摘要丢弃的信息都可被恢复。

- **两个关键组件**  
  1. **仅追加纯文本日志**：自动记录所有用户消息、工具调用、工具输出、摘要和智能体回复，形成完整、无损的历史。
  2. **正则表达式搜索工具 `grep_history`**：在日志中执行大小写不敏感的正则匹配，支持返回匹配行、上下文行、分页、计数模式等。无需嵌入、索引、记忆提取或额外模型。

- **工作流程（算法流程文字描述）**  
  1. 智能体在活动上下文中生成回复、调用工具，同时所有消息和工具输出被追加到历史日志；
  2. 当工作上下文接近窗口上限时，智能体生成摘要（类似 SUPO 的摘要循环），随后把摘要也追加到日志，并将工作上下文重置为系统提示、任务和摘要；
  3. 首次压缩后，`grep_history` 工具可用；智能体自主决定何时检索历史，以恢复被摘要省略的细节；
  4. 最终返回答案。

- **RL 训练**  
  使用 GRPO 强化学习，端到端联合优化任务动作、上下文摘要和记忆检索，奖励来自任务正确性（如 OpenResearcher 的二元正确性奖励，多问题会话取平均），**不对摘要或 grep 查询设置单独监督信号**。

## 6. 主要结论与发现

- **GrepMem 显著优于有损基线**  
  RL 后，GrepMem 在 ContextBench KV Store 上达到 **97.4%** 准确率，Log Triage 上 **95.3%**，而 SUPO 和 Masking 仅在 6.6–20.7% 之间。平均准确率 **66.4%**，为五种策略最高。

- **在 BCP-Multi 上领先**  
  GrepMem 准确率 **46.9%**，比 SUPO 高 **8.8 个百分点**，比 MemGPT 高 **7.0 个百分点**。

- **收益条件取决于任务性质**  
  当问题需要被摘要丢弃的精确细节（如 ContextBench 的精确值、日志条目）时，无损召回优势巨大；当任务可由摘要保留信息完成（如 AMA-Bench stream 的因果/状态问题）时，优势很小甚至无统计显著差异。

- **RL 的影响非均匀**  
  RL 平均提升 GrepMem 5.9 个百分点，Log Triage 上提升 20.3 个百分点，但对 AMA-Bench 几乎无提升，说明收益取决于任务是否涉及可优化的检索与证据利用行为。

- **可扩展性**  
  随输入流长度增长，GrepMem 在 KV Store 和 Log Triage 上保持高准确率，而有损基线严重退化；在 Log Triage 上 RL 还能进一步改善长流性能。

- **成本效益**  
  GrepMem 在全部五个任务的**准确率–令牌成本帕累托前沿**上：相比 SUPO 仅多 6% tokens（BCP-Multi）或少 5%（AMA-Bench file），但在 ContextBench 上以约 19% 额外 token 大幅提升准确率，且仅用 MemGPT 约 **29%** 的 tokens。例外是 AMA-Bench stream，GrepMem 使用 2.3 倍 tokens 但收益有限。

## 7. 优点

- **方法简洁且创新**  
  将“摘要压缩”与“无损日志 + grep”结合，用极简单工具实现免索引记忆，避免了嵌入、索引、记忆提取和额外模型的复杂性。

- **无损保证**  
  日志完整保存所有历史，任何被丢弃的细节都能被正则搜索恢复，从根本上避免有损压缩风险。

- **与强化学习联合优化**  
  通过端到端 RL 同时训练任务行为、摘要和检索决策，不依赖额外监督，展现学习召回策略的潜力。

- **实验设计公正、覆盖广**  
  五个策略统一采用相同 RL 配方、训练数据和工具；任务覆盖研究、轨迹问答、键值召回与日志计数，且区分问题已知/后知，能揭示方法收益的真实条件。

- **成本与可扩展性分析详实**  
  提供准确率–令牌成本帕累托前沿、token 使用量、运行时对比，以及不同流长度下性能变化，评估透明。

## 8. 不足与局限

- **单一模型与受控基准**  
  仅使用 Qwen3.5-9B，结果能否泛化到其他模型（尤其更强或更弱的模型）仍未知；任务限制在受控基准内，未覆盖真实开放域智能体环境。

- **词法搜索限制**  
  grep 依赖显式文本匹配；当相关信息无法通过关键词或正则模式识别（如语义相关但措辞不同）时，检索可能失败。论文也承认其目标不是替代所有复杂记忆系统。

- **部分任务收益有限**  
  在 AMA-Bench stream 上，GrepMem 相对 SUPO 的准确率提升很小（0.9 个百分点且不显著），但 token 成本高 2.3 倍，说明并非所有场景都需要无损检索。

- **基线实现可能不完全还原原方法**  
  MemGPT 的档案记忆使用 BM25 替代原始嵌入，可能削弱其检索能力；评估部分样本数量有限（部分 checkpoint 仅 2 个样本），存在波动。

- **训练与推理成本**  
  每个策略需 24 块 H100 训练，总计约 6,000 H100-小时，训练成本不低；推理时 grep 检索额外调用也增加延迟与 token 消耗。

- **安全与隐私**  
  保留完整交互历史可能含有敏感信息，虽然这不是 GrepMem 独有的问题，但实际部署需额外访问控制和数据保留策略。
