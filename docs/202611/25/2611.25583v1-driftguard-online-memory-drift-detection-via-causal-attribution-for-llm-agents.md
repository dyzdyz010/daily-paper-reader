## 摘要
大语言模型（LLM）智能体依赖持久记忆来规划工具调用并完成多步骤任务，这使其面临记忆漂移：对抗性或误导性记忆会改变执行路径和最终结果。本文研究在线记忆漂移检测，在服务时估计每条检索到的记忆对潜在漂移的因果贡献。我们识别出两个根本挑战。（1）内容级特征不足以进行因果记忆漂移归因，因为仅靠困惑度或检索相关性无法确定哪条检索到的记忆在被中和后会改变智能体行为；（2）反事实归因在在线检测中计算成本过高，因为它需要为每条候选记忆重放下游智能体和工具执行，超出实时服务预算。为应对这些挑战，我们提出 DriftGuard，一种将离线因果监督与在线估计解耦的两阶段框架。具体而言，DriftGuard 首先通过重复的成对反事实重放构建因果监督，从共享的预动作状态继续原始轨迹后缀和单一记忆被中和的轨迹后缀。所得标注通过按组件多数投票聚合为记忆漂移分数（MDS），该分数捕获动作变化、攻击移除、违规移除和任务恢复。在该监督指导下，DriftGuard 随后学习一个在线风险模型，从预动作信息估计 MDS，并通过其最大组件风险标记诱发漂移的记忆，而无需在线反事实推演。大量实验表明，DriftGuard 能准确识别诱发漂移的记忆，并实现高效的在线防御。代码可在 https://anonymous.4open.science/r/DriftGuard-7F0B 获取。

## Abstract
Large language model (LLM) agents rely on persistent memory to plan tool calls and complete multi-step tasks, which exposes them to memory drift: an adversarial or misleading memory alters the execution path and final outcome. In this work, we investigate online memory-drift detection, which estimates each retrieved memory's causal contribution to potential drift at serving time. We identify two fundamental challenges. (1) Content-level features are insufficient for causal memory-drift attribution, as perplexity or retrieval relevance alone cannot determine which retrieved memory would change agent behavior if neutralized; (2) Counterfactual attribution is prohibitively expensive for online detection, as it requires replaying downstream agent and tool execution for each candidate memory, exceeding real-time serving budgets. To address these challenges, we propose DriftGuard, a two-stage framework that decouples offline causal supervision from online estimation. Specifically, DriftGuard first constructs causal supervision through repeated paired counterfactual replays, continuing the original and single-memory neutralized trajectory suffixes from a shared pre-action state. The resulting annotations are aggregated by component-wise majority voting into a memory drift score (MDS) that captures action change, attack removal, violation removal, and task recovery. Guided by this supervision, DriftGuard then learns an online risk model that estimates MDS from pre-action information and flags drift-inducing memories via its maximum component risk, without online counterfactual rollouts. Extensive experiments demonstrate that DriftGuard accurately identifies drift-inducing memories and enables efficient online defense. Code is available at https://anonymous.4open.science/r/DriftGuard-7F0B.

# DriftGuard 论文详细总结

## 1. 论文的核心问题与整体含义

- **研究背景与动机**：
  - LLM 智能体在完成多步骤任务时，普遍依赖持久记忆（persistent memory）来复用历史经验、用户偏好和可重用工作流。
  - 持久记忆一旦被对抗性注入或污染，会导致**记忆漂移（memory drift）**：检索到的误导性记忆悄然改变智能体的执行路径和最终结果，造成安全或任务失败。
  - 现有防御手段（如内容过滤、溯源、链接执行）无法判断**哪一条检索记忆**是导致漂移的因果源头，尤其是在多条相关记忆同时出现、仅一条为恶意的场景下。
  - 论文由此提出**在线记忆漂移检测**问题：在服务时量化每条检索记忆对潜在漂移的因果贡献，并需同时满足在线延迟预算。

- **两个核心挑战**：
  - **内容级特征非因果**：困惑度、检索相关性、注意力、输出有害性等特征只反映表面可疑性，不能判断“中和某条记忆是否会改变智能体行为”。例如图 1 中，外观正常的记忆 `m(3)` 注入了恶意支付端点，而外观可疑的诱饵 `m(2)` 反而无害。
  - **反事实归因成本过高**：直接测量因果效应需对每条候选记忆执行“中和—重放”反事实轨迹，会产生 K 次额外 agent 与工具执行，远超在线服务延迟预算。

## 2. 论文提出的方法论

- **总体思想**：**DriftGuard 两阶段框架**，将离线因果监督构建与在线风险估计解耦：
  - 离线阶段：通过成对反事实重放构造因果监督标签，学习记忆漂移分数（MDS）。
  - 在线阶段：训练轻量在线风险模型（ORM），仅从预动作信息估计 MDS，无需任何反事实 rollout。

- **关键技术细节**：

  - **离线成对反事实轨迹构建（4.1）**：
    - 在每个动作节点 `t`，恢复共享预动作状态（任务查询、执行历史、检索到的 K 条记忆），生成原始轨迹后缀 `τ_orig`。
    - 对每条候选记忆 `m^(k)`，使用 LLM 实现的中和算子 `I(·)` 移除疑似有害指令，保留良性事实与结构，得到干预后的记忆集，生成反事实轨迹后缀 `τ_cf(k)`。
    - 两个分支共享 agent 检查点、解码策略、工具状态、环境快照和解码种子，以保证差异可归因于记忆干预。

  - **记忆漂移分数 MDS（4.2）**：
    - 将干预效应分解为**动作漂移**与**结果漂移**共四个二进制事件维度：
      1. `y_act`（动作变化）：工具选择、参数规范、执行结构三个子指标之一发生任务语义相关变化。
      2. `y_att`（攻击移除）：原始轨迹攻击成功，反事实轨迹攻击不成功。
      3. `y_vio`（违规移除）：原始轨迹发生已执行策略违规，反事实轨迹未发生。
      4. `y_task`（任务恢复）：原始良性任务失败，反事实任务成功。
    - 每个候选记忆进行 R 次重复成对 replay，按组件多数投票得到最终 MDS 标签；并选择与投票结果完全匹配的一组轨迹予以保留。
    - 提供了命题 1 论证 MDS 的条件均值可识别。

  - **在线风险模型 ORM（4.3）**：
    - 输入只包含预动作信息：任务查询、执行历史、除候选记忆外的其他记忆、候选记忆本身、任务契约。
    - 采用预训练 LLM 骨干 + 四输出线性头，经元素级 sigmoid 输出四个事件概率 `ŷ = (ŷ_act, ŷ_att, ŷ_vio, ŷ_task)`。
    - 训练目标为加权二元交叉熵损失（四个损失权重 `λ_1`~`λ_4` 默认为 1）。
    - 提供了推论 1，证明在假设下 ORM 是 MDS 条件均值的一致估计。

  - **在线工作流（4.4）**：
    - 每个动作节点，对每条检索记忆用 ORM 计算风险分数 `s = max(ŷ_act, ŷ_att, ŷ_vio, ŷ_task)`。
    - 若 `s ≥ γ`，则用中和算子 `I(·)` 重写该记忆；否则保留。
    - 阈值 `γ` 在验证集上通过最大化 F1 校准，并在部署前冻结。

  - **在线防御**：No Defense、SMSR、LLM Memory Auditor、A-MemGuard。

## 6. 论文的主要结论与发现

- **离线检测性能显著超越基线**：
  - DriftGuard 在全部 9 个基准-骨干组合上取得最高 AUPRC/AUROC。
  - 在 MPBench 上优势最突出，例如 GPT-5.6 Luna 下 AUPRC 达 0.2415，比最强少样本基线 Claude Opus 5 提升 86.2%。
  - 前沿 LLM 零样本/少样本排名器在低阳性率场景下接近随机水平，说明缺乏干预衍生监督难以学习因果判别。

- **消融发现**：
  - 执行上下文对任务条件记忆漂移检测至关重要；乱序上下文比缺失上下文更有害，说明模型利用上下文结构。
  - 四个 MDS 头互补；移除动作头损失最大，攻击头贡献最小但仍有用。

- **泛化性**：
  - ORM 在 Qwen2.5、Llama3、Falcon3 三个家族均有效，随模型规模增大性能提升，但小模型（如 Qwen2.5-1.5B）已能超过最强 LLM 基线。

- **在线防御效果**：
  - DriftGuard 在 3 个基准、3 种攻击下均实现最低 ASR 与最高 TSR。
  - 例如 Mem2ActBench 上 Direct Override ASR 从 46.7% 降至 5.3%，Sleeper Memory 从 77.4% 降至 3.3%；同时 TSR 大幅提升。

- **运行时效率**：
  - DriftGuard 每任务额外延迟仅 1.52 秒，比 A-MemGuard 快 75.4%、token 开销降低 62.1%；且无需额外受害者 agent rollout。
  - 延迟主要由记忆重写（~80%）贡献，ORM 评分仅约 20%；随 K 增长仍远低于直接反事实 replay（约 20 倍差距）。

- **超参数鲁棒性**：
  - 损失权重在 0.25~2 范围内表现稳定；阈值在验证集选择值附近平衡安全与效用；R=3 已接近饱和，更多重复收益递减。

## 7. 优点

- **问题定义清晰**：首次将在线记忆漂移检测形式化为因果归因与部署约束的折中问题，明确区分于内容级安全过滤。
- **方法论创新**：两阶段解耦设计，离线用反事实 replay 获取因果监督，在线用轻量回归模型估计，避免在线反事实推演。
- **MDS 分解合理**：四个维度（动作、攻击、违规、任务）分别刻画近端行为变化与远端安全/效用后果，比单一标量更具可解释性。
- **实验全面严谨**：覆盖多个基准、多种受害者骨干、多种攻击、多个基线；消融、泛化、效率、超参数敏感性均有分析。
- **在线部署友好**：额外延迟低，无额外 agent rollout，适合实时服务。

## 8. 不足与局限

- **单记忆干预**：离线监督仅考虑单一记忆中和，未建模多条记忆之间的交互、共谋或组合效应（如 MemCollusion 类攻击）。
- **中和算子安全性**：重写记忆不能保证在域转移或未见攻击下始终安全，缺乏显式的安全/效用保证。
- **评估范围有限**：实验集中在工具使用类智能体，未覆盖更广泛的 agent 形态（如纯推理、多智能体协作、真实生产系统）。
- **离线数据构建成本高**：虽然在线快，但离线需要大量反事实轨迹（每节点 K×R 次 replay），对大规模训练数据而言成本可能很高，且论文未量化这一成本或提供更高效的监督生成方式。
- **理论假设较强**：一致性结果依赖 SUTVA、忠实联合重放、轨迹级 i.i.d. 等假设，实际中可能不完全成立。
- **ORM 泛化能力**：ORM 在特定受害者 agent 和基准上训练，迁移到新的 agent

或任务分布时，性能可能显著下降，需要额外适配或重新训练；论文未系统评估跨智能体架构、工具集和环境设定的零样本迁移能力。
