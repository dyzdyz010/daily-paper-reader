## 摘要
个性化 LLM 智能体必须依据用户当前偏好行动，而这些偏好在交互过程中会变化，且很少被完整表达。现有记忆系统从交互历史中存储和检索内容，让智能体自行判断哪些偏好仍然有效以及适用于何处。这些内容并不表明某个偏好是否仍然当前，或适用于哪个场景，因此智能体常常基于过时或被错误应用的偏好行动。我们则将记忆视为助手对用户的信念。借鉴布迪厄对惯习（habitus）作为持久但可修正的倾向的论述，我们将用户建模为潜在偏好状态，每次交互（包括当前请求）既揭示又更新该状态。这一信念概括了历史记录对该状态所提供的支持，记忆则由与智能体当前决策相关的各个信念组成，每条信念都带有其证据、适用范围和状态。我们在 HabitusMem 中实现了这一观点，HabitusMem 是一个经过训练的写入器，以文本记录形式为冻结的智能体陈述这些信念。在两个智能体家族中，HabitusMem 在 PersonaMem-v2 和 VitaBench 2.0 上均取得了记忆系统中的最佳结果。对照分析表明，学习到的请求条件化带来了回答性能的提升，而辅助训练任务则改善了工具使用。

## Abstract
Personalized LLM agents must act on a user's current preferences, which change across interactions and are rarely stated in full. Existing memory systems store and retrieve content from the interaction history and leave the agent to work out which preferences still hold and where they apply. Such content does not indicate whether a preference is still current or where it applies, so agents often act on outdated or misapplied preferences. We instead treat memory as the assistant's belief about the user. Following Bourdieu's account of habitus as durable but revisable dispositions, we model the user as a latent preference state that every interaction, including the current request, both reveals and updates. The belief summarizes what the history supports about this state, and memory consists of the individual beliefs that bear on the agent's current decision, each with its evidence, scope, and status. We implement this view in HabitusMem, a trained writer that states these beliefs as text records for a frozen agent. Across two agent families, HabitusMem achieves the best results among memory systems on both PersonaMem-v2 and VitaBench 2.0. Controlled analyses show that learned request conditioning drives the answering gain, while auxiliary training tasks improve tool use.

## 1. 论文的核心问题与整体含义

- **研究动机**：个性化 LLM 智能体需在多次交互中适应用户偏好，但用户偏好往往是隐式、动态、随情境变化的，很少被完整表述。现有记忆系统（如事实抽取、摘要、检索压缩）主要存储“历史说了什么”，而非“历史对当前用户状态意味着什么”。
- **核心问题**：内容型记忆无法回答三个关键问题：
  - 某条偏好的**可信度**如何？证据强弱未区分。
  - 该偏好**适用于哪些情境**？是否仍然有效？是否已被撤回或取代？
  - 哪些偏好与**当前决策**相关？
- **整体含义**：论文将个性化记忆重新定义为**助手对用户的信念**。借鉴布迪厄的“惯习”（habitus）概念，将用户建模为潜在偏好状态，记忆由与当前决策相关的信念组成，每条信念明确携带**证据（evidence）、适用范围（scope）、状态（status）**，从而让智能体能够依据用户“当前”偏好行动，而非依赖过时或误用的历史内容。

## 2. 方法论

### 2.1 核心思想

- **信念状态模型**：将用户偏好视为潜在状态 \(z_t\)，每次交互（包括当前请求）既揭示又更新该状态。信念 \(b_t(z_t) = p(z_t \mid H_t)\) 概括历史证据对用户当前状态的支持程度。
- **记忆的定义**：记忆是由与当前决策相关的**个体信念**组成，每条信念是一个四元组：
  - `claim`：关于用户偏好、情境或约束的陈述；
  - `evidence`：支持该陈述的观察来源；
  - `scope`：该陈述适用的情境；
  - `status`：该陈述当前是活跃、已被取代还是被撤回。

### 2.2 形式化框架

- 给定历史 \(H_t = (o_1, \dots, o_t)\)，信念更新递归为：
  \[
  b_t(z_t) \propto p(o_t \mid z_t) \int p(z_t \mid z_{t-1}) b_{t-1}(z_{t-1}) \, dz_{t-1}
  \]
- 对给定请求 \(q_t\)、记忆 \(m\) 和执行指令 \(g_\tau\)，冻结智能体产生动作 \(a \sim A(\cdot \mid q_t, m, g_\tau)\)。
- 理想记忆 \(m^\star_t\) 最小化期望损失：
  \[
  R_\tau(m; H_t) = \mathbb{E}_{z_t \sim b_t} \mathbb{E}_{a \sim A} [\ell_\tau(a, z_t; q_t)]
  \]
  \[
  m^\star_t \in \arg\min_{m \in \mathcal{M}} R_\tau(m; H_t)
  \]
- 该框架将“信念”和“决策”分离：请求既提供证据（更新信念），也决定哪些信念对当前决策重要。

### 2.3 HabitusMem 实现

- **写入器（writer）**：基于 Qwen3.5-9B + 一个 LoRA 适配器，接收历史片段、格式指令和当前请求后缀，一次性生成以 `## Beliefs` 开头的记录列表，每条记录格式为：
  `claim | evidence: 来源 | scope: 情境 | status: 状态`
- **输入选择**：按位置/预算规则选择历史视图 \(X_t\)。在 PersonaMem-v2 保留历史开头；在 VitaBench 2.0 保留开头和最近交互。
- **生成与使用**：写入器使用贪心解码生成记忆 \(\hat{m}_t\)，冻结智能体基于 \(\hat{m}_t\) 和当前请求行动。
- **训练两阶段**：
  - **Stage 1（父写入器）**：先用 DeepSeek-V4-Flash 教师生成的信念记忆冷启动；再将每个训练请求的标注偏好置顶到静态记忆生成目标，让父写入器学会请求条件化推断。
  - **Stage 2（HabitusMem 写入器）**：从父写入器初始化，在四个任务上联合训练：
    - \(D_1\) **直接写入**：从历史和请求生成信念记录；
    - \(D_2\) **状态更新**：基于新交互修订已有信念（取代/撤回）；
    - \(D_3\) **请求投影**：选择与当前问题相关的信念；
    - \(D_4\) **动作投影**：保留精确的选择和履行约束（如产品、变体、数量、地址、时间）。
  - 损失为教师强制 token 损失，所有任务共享一个 LoRA 适配器。

## 3. 实验设计

- **VitaBench 2.0**：771 个子任务、56 个用户，智能体使用工具完成配送、店内消费和在线旅行任务，偏好隐含在对话和行为日志中。每个子任务运行 4 次，指标为 Avg@4、Pass@4、Pass 4（全成功）。

## 6. 主要结论与发现

- **总体性能**：
  - PersonaMem-v2 上，HabitusMem 在两个智能体下均是最准确的紧凑记忆系统（Qwen: 0.537，DeepSeek: 0.484），分别比最强基线高 4.8 和 4.6 个百分点；在 9 个场景中分别领先 5 个和 8 个场景。
  - VitaBench 2.0 上，HabitusMem 获得最高平均奖励（Qwen: 0.3291，DeepSeek: 0.3573）和最高的非特权全成功（0.1310 / 0.1284），超过 Full context。
- **请求条件化的关键作用**：推理干预显示，移除请求或替换为无关请求会使准确率从约 0.53/0.48 降至 0.40/0.34，生成分数从约 0.33/0.38 降至 0.12–0.20；且未训练写入器无法从请求内容中受益，说明**请求条件化必须被学习**。
- **辅助任务的贡献**：完整四任务混合相比 Direct only 在 VitaBench 平均奖励上提升约 3.3–4.5 点；状态更新、请求投影、动作投影作为整体改善了工具使用。
- **记录字段的作用**：结构化四字段相比纯文本在 PersonaMem-v2 上带来 1.3–1.9 个准确率点和 3.3–3.9 个生成分数点提升；受控探针显示字段有助于保留和区分范围与状态。
- **一致性与覆盖的差异**：信念记忆比内容型记忆在多次试验中更稳定，但与 Full context 相比，全历史在覆盖上仍有优势，而生成分数低，说明仅提供证据不足以引导开放生成，需要预先推断偏好。

## 7. 优点

- **范式创新**：从“存储历史内容”转向“维护对用户的信念”，回应了当前个性化记忆的核心缺陷。
- **理论扎实**：借鉴 Bourdieu 的惯习概念和贝叶斯决策理论，将记忆问题形式化为期望损失最小化，逻辑清晰。
- **结构化信息**：四字段记录（claim/evidence/scope/status）显式区分证据强度、适用范围和状态演变，避免过时/误用偏好。
- **与冻结智能体兼容**：无需修改下游智能体，只需训练一个写入器，易于部署和迁移。
- **训练任务设计巧妙**：四个任务分别对应信念推断、更新和两类投影，覆盖从历史到决策的完整链路。
- **实验严谨**：大量配对消融、受控探针、统计检验和案例分析，较客观地分离各组件贡献。
- **跨模型泛化**：在两个不同智能体家族上均取得一致优势。

## 8. 不足与局限

- **自述局限**：
  - 固定输入预算可能丢失长历史中的相关证据；
  - 信念提取和应用仍不完美，尤其是撤回偏好和精确执行约束；
  - 未评估更广泛的应用（邮件撰写、推荐、日程规划等）。
- **实验覆盖**：
  - 仅两个基准和两个智能体家族，推广性有待验证；
  - 未报告训练种子/多次训练方差，某些统计结果不显著；
  - 部分消融（如 leave-one-out）只在 PersonaMem-v2 上评估，工具使用上的单任务消融不完整。
- **偏差风险**：
  - 训练目标的构建依赖教师模型（DeepSeek-V4-Flash 和父写入器），可能引入教师偏差；
  - 目标生成未校验记录事实内容，可能产生不准确信念；
  - 受控探针显示代理模型有时不遵守 `status: retracted`，说明状态字段无法保证下游遵守。
- **应用限制**：
  - 推理成本较高，每个新请求需要一次写入器生成；
  - 输入选择规则简单，对超长历史的分段处理有限；
  - 当前仅限文本输入，所用基础模型虽为视觉语言模型但未利用多模态信息。
