## 摘要
长期智能体随着交互的展开会积累大量外部记忆存储，从而增加存储、检索和响应生成的成本。效率受到两个耦合因素的制约：记录数量的增长会增加检索开销，而更长的检索上下文会增加预填充计算和解码时的注意力成本。现有方法会剪枝或合并记录，但剪枝可能丢弃有用证据，而合并可能产生更少但更长的检索单元。我们提出了 MemFolder，一个结构引导的记忆折叠框架，可依次减少记录数量和上下文长度。该框架包含两个共享记忆分组的核心组件，利用跨记录结构来指导证据合并和紧凑表示。RecordFolder 对实体提及进行实体锚定，逐步选择具有代表性且互补的锚点，并将语义和实体亲和度与时间链式关系相结合，将兼容记录合并为更少的检索单元。ContextFolder 将这些分组内的原始记录编码为紧凑文本，并在关键事实无法恢复时利用验证反馈修订编码。在三个文本记忆基准 LoCoMo、PersonaMem 和 LongMemEval 以及两个多模态基准 M3-Bench-web 和 M3-Bench-robot 上的实验证明了我们方法的强大性能。值得注意的是，在 Mem0 上，RecordFolder 在记录减少 50% 的情况下，在三个文本基准上保留了原始平均性能的 99.0%，在性能保持率上比最强基线高出 1.9 个百分点。与 ContextFolder 结合后，现有记录压缩方法进一步缩短了其输出记录，同时保留了大部分性能。

## Abstract
Long-term agents accumulate large external memory stores as interactions unfold, increasing the costs of storage, retrieval, and response generation. Efficiency is constrained by two coupled factors: a growing record count increases retrieval overhead, while longer retrieved contexts increase prefill computation and decoding-time attention costs. Existing methods prune or consolidate records, but pruning can discard useful evidence, whereas consolidation may produce fewer yet longer retrieval units. We introduce MemFolder, a structure-guided memory folding framework that sequentially reduces record count and context length. The framework comprises two core components that share memory groups, using cross-record structure to guide both evidence consolidation and compact representation. RecordFolder grounds entity mentions, progressively selects representative yet complementary anchors, and combines semantic and entity affinity with temporal chaining to consolidate compatible records into fewer retrieval units. ContextFolder encodes the original records within these groups into compact text and uses verification feedback to revise encodings when key facts cannot be recovered. Experiments on the three text-based memory benchmarks LoCoMo, PersonaMem, and LongMemEval and the two multimodal benchmarks M3-Bench-web and M3-Bench-robot demonstrate the strong performance of our methods. Notably, on Mem0, RecordFolder retains 99.0% of the original average performance across the three text-based benchmarks with 50% fewer records, exceeding the strongest baseline by 1.9 percentage points in performance retention. Combined with ContextFolder, existing record compression methods further shorten their output records while retaining most of their performance.

## 2. 方法论

MemFolder 是一个结构引导的记忆折叠框架，由两个共享记忆分组的组件顺序组成：

### 2.1 RecordFolder：记录级压缩

目标：将 \(N\) 条记录压缩为 \(K\) 个检索单元（\(K = \max\{1, \text{round}(\kappa N)\}\)，\(\kappa\) 为保留比例）。

核心流程：

1. **实体接地（Entity Grounding）**  
   - 使用 LLM 提取每条记录中的实体，包括人物、作品、活动、话题等，并赋予规范标签。  
   - 会话内联合处理以解析指代；跨会话维护标签注册表，复用已知实体标签，必要时用限定词区分同名实体。  
   - 对残差标签用嵌入余弦相似度合并（阈值 \(\theta_{\text{ent}}\)）。  
   - 过滤掉说话人和合成事件标识后，得到每条记录的实体集合 \(E_i\)。

2. **渐进式锚点选择（Progressive Anchor Selection）**  
   - 基于密度峰值聚类思想选择 \(K\) 个锚点。  
   - 首锚点：局部密度 \(\rho_i = \exp\left(-\frac{1}{k}\sum_{j \in kNN(i)} D_{ij}\right)\)，分离度 \(\delta_i = \min_{j: \rho_j > \rho_i} D_{ij}\)，选择 \(a_1 = \arg\max_i \rho_i\delta_i\)。  
   - 后续锚点：引入相对已选锚点的新颖性 \(\rho_i^{(r)} = 1 - \exp\left(-\frac{1}{k'}\sum_{a \in kNN_{A_r}(i)} D_{ia}\right)\)，并结合分离度继续选择，鼓励互补覆盖。  
   - 最近锚点分配形成初始分组 \(\pi_0\)。

3. **实体感知亲和度（Entity-Aware Affinity）**  
   - 实体权重：\(w(e) = \log(N / df(e))\)，其中 \(df(e)\) 是包含实体 \(e\) 的记录数，稀有实体权重更高。  
   - 实体集合质量：\(\mu(S) = \sum_{e \in S} w(e)\)。  
   - 实体相似度：\(e_{ij} = \mu_{ij} / \mu(E_i \cup E_j)\)，\(\mu_{ij} = \mu(E_i \cap E_j)\)。  
   - 最终亲和度：\(\text{affinity}(i,j) = \alpha_{ij} e_{ij} + (1-\alpha_{ij}) c_{ij}\)，其中 \(c_{ij}\) 是余弦相似度，\(\alpha_{ij}\) 由信号方差自适应计算。

4. **时间链式合并与固化（Temporal Chaining and Consolidation）**  
   - 对每个非锚点记录 \(m_s\) 考察前 \(W\) 条前驱记录 \(m_p\)，保留增益 \(g(p,s) = \text{affinity}(p,s) - \cos(x_s, x_{a_0(s)})\) 为正的链接，每节点最多保留 \(d\) 条链接。  
   - 用匈牙利匹配最大化总增益，保证时间顺序，形成非分支链。  
   - 锚点无入边，含锚点的链保留在原组；无锚链整体分配到余弦相似度最大的锚点组。  
   - LLM 按时间顺序合并同一组内的多条记录为一个检索单元。

### 2.2 ContextFolder：上下文级压缩

目标：在不改变分组的前提下，将每个组内原始记录编码为更紧凑的文本，并保证关键事实可恢复。

核心流程：

1. **规划器（Planner）**  
   - LLM 从组内记录中提取原子事实，并为每个事实生成验证问题和期望答案。  
   - 标注事实重要性（high/med/low）和可推断性（inferable）。  
   - 高重要性且不可推断的事实必须保留；中等重要性事实在目标保留比例 \(\tau \ge \tau_{\text{req}}\) 且不可推断时也要求保留。  
   - 事实权重：high/med/low 分别为 3/2/1；可推断事实权重减半。

2. **压缩器（Compressor）**  
   - 使用软 token 预算：\(B_G = \max\{3, \text{round}(\tau S_G)\}\)，\(S_G\) 是组内源记录总长度。  
   - 采用语法编码：`@YYYY-MM-DD` 表示日期，`A -> B` 表示状态变化，`E: x` 表示属性，`~` 表示否定，`?` 表示不确定。  
   - 优先保留不可推断的高重要性事实，丢弃可推断或低优先级细节，同时保持实体名、数字、日期的精确性。

3. **盲验证器（Blind Verifier）**  
   - 一个盲读者只看到压缩编码、语法图例和验证问题，看不到源记录和标准答案。  
   - 盲读者尝试回答问题，证据不足时返回 `UNKNOWN`。  
   - 判定器对回答与参考事实进行比较，允许语义近似，但名称、日期、数字必须精确匹配。  
   - 最多进行 \(R_{\max}\) 轮编码-验证循环；如果必需事实未通过或超出预算，则反馈修订。  
   - 选择通过全部必需事实的最短候选；若无候选通过，则最大化加权恢复率；若压缩后长度不短于源文本，则回退到源文本或较短候选。

  - 在 M3-Agent 上，70% 记录减少时性能保留达到 102.6%，即压缩后平均准确率反而略升。

## 7. 优点

- **双轴联合压缩**：同时减少记录数量和单条记录长度，避免传统方法只优化单一维度的缺陷。
- **结构引导**：利用实体、语义、时间等多种跨记录结构信号，提高合并质量。
- **验证反馈机制**：ContextFolder 的盲验证循环可以在压缩后检测关键事实是否丢失，并驱动修订，降低信息损失风险。
- **即插即用**：RecordFolder 和 ContextFolder 都能与现有记忆系统或压缩方法结合使用，灵活性强。
- **实验全面**：覆盖文本和多模态、多个底层框架、多种压缩比例，同时报告精度、token 效率和检索延迟，证据较充分。

## 8. 不足与局限
