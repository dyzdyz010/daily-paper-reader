## 摘要
多模态大语言模型（MLLM）智能体在任务导向环境中已展现出可观的能力。然而，当查询被推迟到探索之后时，它们仍然面临困难，因为这要求智能体在知道哪些细节重要之前保留视觉证据。我们提出 EvoViM，一个递归自进化的框架，其中冻结的多模态模型将自身的交互经验转化为一个用于记忆和技能的视觉程序。该程序保留图像并直接在像素上计算，其操作决定在每个任务中如何使用这些证据。在记忆进化过程中，同一模型追踪其视觉轨迹中的失败，定位到丢失或误用证据的操作并对其修正。它还会重写笔记和分析工具以指导后续修订，后续修订建立在早期发现之上，并跳过已失败的更改。我们在六个任务上使用三个多模态模型评估 EvoViM，任务涵盖视觉匹配、空间回忆和顺序决策，其中包括三个带延迟查询的任务。在这六个任务上，EvoViM 在留出集上的平均得分比主对比中最强基线 AutoMem 提高了 31.3-47.6 分。仅根据初始环境指令编写一次的程序表现明显更差，这凸显了交互经验在塑造视觉证据保留和使用方式中的价值。代码和数据集可在 https://evovim.github.io/ 获取。

## Abstract
Multimodal large language model (MLLM) agents have shown promising capabilities in task-oriented environments. However, they still struggle when queries are deferred until after exploration, requiring them to retain visual evidence before knowing which details will matter. We introduce EvoViM, a recursively self-evolving framework in which a frozen multimodal model turns its own interaction experience into one visual program for memory and skills. The program retains images and computes directly on pixels, and its operations decide how this evidence is used in each task. During memory evolution, the same model traces failures in its visual trajectories to the operations that lost or misused evidence and revises them. It also rewrites the notes and analysis tools that guide later revisions, which then build on earlier findings and skip changes that have already failed. We evaluate EvoViM with three multimodal models on six tasks covering visual matching, spatial recall, and sequential decision-making, including three tasks with deferred queries. Across the six tasks, EvoViM improves the average score over AutoMem, the strongest baseline in the main comparison, by 31.3-47.6 points on held-out episodes. Programs written once from the initial environment instructions perform substantially worse, highlighting the value of interaction experience in shaping how visual evidence is retained and used. Code and dataset are available at https://evovim.github.io/.

# EvoViM 论文总结

## 1. 核心问题与整体含义

- **研究背景**：多模态大语言模型（MLLM）智能体在任务导向环境中表现良好，但主要处理指令先行、查询已知的场景。
- **核心问题**：在“延迟查询探索”（exploration with deferred queries）中，智能体需要在探索阶段保留视觉证据，但此时并不知道后续会问什么问题、哪些视觉细节将来重要。这要求智能体在没有明确目标的情况下决定存储什么、如何存储以及如何利用证据。
- **现有方法的不足**：
  - **文本记忆**（如 AutoMem 演化出的文本记忆）难以保留相似图像之间的细微视觉差异，导致检索时无法区分。
  - **手工设计的视觉记忆**（如 VISTA 风格的全帧存储）能保留像素，但缺乏将匹配证据转化为正确答案的任务特定操作，例如把匹配结果关联到位置信息或判断“未见过”。
  - **一次性编写的程序**往往基于初始环境指令预设错误的问题，无法适应实际延迟查询的需求。
- **论文整体含义**：提出 EvoViM，通过递归自进化，让冻结的 MLLM 将自身交互经验转化为一个统一用于记忆和技能的**视觉程序**，并让该程序直接对像素进行计算，从而在延迟查询任务中实现有效的证据保留与利用。

## 2. 方法论

- **核心思想**：
  - 将记忆和技能视为经验的两个用途，统一置于一个视觉程序中。
  - 程序在当前 episode 中保存观察结果，其操作（决定保留什么、如何利用）由之前 episode 的经历塑造。
  - 冻结的 MLLM 执行任务，并在代际之间修订程序；同时它还会修订用于指导后续修订的笔记和分析工具，形成递归进化。

- **视觉程序结构**：
  - 程序定义**记忆操作**和**图像处理工具**，使用 Python 编写，并包含指导模型使用这些工具的提示词。
  - 可以存储完整视图、对象裁剪或与位置关联的像素特征。
  - 像素计算允许程序处理存储证据和当前图像，保留文本笔记难以保留的视觉区分。
  - **视觉召回**将选中的帧、裁剪或蒙太奇放入下一个模型请求中，使存储在决策时可被使用。
  - 程序代码还可读取当前帧和累计状态，为候选动作评分或建议下一步动作。

- **任务执行（Algorithm 1）**：
  - 每个步骤包含两个阶段：**记录（Record）阶段**和**行动（Act）阶段**。
  - 记录阶段：模型观察前一个动作的结果，决定是否将信息写入记忆。
  - 行动阶段：模型调用记忆程序和工具，选择并提交动作。
  - 每个阶段开始新对话，episode 记忆通过程序保持可用；所有请求包含当前图像，工具结果进入下一请求。

- **程序修订（Algorithm 2）**：
  - 首先运行起始程序获取开发集 episode。
  - 每一代，模型使用命令行编码工具检查父程序及其开发 episode，包括按步骤标记的帧、记忆快照和工具结果。
  - 每个修订使用两个开发种子的证据，并要求模型解释变化为何能在未见实例上奏效；禁止将开发集中的具体事实硬编码，必须从观察中动态获取。
  - 反馈包含**增强反馈**：episode 摘要、工具使用统计、固定分析问题，帮助模型识别证据丢失或误用位置，并要求提出结构修订（如新存储模式或处理视觉证据的工具）。
  - 模型维护**playbook**、**笔记**和**分析脚本**，将先前经验保留并传递给后续修订，包括被拒绝的候选。
  - 候选经过**代码检查**（使用桩模型回放记录观察，测试工具接口和状态恢复）和**门控**（开发集平均分数更高才接受，平局需满足效率条件并降低 token/步数）。候选失败可重试一次。

## 3. 实验设计

- **任务与数据集**：
  - **Card Matching**（视觉匹配）：基于 RNG-Bench，12×12 噪声纹理卡片，144 张卡，需记住卡片外观和位置找出配对。
  - **DMV-Hard**（视觉匹配，延迟查询）：基于 DMV-Bench，100 个产品页面，加入生成图案，查询为照片细节或图案的变换裁剪，需识别先前浏览产品。
  - **MC Gallery**（空间回忆，延迟查询）：基于 GameWorld，探索画廊，之后被展示重拍绘画图片，回答其悬挂位置；包含未见过的诱饵。
  - **Poster Maze**（空间回忆，延迟查询）：基于 RNG-Bench，探索迷宫，之后回答海报位置；同样包含诱饵。
  - **Tetris** 和 **Pac-Man**（顺序决策）：基于 GameWorld，测试从当前观测进行决策的能力。

- **基准方法**：
  - No memory（无记忆参考）
  - Rolling summary（文本压缩，风格类似 ReSum）
  - Hand-crafted text（手工文本记忆，AutoMem 的起点）
  - Hand-crafted visual（手工视觉记忆，EvoViM 的起点）
  - AutoMem（演化的文本记忆程序，最强基线）
  - EvoViM（本文方法）

- **模型**：GPT-6.1 Sol、Claude Haiku 5.5、Qwen3.8-27B。
- **评估指标**：
  - Card Matching：配对清除比例。
  - DMV-Hard：答案准确率，并区分照片细节与生成图案。
  - MC Gallery 和 Poster Maze：8 个问题中正确回答比例（诱饵必须回答“未见过”）。
  - Tetris 和 Pac-Man：GameWorld 归一化任务进度。
  - 使用留出集上的 bootstrap 置信区间（10,000 次成对重采样）评估统计显著性。
- **实验协议**：每个任务和模型各进化一个独立程序，3 代，共用两个开发种子；留出集与开发集完全分离。

  - 使用留出集和 bootstrap 置信区间，结果统计较为客观。
  - 与多个基线对比，包含最强基线 AutoMem 和手工视觉记忆，比较公平。
  - 消融和机制分析深入，但部分消融仅使用一个模型（Claude Haiku 5.5），且重复运行次数有限（如 MC Gallery 3 次），可能影响稳健性结论。
  - 未报告多种随机种子下的平均变异，部分最终程序存在较高方差（如 Poster Maze 标准差较大）。

## 6. 主要结论与发现

- **整体性能**：EvoViM 在六个任务上的平均分比最强基线 AutoMem 高 **31.3–47.6 分**，在所有三个模型上均排名第一（除顺序决策组在 GPT-6.1 Sol 上未领先）。
- **视觉匹配**：EvoViM 在 DMV-Hard 上对照片细节和生成图案都能较好回答，而 AutoMem 主要只在照片细节上成功；Card Matching 上 EvoViM 清除了全部配对，Qwen3.8-27B 的翻转次数达到完美记忆和逐行探索的贪婪策略水平。
- **空间回忆**：EvoViM 在 MC Gallery 和 Poster Maze 上超过固定视觉记忆，即使后者配了通用匹配器；演化的程序能将存储视图与位置关联并有效判断“未见过”。
- **顺序决策**：Claude Haiku 5.5 和 Qwen3.8-27B 的 EvoViM 在 Tetris 和 Pac-Man 上得分最高；程序提供从像素计算的动作建议，提高效率并减少静止步骤。
- **成本**：在部分模型上，EvoViM 用更少的输入 token 取得更高得分；但在 DMV-Hard 上 EvoViM 使用更多模型 token，而代码运行时间远低于自动搜索变体。
- **机制分析**：演化出的程序几乎都会新增图像记忆和帧解析机制，而 AutoMem 主要增加文本笔记；修订经验被后续修订复用，第一代带来大部分收益。
- **核心结论**：交互经验对塑造视觉证据的保留和利用至关重要；仅从初始指令编写的程序表现显著更差。

## 7. 优点

- **新颖统一的框架**：首次将记忆和技能统一为一个视觉程序，并让程序直接对像素操作，突破了文本记忆在视觉区分上的局限。
- **递归自进化设计**：不仅程序本身进化，指导程序修订的笔记、playbook 和分析脚本也同步进化，形成层次化自改进。
- **强泛化与防过拟合措施**：修订过程中明确禁止硬编码开发集事实，强制模型从观察中提取信息，并增加多种子验证。
- **实验设计扎实**：覆盖三类能力、三种模型、多个基线，使用留出集和置信区间，并进行了大量消融和失败归因分析。
- **效率优化明显**：在多个任务上，演化程序通过代码计算减少模型重复推理，降低 token 和请求次数。
- **分析深入**：提供了程序机制统计、修订记录、失败阶段归因、修复案例分析等，增强了可解释性。

## 8. 不足与局限

- **任务范围有限**：未评估涉及音频或具身环境中的多模态任务；作者也指出需要进一步测试感官噪声和视觉-听觉证据结合。
- **模型依赖与不稳定性**：GPT-6.1 Sol 在顺序决策任务上未取得领先，其程序对动作选择的代码支持不足；部分进化运行之间存在较大波动（如 MC Gallery 重复运行得分 67.5–98.8），进化过程可能不稳定。
- **成本不平衡**：在 DMV-Hard 等任务上，EvoViM 的模型 token 消耗高于自动检索变体，且代码运行时间并非总是最低。
- **实验充分性限制**：消融实验主要使用 Claude Haiku 5.5 一个模型，重复运行次数较少；对进化过程本身的随机性控制有限。
- **应用限制**：框架依赖 Python 代码环境和可定义的像素计算工具，对无法利用代码工具或真实连续控制环境的迁移可能受限；此外，使用的模型版本较新且可能由作者自行设定，外部复现可能存在版本或可用性问题。
- **偏差风险**：论文声明使用 Claude Code 辅助实验、分析和写作，虽然作者检查输出，但存在轻微的潜在偏差；此外，Pac-Man 的执行受壁钟时间影响，导致运行间变异性可能干扰结果。
