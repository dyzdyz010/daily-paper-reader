## 摘要
LLM 智能体在推理与工具执行之间交替，跨调用重复使用其不断增长的上下文。在高并发下，它们合并的键值（KV）缓存工作集可达数百 GiB，远超 GPU 内存容量。当空闲 KV 缓存块被逐出到更慢的存储层时，返回的智能体会产生昂贵的读取，导致推理停顿。为解决此问题，我们提出 TripleKV，一个三层 KV 缓存管理系统，用于隐藏这些读取延迟。在智能体工作负载中，下一次推理请求所需的 KV 块是预先已知的；不确定的只是其重用时间。TripleKV 使用工具感知的延迟预测器来估计每次工具调用何时完成，并提前将所需 KV 块从 SSD 预取到主机 DRAM。与 GPU 预取不同，这避免了占用稀缺的 GPU 内存并干扰并发推理请求。为进一步提高 DRAM 利用率，TripleKV 消除了 DRAM 中与 GPU 常驻块的重复，并引入牺牲缓存机制，在块从 GPU 内存被逐出时从 SSD 重新填充。在数据、网页和编程智能体上，TripleKV 将需要关键路径 SSD 读取的请求比例从 45–76% 降至 10% 以下。与扩展了 DRAM 和 SSD KV 缓存层的 vLLM 相比，它还将 P95 首 token 时间（TTFT）最多降低 49%；与近期智能体感知系统相比，P95 TTFT 降低 1.5–7 倍。

## Abstract
LLM agents alternate between inference and tool execution, repeatedly reusing their growing context across calls. Under high concurrency, their combined key-value (KV) cache working set can reach hundreds of GiB, far exceeding GPU memory capacity. As idle KV cache blocks are evicted to slower storage tiers, returning agents incur expensive retrievals that stall inference.   To address this problem, we present TripleKV, a three-tier KV cache management system that hides the delays of these retrievals. In agentic workloads, the KV blocks needed by the next inference request are known in advance; only the time of their reuse is uncertain. TripleKV uses a tool-aware latency predictor to estimate when each tool call will complete and prefetches the required KV blocks from SSD into host DRAM ahead of time. Unlike GPU prefetching, this avoids reserving scarce GPU memory and interfering with concurrent inference requests. To further improve DRAM utilization, TripleKV eliminates duplication of GPU-resident blocks in DRAM, and introduces a victim-cache mechanism that refills blocks from SSD upon their eviction from GPU memory.   Across data, web, and coding agents, TripleKV reduces the fraction of requests requiring critical-path SSD reads from 45-76% to under 10%. It also reduces P95 time to first token (TTFT) by up to 49% compared with vLLM extended with DRAM and SSD KV-cache tiers, and achieves 1.5-7$\times$ lower P95 TTFT than recent agent-aware systems.
