ABSTRACT
Long-horizon agents repeatedly feed an ever-growing interaction trajectory to a
specialized agent model. Prefix caching reuses computation over repeated history,
but cannot prevent context growth or remove information irrelevant to the current
decision. This is especially costly when the specialized agent lacks the cached-
input discounts available to general-purpose models, making trajectory compres-
sion a natural alternative. However, existing compression methods on selective
context risk losing global information, recursively rewriting summary leads to se-
mantic drift, while repeatedly recompressing the full history shifts the growing
cost to the compressor. Therefore, we introduce DMC-5 (Dual-Model Collabo-
ration with CaChe-aware Context Compression), an asymmetric framework that
assigns full-history integration to a general compression model and action gen-
eration to a specialized agent model. DMC-5 maintains the raw trajectory as an
Append-only Canonical View, preserving global access while allowing the com-
pressor to reuse a stable historical prefix instead of recursively rewriting or recom-
puting prior context. The agent operates only on a compact Decision View with
recent raw interactions, reducing repeated input while retaining the information
needed for the next action. DMC-5 further incorporates YAMATO (integritY-
Aware Memory Abstractions for Tool Operations) to preserve execution-critical
information during lossy compression. Experiments on AppWorld, OfficeBench,
and 8-objective QA show that DMC-5 reduces agent model input by 38.5∼57.0%
and end-to-end cost by 14.5∼28.0% with 78.0∼85.0% compressor cache-hit rates,
while improving task performance by 1.0∼5.8% over the uncompressed baseline.

INTRODUCTION
Long-horizon, tool-using agents repeatedly ask a specialized decision model to reread an ever-
growing trajectory of reasoning, actions, and observations (Yao et al., 2023; Packer et al., 2023).
As shown in Fig. 1(a), an LLM agent repeatedly rereads a growing history, although only a small
fraction is relevant to current decision, increasing cost and distracting the model (Laban et al., 2026).
Prefix caching reuses stable prefixes (OpenAI, 2026; Song, 2026) to reduce computation, but it nei-
ther shortens the context length nor removes irrelevant content. This cost is especially pronounced
for fine-tuned or customized agent endpoints, for which cached-input discounts are often unavailable
or limited than those offered for general models. (OpenAI, 2026; Google Cloud, 2026; Microsoft
Azure, 2026; Alibaba Cloud, 2026). To address this issue, trajectory compression shifts history in-
tegration to a lower-cost compressor, reducing the context repeatedly processed by the agent model.
Existing compressors reduce agent-side context through three update patterns in Fig. 1(b), but each
incurs extra end-to-end cost. Selective Context (Xiao et al., 2026; Ning et al., 2026; Hu et al.,
2025; Ye et al., 2026; Verma, 2026) keeps raw trajectory in sliding window and compresses context
outside, reducing compression cost at the risk of missing global information and triggering repeated
steps. Recursive Summary (Zhou et al., 2026; Yu et al., 2026; Wu et al., 2025) updates a previous
summary with new interactions to avoid full-history rereading, but rewritten summary can accumu-
late semantic drift (Kang et al., 2026; Shi et al., 2026) and limit prefix-cache reuse. Full-history
Recompression (Li et al., 2023; Jiang et al., 2024; Xu et al., 2024) rebuilds context from retained

Therefore, a practical compression framework must control both compression overhead and the
interaction overhead introduced by information loss. This requires the compressor and the agent
to consume different views of the trajectory. An ideal compressor should retain access to the full
trajectory so that previously observed information remains recoverable, while extracting the context
most relevant to the current task. This full-history role can be assigned to a general model with strong
cross-task generalization and discounted cached-input pricing, using an append-only trajectory view
to preserve prior information and maintain stable prefix reuse across compression rounds. The
agent, in contrast, should specialize in the downstream task and action space, often through fine-
tuning, while consuming only a compact Decision View that keeps information critical for the next
action, especially when its deployment provides no or limited cached-input discount. Together, this
asymmetric design assigns full-history integration to a general compression model and compact
action generation to specialized agent model, reducing both compression and interaction overhead.
Motivated by this, we introduce DMC-5 (Dual-Model Collaboration with CaChe-Aware Context
Compression), an asymmetric framework that assigns full-history integration to a general compres-
sion model and action generation to a specialized agent model. Its compressor reads an Append-
only Canonical View containing the full-history raw trajectory, so each compression integrates the
full history without recursively rewriting previous summaries, while the unchanged prefix remains
reusable across compression rounds. The agent receives a Decision View composed of compact
context and recent raw interactions, reducing repeated input while preserving critical information
for the next action. To protect execution-critical state during lossy compression, DMC-5 incorpo-
rates YAMATO (integritY-Aware Memory Abstractions for Tool Operations). YAMATO lets the
compressor reference selected raw actions, tool results, and work-product updates through pinned
pointers, and deterministically restores the information from the raw records rather than being rewrit-
ten by the model. It also maintains a persistent failure ledger and provenance tags across compres-
sion. Therefore, DMC-5 preserves full-history access during compression, keeps the agent context
compact, and protects state whose corruption or omission could affect subsequent execution.
Across AppWorld, OfficeBench, and 8-objective QA, DMC-5 reduces agent-model input by
38.5∼57.0% and end-to-end cost by 14.5∼28.0%, while achieving 78.0∼85.0% compressor cache-
hit rates. Compared with the uncompressed baseline, task performance improves by 1.0∼5.8%
across the three benchmarks. In summary, we conclude our contributions as follows:

• We propose DMC-5, separating cache-aware context compression from specialized action

• We evaluate DMC-5 across three long-horizon agent benchmarks. It reduces agent input

DMC-5: DUAL-MODEL COLLABORATION
Full-history integration and action generation impose different context requirements: the former
benefits from complete historical access, while the latter should avoid repeatedly processing irrele-
vant history. Therefore, DMC-5 assigns full-history integration to a general compressor (denoted as
V) and action generation to a specialized agent (denoted as Urizen), as shown in Fig. 2(a). Accord-

View for V and a compact Decision View for Urizen.

2.3
V: CACHE-AWARE CONTEXT COMPRESSION
Full-history compression preserves access to earlier information, but repeatedly processing the
growing trajectory can shift the cost from the agent to the compressor. V addresses this cost through
append-only prefix reuse, as shown in Fig. 2(b). Compression is triggered when the accumulated
uncompressed history exceeds a token threshold T or the compression interval ∆is reached. At
agent turn t, V’s input is decomposed as
XV
t = Ht ⊕Ut,
(10)
where Ht is the previously processed prefix and Ut contains newly eligible turns since the last
compression. Because the canonical trajectory is append-only, Ht remains byte-identical and in
the same order across compression events, allowing the endpoint to serve Ht at the cached-input
price while only Ut is prefilled as new input. Therefore, V retains access to the full history without
repeatedly paying the uncached-input cost for the same trajectory.
Once the compression is triggered, V outputs a structured summary containing completed and pend-
ing progress, key data, and pinned pointers to execution-critical raw records in canonical view. The
output is passed to YAMATO and is never written back to the canonical trajectory. With the cache-
aware context compression design, V retains full-history access without recursive summary, while
keeping the historical prefix reusable across compression rounds.
2.4
YAMATO: INTEGRITY-AWARE MEMORY ABSTRACTIONS FOR TOOL OPERATIONS
Lossy compression reduces agent input, but corrupted or omitted tool operation state can cause in-
correct or repeated actions. Tool operation often depends on exact identifiers, arguments, returned
values, and artifact states. As shown in Fig. 2(c), YAMATO preserves such execution-critical infor-
mation through deterministic restoration rather than model transcription, maintaining information
integrity while reducing output tokens.
Specifically, YAMATO treats records whose values may affect subsequent action (e.g., identifiers,
arguments, returned values, and work-product states) as execution-critical, and lets compressor ref-
erence them through pointers. In particular, V outputs a structured summary Zt and a set of pinned
pointers Πt:

terms of Ccmp rather than optimizing the agent-side compression ratio alone.

EXPERIMENTAL SETUP
Benchmarks. We evaluate DMC-5 on three long-horizon agent benchmarks. AppWorld (Trivedi
et al., 2024) contains 168 executable multi-step application tasks, while OfficeBench (Wang et al.,
2024b) contains 192 shorter office-oriented tool-use tasks; we report accuracy on both. 8-objective
QA contains 200 multi-objective tasks with substantially longer accumulated context, follow-
ing (Kang et al., 2026) and report EM/F1. Together, they cover complex executable interaction,
shorter workflows, and long-context information integration. Detailed task splits are provided in
Appendix 6.2. All results are averaged over three independent runs, reported in Appendix 6.3.1
Models and baselines. For fair comparison, we use the same fine-tuned Qwen3.5-27B as the agent
and DeepSeek-V4-flash as the compressor, comparing against NO COMPRESSION, FIFO (Yang
et al., 2024), AGENTDIET (Xiao et al., 2026), and ACON (Kang et al., 2026). ACON is evaluated
under official implementation, while AgentDiet is reproduced since no official code is available,
reported in Appendix 6.2.4. Other model configurations are specified in the corresponding ablations.
Cost billing. We compute billed cost from observed uncached input, cached input, and output tokens
using Eq.(5). All reported costs come from total tasks run and include both agent and compressor
calls. Cache Hit denotes the provider-reported cached tokens. Details please refer to Appendix 6.2.2
Hyperparameters. We use K = 1, ∆= 3, and T = 6000 by default. The compressor uses
temperature 0 with thinking disabled, while the agent follows benchmark-default decoding. Please
see Appendix 6.2.3 for more details.

3.3
ANALYSIS ON CACHE-AWARE CONTEXT COMPRESSION
Append-only vs. Recursive Summary. Table 2 shows that compared with ACON-style recursive
summary, append-only DMC-5 configuration reuses 15.6K∼198.2K cached tokens per task and
reduces uncached compressor input by 12.7∼42.3% across the three benchmarks, while improving
task scores by 4.7∼10.9%. Despite processing more total compressor tokens, DMC-5’s compressor
cost remains comparable to recursive compression, with 23.7% and 25.1% lower cost per success on
AppWorld and 8-objective QA, respectively. Fig. 4 further shows that the cache-hit rate of append-
only input increases from 0 to 96% by the last compression, whereas recursive compression records
no cache hits. Therefore, DMC-5 retains full-history access while leveraging low-cost prefix caching
to handle repetitive history, achieving higher task performance and lower end-to-end cost.
Longer trajectories benefit more from DMC-5. Fig. 5 shows how the cost structure changes
as an AppWorld trajectory grows. Without compression, per-step cost continues to increase with
the accumulated history. After compression, DMC-5 reduces the agent-side cost and eventually
drives it downward, indicating that the Decision View removes substantial redundant history, while
the Append-only Canonical View keeps the added compressor cost growing slowly through prefix
reuse. Table 3 shows the same trend that tasks compressed only once cost 10.7% more than No
Compression, whereas tasks with at least two compressions save 16.6∼26.5% and improve accuracy
by 3.7∼9.7%. As these per-step savings accumulate, Fig. 6 shows that DMC-5 reaches break-even
around step 16 and achieves 25% net cost saving by step 50. Easy tasks realize savings earlier, while
hard tasks gain more as the trajectory grows, reaching 30% cumulative saving. Overall, longer tasks

ANALYSIS ON ASYMMETRIC DUAL-MODEL COLLABORATION
Table 4 evaluates whether history integration and action generation benefit from different model
roles.
Using the same compressor, replacing the general agent with the specialized fine-tuned
Qwen3.5-27B improves AppWorld success from 67.9% to 78.2% with DeepSeek-V4-flash, and
from 61.3% to 73.8% with Qwen3.7-flash. This shows that the specialized model remains important
for downstream action generation even when it no longer processes the full trajectory.
At the same time, moving full-history integration to a general compressor reduces the cost of spe-
cialized calls. Using the specialized model itself for compression raises total cost to 21.49 with only
77.4% success, whereas DeepSeek-V4-flash→Specialized achieves 78.2% at 10.31. Qwen3.7-flash
further lowers the cost to 9.50, but its lower 73.8% success shows that the compressor must still
preserve an accurate Decision View. Overall, the results support the asymmetric design: general
models provide cheaper full-history integration, while specialized agents preserve action quality.

3.6
GENERALIZATION TO AGENT ENDPOINTS WITH CACHED-INPUT DISCOUNTS
To evaluate DMC-5’s generalization ability under deployments where the acting agent also benefits
from prefix caching, we repeat the same AppWorld tasks using a Qwen3.8-27B base endpoint with
discounted cached-input pricing. The results show that DMC-5 remains cost-effective even when
the uncompressed agent already achieves a high cache-hit rate. At the actual price ratio of 20%, the
baseline achieves a 70.5% agent cache-hit rate, while DMC-5 achieves 51.5%. Despite the lower
agent-side cache reuse, DMC-5 reduces total cost from 35.72 to 32.38 (9.4%) and increases task
success from 71.5% to 73.9%.
We further quantify the break-even boundary by varying the agent-side cached-input price while
keeping the uncached-input price and observed token traces fixed. As shown in Table 6, the two
methods reach equal cost at a cached-to-uncached price ratio of 9.1%. Thus, DMC-5 remains
cheaper as long as the cached-input price exceeds 9.1% of the uncached-input price. Under the
actual pricing ratio of 20%, DMC-5 operates comfortably within this cost-saving region.
Overall, although DMC-5 is primarily designed for specialized agents without cache discounts, our
results demonstrate that it also generalizes effectively to cache-enabled agent deployments.

RELATED WORK
Agent context compression and memory. Prompt compression shortens an LLM’s input by token
selection or summaries. LLMLingua and LongLLMLingua use smaller models to identify useful
content, while RECOMP compresses retrieved evidence (Jiang et al., 2023b; 2024; Xu et al., 2024).
Agent trajectories require repeated compression because they grow after every action. MemGPT
manages context as tiered memory, and HiAgent groups interactions by subgoal (Packer et al., 2023;
Hu et al., 2025). ACON optimizes compression guidelines for histories and observations and distills
them into smaller compressors; AgentDiet removes useless, repeated, or expired content; AdaCoM
trains an external context manager; and Focus lets an agent trigger consolidation (Kang et al., 2026;
Xiao et al., 2026; Yi et al., 2026; Verma, 2026). MemAgent streams long inputs through a fixed-size
memory trained with reinforcement learning (Yu et al., 2026). These methods shorten the acting
model’s context by selecting, rewriting, or externally managing prior state. Instead, DMC-5 keeps
the raw trajectory append-only for repeated full-history integration, preserving a stable cached prefix
for the compressor while providing the specialized agent with a separate compact Decision View.
Cache-aware LLM inference.
Serving systems reduce repeated-prefix cost by managing KV
caches. KVFlow schedules cache retention for agent workflows, CacheBlend reuses non-prefix
caches through selective recomputation, and ThinKV compresses reasoning-model caches with
adaptive quantization and eviction (Pan et al., 2025b; Yao et al., 2025; Ramachandran et al., 2026).
LRAgent supports cache sharing across LoRA-specialized agents by separating shared and adapter-
dependent states (Jeon et al., 2026). CAPC is particularly relevant to our setting, as it shows that
query-dependent prompt compression can disrupt prefix reuse and explicitly optimizes compression
for cache compatibility (Song, 2026). However, CAPC focuses on cache-aware compression within
individual prompts, whereas DMC-5 considers repeated trajectory compression across agent turns.
By maintaining an append-only full-history view, DMC-5 enables trajectory-level history integration
to continuously reuse existing prefix caches and benefit from serving-side cache optimizations.
Multi-model collaboration and agent efficiency.
Model cascades and routers reduce cost by
assigning requests to models with different capabilities.
FrugalGPT learns API cascades, and
RouteLLM selects between stronger and weaker models from preference data (Chen et al., 2024;
Ong et al., 2025). DUET uses one model to produce a short reasoning signal that another turns into
an answer (Chen et al., 2026). Research on agent evaluation also argues that quality and resource
use should be measured together (Kapoor et al., 2025). Unlike routing or cascade methods that de-
cide which model should answer a request, DMC-5 keeps both models active with fixed asymmetric
roles. The general model integrates full history into a compact Decision View for specialized model
to generate action, reducing end-to-end cost while keeping task performance of long-horizon agents.

CONCLUSION
We presented DMC-5 (Dual-Model Collaboration with CaChe-Aware Context Compression), a
dual-model framework for reducing end-to-end cost of long-horizon agents by assigning full-history
integration to general compressor and action generation to specialized agent. DMC-5 uses Append-
only Canonical View to preserve full-history access and prefix-cache reuse, compact Decision View
to reduce repeated agent input, and YAMATO (integritY-Aware Memory Abstractions for Tool Op-
erations) to protect execution-critical information during lossy compression. Across AppWorld,
OfficeBench, and 8-objective QA, DMC-5 reduces agent input by 38.5∼57.0% and end-to-end cost
by 14.5∼28.0%, while improving task performance by 1.0∼5.8% over uncompressed baseline.

6.1
YAMATO IMPLEMENTATION DETAILS
YAMATO augments lossy semantic compression with execution-critical information that should
not be reconstructed from model-generated text. It introduces no additional LLM calls: all model-
generated fields are produced within the existing compressor call, while pointer restoration, work-
product retention, failure tracking, and provenance checks are implemented deterministically in
code.
At compression round r, the compressor V reads the task instruction and the eligible prefix of the
Append-only Canonical View, and outputs

(13)
where Zr is a structured semantic summary and Πr contains references to canonical records that
should be restored exactly. YAMATO organizes the compressed state through three complemen-
tary mechanisms: (i) a structured summary with turn provenance, (ii) exact restoration of selected
canonical records, and (iii) a persistent failure ledger. The resulting compact state is then combined
with recent uncompressed turns to form the Decision View.
6.1.1
CANONICAL RECORDS AND PRESERVATION CANDIDATES
Each canonical turn ξi = (ai, oi) contains the agent action ai and its observation oi, both of which
remain unchanged in the Append-only Canonical View. YAMATO maintains a turn registry that
maps each turn index i to its raw action and observation strings.
Specifically, each new action–observation turn is serialized once when it is appended to the Canon-
ical View. Deterministic rules add a type marker to the turn header: (API DOC) and (FILE
CONTENT) denote literal tool outputs, (WORK PRODUCT) denotes artifact-producing or artifact-
updating actions, and (FAILED) denotes unsuccessful operations. Once appended, earlier turns are
neither regenerated nor relabeled, preserving the byte-identical historical prefix required for cache
reuse.
For example, an API-documentation turn may be serialized as:
--- Turn 7 (API DOC) ---
[ASSISTANT ACTION]
get_api_documentation("calendar.create_event")
[TOOL RESULT]
create_event(calendar_id, title, start_time)
These markers guide the compressor in identifying candidate records for exact preservation. When
a marked record is needed in the Decision View, the compressor can reference it with a turn pointer
instead of copying the full raw content into the semantic summary. For example, it may emit
<<TURN 7 RESULT>>, which YAMATO resolves deterministically to the original observation
stored in the Canonical View.

6.2.3
INFERENCE CONFIGURATION, PROMPTS, AND COMPRESSION SETTINGS
Inference configuration.
All compressor calls use greedy decoding with temperature 0 to mini-
mize stochastic variation in the compressed state. We disable the model’s internal thinking mode
(enable thinking=false), since trajectory compression is formulated as structured informa-
tion extraction and state preservation rather than open-ended reasoning. For the specialized agent,
we retain the decoding configuration recommended by the deployed API endpoint, including its
default temperature and benchmark-consistent thinking setting. We do not fix generation seeds. In-
stead, all reported results are obtained from three independent runs to capture the stochasticity of
API-based agent execution.
Hyperparameters.
Unless otherwise specified, DMC-5 uses the same compression configuration
across all three benchmarks. The most recent K = 1 interaction turn is always retained verbatim
in the Decision View. A new compression round is triggered when either (i) three new interaction
turns have accumulated since the previous compression, or (ii) the newly accumulated uncompressed
trajectory exceeds 6,000 tokens. Thus, with compression interval ∆= 3 and token threshold T =
6,000, the trigger condition is
Compress(t) = I [∆turn(t) ≥3 ∨∆token(t) ≥6,000] .
(26)
At each compression round, the compressor reads the complete eligible prefix from the Append-only
Canonical View, while the most recent turn remains uncompressed.

6.2.4
BASELINE IMPLEMENTATIONS
We compare DMC-5 against four representative context-management settings. Unless otherwise
specified, all methods use the same fine-tuned Qwen3.5-27B agent, the same 50-step interaction
cap, and the same cost-accounting rules. For methods that require an auxiliary compression model,
we use DeepSeek-V4-flash unless stated otherwise. Method-specific trigger and update policies are
preserved by design.
No Compression.
The agent receives the complete interaction trajectory at every step without any
history reduction or auxiliary compressor. This setting serves as the full-history reference for both
task performance and end-to-end cost.
FIFO.
FIFO retains only the most recent five interaction turns and discards all earlier turns (Yang
et al., 2024). It introduces no auxiliary model call and therefore represents a simple window-based
context reduction baseline. We use the same five-turn window as in prior long-horizon agent com-
pression evaluations.
25


AgentDiet.
AgentDiet (Xiao et al., 2026) performs inference-time trajectory reduction by revisit-
ing an earlier interaction after a fixed lag and replacing it with a shorter version when redundant, ex-
pired, or otherwise unnecessary content can be removed. The reduction is produced by a lightweight
reflection model conditioned on the target interaction and its surrounding trajectory context. Due
to no official implementation was available, we reproduced the method following the algorithm and
prompting strategy described in the paper. The hyperparameters used are the same as those for
DMC-5 or follow the default settings from the original paper.
ACON.
ACON (Kang et al., 2026) uses generative history compression in which the current com-
pressed memory is recursively updated with newly accumulated interactions. We use the official im-
plementation, with only the adaptations required to interface with our agent/compressor endpoints
and evaluation configuration. The agent model, compressor model, maximum interaction steps, and
cost accounting are the same as those for DMC-5.

6.3.2
HYPERPARAMETER SENSITIVITY
DMC-5 has three main context-control hyperparameters: the recent raw-turn window K, com-
pression interval ∆, and token threshold T. Our default configuration uses K = 1, N = 3, and
T = 6000. We vary one hyperparameter at a time while keeping the other two fixed.
The results show that DMC-5 is reasonably stable around the default configuration. For the com-
pression threshold, an overly small T = 3000 degrades both accuracy and cost efficiency, while
increasing T beyond 6000 brings no further quality gain and slightly increases cost. Varying the
recent raw-turn window has only a minor effect on accuracy, but larger K consistently increases
cost by retaining more uncompressed context. The compression interval exhibits the clearest trade-
off: compressing every turn (N = 1) substantially increases cost and also hurts accuracy, whereas a
larger interval (N = 5) slightly reduces task quality without further cost benefit. Overall, the default
setting T = 6000, K = 1, and N = 3 provides the best quality–cost balance among the evaluated
configurations.

6.4
LIMITATION AND FUTURE WORK
Our experiments show that DMC-5 remains effective across different compressor models, task
difficulties, and a broad range of pricing configurations, while YAMATO substantially mitigates
compression-induced information loss and repeated failures. Nevertheless, several broader settings
remain beyond the current design scope.
First, DMC-5 is designed primarily to reduce billed inference cost by separating full-history in-
tegration from specialized action generation and exploiting prefix reuse in the compressor. The
current implementation already achieves substantial cost savings, but compression is performed
synchronously, so the additional compressor calls can increase wall-clock latency. Further reducing
this latency overhead remains an open problem beyond the current scope of DMC-5. Future work
could therefore investigate asynchronous or parallel compression, speculative refresh, and overlap
between compression and agent execution.
Second, YAMATO effectively protects execution-critical information from corruption or omission
during compression. However, when the required information is already available, the underlying
agent may still make task-interpretation or reasoning errors. Handling such reasoning errors remains
beyond the current scope of DMC-5 and may benefit from stronger planning, verification, or self-
correction mechanisms.
Third, DMC-5 currently uses a fixed compression policy with predefined thresholds and a fixed di-
vision of roles between the general compressor and specialized agent. Our sensitivity experiments
indicate that the default policy is robust across the evaluated settings, but different workloads may fa-
vor different compression timing, context allocation, or compressor choices. Adapting compression
behavior to workload characteristics remains an open direction beyond the current scope of DMC-5.
Future work could explore adaptive compression triggers, dynamic model selection, and tighter in-
tegration with serving-side cache management, as well as broader evaluation on longer-horizon and
more heterogeneous agent workloads.
6.5
RELATED WORK
Section 4 provides a compact comparison in the main paper. Here we further distinguish related
methods by the state they operate on, how that state is updated over time, and where computational
savings arise.
6.5.1
AGENT CONTEXT COMPRESSION AND MEMORY
Prompt and context compression.
Prompt-compression methods primarily reduce the represen-
tation presented to a downstream model. LLMLingua scores and removes less informative tokens,
while LongLLMLingua introduces query-aware compression for long inputs (Jiang et al., 2023b;
2024). LLMLingua-2 learns a bidirectional token classifier from distilled compression data, Dodo
performs input-dependent contextual compression for decoder-only models, and RECOMP selects
or summarizes retrieved evidence before generation (Pan et al., 2024; Qin et al., 2024; Xu et al.,
2024). These methods mainly optimize the length or information density of a given model input.
A complementary line compresses text into learned latent representations. Gisting encodes reusable
information into special tokens, AutoCompressors recursively construct summary vectors, and ICAE
35


maps long inputs into compact memory slots (Mu et al., 2023; Chevalier et al., 2023; Ge et al.,
2024). Latent representations can achieve high compression density, but generally require a com-
patible downstream model. DMC-5 instead produces a textual Decision View that can be consumed
by an independently deployed specialized agent. More importantly, DMC-5 focuses on repeated
trajectory integration rather than compressing a single static input.
Persistent agent memory.
Agent-memory systems focus on organizing historical information for
later access. MemGPT moves information across memory tiers, HiAgent groups interactions by
subgoal, Generative Agents retrieves experiences and forms higher-level reflections, and Reflexion
stores verbal feedback from previous failures (Packer et al., 2023; Hu et al., 2025; Park et al., 2023;
Shinn et al., 2023). MEMORYLLM maintains an updatable latent memory pool, while RAPTOR or-
ganizes recursive summaries in a retrieval hierarchy (Wang et al., 2024a; Sarthi et al., 2024). These
methods primarily address how historical information is stored, organized, or retrieved. DMC-5
addresses a different problem: how a growing interaction trajectory is repeatedly integrated into the
next decision while controlling both agent-side input and compressor-side cost.
Trajectory-update strategies.
Recent agent context-management methods can be characterized
by their dominant history-update behavior. These categories describe update patterns rather than
mutually exclusive method families.
Selective-update methods retain a recent window or selected trajectory elements while removing or
folding less relevant content (Xiao et al., 2026; Ning et al., 2026; Hu et al., 2025; Ye et al., 2026;
Verma, 2026). They reduce the amount of history processed at each step, but information removed
from the active state may be unavailable when it becomes relevant again.
Recursive-update methods maintain a bounded state by combining the previous compressed memory
with newly generated interactions (Zhou et al., 2026; Yu et al., 2026; Wu et al., 2025). This avoids
rereading the complete trajectory, but repeatedly rewriting the same state can accumulate omissions
or altered details (Kang et al., 2026; Shi et al., 2026). It also changes the prefix presented to the
compressor across rounds, limiting prefix-cache reuse.
Full-history recompression instead reconstructs a compact representation from retained raw context,
preserving access to earlier information but repeatedly processing an expanding history (Li et al.,
2023; Jiang et al., 2024; Xu et al., 2024).
DMC-5 combines full-history access with a different update protocol. Its Append-only Canonical
View preserves raw trajectory records and a stable historical prefix for repeated compressor calls,
while a separate compact Decision View is regenerated for the specialized agent. YAMATO further
restores selected execution-critical records directly from the Canonical View rather than relying on
model rewriting. The design therefore jointly targets history recoverability, compression integrity,
prefix-cache reuse, and agent-side context cost.
6.5.2
CACHE-AWARE LLM INFERENCE
Prefix reuse and serving-side cache organization.
LLM serving systems reduce repeated com-
putation by organizing reusable KV states.
PagedAttention manages KV blocks using virtual-
memory techniques, SGLang organizes shared prefixes in a radix tree, Prompt Cache exposes
reusable prompt modules, and FastTree optimizes attention execution for prefix-sharing request trees
(Kwon et al., 2023; Zheng et al., 2024; Gim et al., 2024; Pan et al., 2025a). These systems optimize
how reusable states are stored or scheduled once shared prefixes exist.
DMC-5 operates at a different layer. It does not modify the serving runtime or directly manipulate
KV tensors. Instead, it structures repeated compressor requests so that the historical portion remains
byte-identical across rounds. The application therefore creates a stable reusable prefix that standard
provider-side prefix caching can exploit.
KV-cache selection and compression.
Another line reduces the memory or bandwidth footprint
of cached attention states. H2O retains recent tokens and attention heavy hitters, Scissorhands ex-
ploits persistent token importance, StreamingLLM combines attention sinks with a recent window,
SnapKV selects head-specific KV positions, QUEST loads query-relevant KV pages, and ThinKV
36


combines reasoning-aware retention with adaptive quantization and eviction (Zhang et al., 2023;
Liu et al., 2023; Xiao et al., 2024; Li et al., 2024; Tang et al., 2024; Ramachandran et al., 2026).
These methods compress or select internal model state. They can reduce inference memory or
attention cost without necessarily reducing the prompt tokens billed to an API endpoint. DMC-
5 instead reduces the textual context repeatedly processed by the acting model while organizing
compressor input for prefix reuse. The two optimization layers are therefore complementary.
Cache reuse across requests and workflows.
CacheGen encodes and transfers KV states across
machines, CacheBlend reuses non-prefix cached chunks with selective recomputation, KVFlow
schedules prefix retention across agent workflows, and LRAgent shares base-model cache states
across LoRA-specialized agents (Liu et al., 2024b; Yao et al., 2025; Pan et al., 2025b; Jeon et al.,
2026). These methods improve how reusable cache states are transferred, scheduled, or shared
across requests.
CAPC is particularly related to DMC-5 because it explicitly studies the conflict between prompt
compression and prefix reuse (Song, 2026). CAPC optimizes compression within an individual
prompt so that shortening the input does not unnecessarily destroy reusable cached prefixes. DMC-
5 addresses the complementary multi-turn problem. It organizes a growing trajectory across repeated
compressor calls so that the historical prefix remains reusable, while the specialized agent receives
a separate Decision View optimized for action generation. Thus, cache management and semantic
compression remain separate mechanisms, but DMC-5 connects them through the trajectory-update
protocol.
6.5.3
MULTI-MODEL COLLABORATION AND AGENT EFFICIENCY
Routing and cascades.
Model routers and cascades reduce inference cost by deciding which
model should handle a request. FrugalGPT learns cascades across model APIs, RouteLLM learns
routing decisions from preference data, Hybrid LLM predicts query difficulty, and AutoMix starts
with a cheaper model and escalates uncertain requests (Chen et al., 2024; Ong et al., 2025; Ding
et al., 2024; Aggarwal et al., 2024). Their central decision is which model should produce the
answer.
DMC-5 does not route requests between interchangeable models. Both models remain active and
have fixed asymmetric roles. The general compressor performs full-history integration, while the
specialized agent performs downstream action generation. This functional decomposition also al-
lows each model to receive a context designed specifically for its role.
Collaborative generation.
Other multi-model systems collaborate by exchanging generated out-
puts. LLM-Blender ranks and fuses candidate responses, Mixture-of-Agents propagates responses
through layered model groups, DUET transfers a compact reasoning signal between models, and
speculative decoding uses a smaller model to draft tokens that a larger model verifies (Jiang et al.,
2023a; Wang et al., 2025; Chen et al., 2026; Leviathan et al., 2023). These methods collaborate over
answers, reasoning signals, or token proposals.
DMC-5 instead collaborates over persistent agent state. The compressor constructs the Decision
View from the evolving trajectory, and the specialized agent acts from that state. The collaboration
therefore persists across interaction turns rather than forming a one-shot generation pipeline.
Agent evaluation and end-to-end efficiency.
Long-horizon agent benchmarks expose interaction
costs that are largely absent from single-turn evaluation. AgentBench spans multiple interactive en-
vironments, AgentBoard reports intermediate progress, WebArena evaluates agents on reproducible
websites, and SWE-bench evaluates repository-level software-engineering workflows (Liu et al.,
2024a; Ma et al., 2024; Zhou et al., 2024; Jimenez et al., 2024). AppWorld and OfficeBench extend
this setting to executable API workflows and office automation (Trivedi et al., 2024; Wang et al.,
2024b).
Final task success alone does not capture the cost of additional model calls, retries, or longer trajec-
tories. Agentless demonstrates that simpler pipelines can outperform more elaborate agents at lower
cost, while broader work on agent evaluation argues for reporting resource consumption together
with task quality (Xia et al., 2025; Kapoor et al., 2025). DMC-5 follows this perspective by jointly
37


measuring task performance, agent-side input, compressor cache reuse, and end-to-end billed cost,
thereby capturing both compression savings and interaction overhead caused by lost state.
