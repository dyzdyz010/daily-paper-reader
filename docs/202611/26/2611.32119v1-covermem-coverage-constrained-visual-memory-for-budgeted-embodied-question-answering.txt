Abstract
Episodic-memory embodied question answering enables
agents to answer questions based on previously recorded
visual observations of the surrounding scenes. However,
growing observation histories, varying observation qual-
ity across viewpoints, and limited computational resources
make it challenging to construct and maintain compact vi-
sual memories while retrieving sufficient evidence for ques-
tion answering. To address these challenges, we introduce
CoverMem, which incorporates three key components: (1)
a coverage-constrained memory construction method that
selects a compact set of informative full frames satisfying
object-quality and representative-scene coverage require-
ments; (2) a coverage-preserving incremental maintenance
strategy that locally reselects only the affected frames to
satisfy updated coverage requirements as observations ar-
rive; and (3) a budgeted complementary frame selection
method that balances question relevance, additional sup-
port for question requirements, and redundancy with se-
lected frames within a fixed budget. Experimental results on
three benchmarks covering diverse environments and ques-
tion types demonstrate that CoverMem improves question-
answering performance under limited visual budgets.

1. Introduction
Vision-language models (VLMs) [16, 19] enable agents
to answer questions about objects, locations, states, and
spatial relations using historical visual observations [26].
Episodic-memory embodied question answering (EM-
EQA) depends both on model reasoning and on the abil-
ity to retain and retrieve useful visual evidence from grow-
ing observation histories, often by compressing observa-
tions and retrieving a few relevant frames per question. Yet
memory construction must select observations before fu-
ture questions are known, whereas answering requires suffi-
cient evidence under a limited source-frame budget. Conse-
quently, excessive compression may discard critical details,
while retaining more observations does not ensure effective
use of the available answering budget.
Existing research addresses this challenge through visual
memory organization and evidence retrieval. The former
organizes observations using view-based memories, object-
or relation-centric structures, and reconstructed 3D repre-
sentations [14, 17, 20, 25, 30, 40], supported by aggrega-
tion and incremental updates [12, 14, 40]. The latter uses
semantic similarity, object- or location-guided search, and
relevance-diversity selection [18, 28, 29], sometimes inter-
leaving retrieval and reasoning [2, 12]. However, retaining
an object’s presence does not ensure a sufficiently informa-
tive observation, since views differ in sharpness, visibility,
and detail. Moreover, high-quality views of individual ob-
jects may lack the layout or contextual information needed
to answer questions. During memory updates, new obser-
vations may show one object more clearly but miss other
objects or scene context in earlier frames, so direct replace-
ment can discard useful information. At question time, rel-
evance or visual diversity alone may yield overlapping ev-
idence for some question aspects, leaving others underrep-
resented despite useful observations remaining in memory.
Figure 1 provides a lounge example for discussing mem-
ory retention and question-time frame selection. For “What
tables are in the lounge’s seating areas?”, high question-
relevance scores may cause retrieval to favor repeated views
of the round high table (frame 340), overlooking the table
in front of the sofa (frame 440). We consider two related
but distinct design questions. Before a question is known,
memory construction must retain informative object obser-
vations together with scene context, and maintenance must
avoid losing useful information as observations arrive. Af-
ter the question is given, evidence selection must choose an
informative set of frames to answer the question accurately
within the available visual input budget.
We introduce COVERMEM, a visual memory frame-
work that combines coverage preservation before ques-
tions are known with complementary evidence selection
within the available input image budget. Before questions
are known, CoverMem constructs a compact memory that
meets object-quality thresholds relative to historical best
observations while covering representative scenes. As new
observations arrive, CoverMem locally reselects affected
frames while keeping unaffected frames fixed, then verifies
that the memory satisfies both constraints. For each ques-
tion, CoverMem evaluates each candidate’s additional sup-
port for question-derived requirements relative to selected
evidence, alongside relevance and visual redundancy.
Experiments on three QA benchmarks with two answer-
ing models evaluate answer quality under limited source-
frame budgets, while component analyses examine memory
quality, maintenance cost, and frame selection.
Our contributions are summarized as follows:
• We propose compact memory construction under object-
quality and representative-scene coverage constraints,
with per-object thresholds relative to historical best ob-
servations and at least one frame per representative scene.
• We enable incremental memory maintenance that locally
reselects affected frames under updated constraints, keeps
unaffected frames fixed, and verifies that the resulting
memory satisfies all updated constraints.
• We develop complementary frame selection under a fixed
image budget, combining question relevance, additional
support for question-derived requirements relative to se-
lected evidence, and visual redundancy.
2. Related work
Embodied question answering. EQA with episodic mem-
ory [26] answers questions by retrieving relevant stored
views [26, 40], while active EQA navigates and explores for
question-relevant evidence [7, 10, 12, 13, 32, 33, 42]. We
maintain full-frame episodic memory and select a limited
number of source frames for answering.
Memory construction and maintenance. Image memo-
ries retain detail and context [18, 40], while object-centric
structures support retrieval and relational reasoning but may
omit appearance and context [12, 14]. Reconstructed 3D ge-
ometry and appearance support spatial reasoning and novel-
view rendering [22, 23, 25, 41]. Methods integrate struc-
tured and visual evidence for question answering [25, 33],
while 3D-Mem updates memory incrementally [40]. Cover-
Mem enforces object-quality and representative-scene cov-
erage and uses local reselection for updates, fixing unaf-
fected frames and verifying both constraints.
Evidence retrieval and selection.
Before answering,
OpenEQA samples frames uniformly [26], while question-
conditioned selection uses semantic similarity and ques-
tion cues [18, 28, 37, 41] or balances relevance and diver-
sity [24]. Others interleave retrieval and reasoning [2, 11,
35, 36], with GraphPad editing scene graphs [1]. To limit
evidence overlap, CoverMem combines relevance, visual
redundancy, and additional requirement support relative to
selected frames under a source-frame budget.

3. Method
From observation history Ht collected by time t, Cover-
Mem constructs reusable visual memory independently of
questions, with active memory Mt ⊆Ht.
To support
this process as new observations accumulate, each retained
frame’s associations with detected object instances and rep-
resentative scene groups enable coverage evaluation and the
identification of related frames during incremental main-
tenance. Given a question q, CoverMem selects at most
K distinct source frames Sq ⊆Mt for answering. We
first define the coverage constraints in Section 3.1, then de-
scribe incremental maintenance through local reselection in
Section 3.2, and finally introduce budgeted complementary
frame selection in Section 3.3.

3.2. Coverage-preserving incremental maintenance
Motivated by dynamic set cover [15], CoverMem maintains
coverage through local reselection when accumulated ob-
servations introduce new objects or scene groups, or pro-
vide clearer views of previously recorded objects.
At update t + 1, let Bt+1 = Ht+1 \ Ht contain frames
collected since the previous update at t. Their object qual-
ities and scene associations extend existing records, updat-
ing historical bests without altering previous scores or asso-
ciations. Improved historical bests raise observed objects’
thresholds and may disqualify earlier object–frame pairs,
while thresholds for absent objects remain unchanged. To
limit reselection cost, Lt+1 includes Bt+1 and frames in
Mt sharing an object or representative scene with any new

3.3. Budgeted complementary frame selection
At answering time, CoverMem selects complementary
frames within the image budget, as illustrated in Figure 3.
Selection combines relevance to the complete question, ad-
ditional support for question-derived visual requirements,
and visual redundancy with the frames already selected.
Question-derived visual requirements. Each question q
is first parsed into a nonempty set of visual requirements
D(q), specifying the objects, attributes, or relations needed
for answering, with the complete question used as a sin-
gle requirement if parsing fails. For each candidate frame
f
∈Mt, relevance rq(f) ∈[0, 1] matches the com-
plete question against global image features [31], while re-
quirement support sq(f, d) ∈[0, 1] combines global image
matching with the strongest regional evidence from object
crops and region descriptions, using global matching alone
when no regions are available (Appendix A.2).

lected frames, let S denote the selected frame set, initial-

4. Experiments
We evaluate CoverMem through five research questions.
Q1: How does CoverMem compare with existing meth-
ods across benchmarks and answering models? (Sec. 4.2)
Q2: How do coverage constraints and observation-quality
scoring affect memory quality and answering performance?
(Sec. 4.3) Q3: Can local maintenance preserve coverage
while reducing maintenance cost?
(Sec. 4.4) Q4: How
do selection components and candidate pools affect answer
quality? (Sec. 4.5) Q5: How does the frame budget affect
answer quality, and what are the costs of memory construc-
tion and question-time API usage? (Sec. 4.6)
4.1. Experimental setup
Datasets.
Experiments use OpenEQA, EXPRESS, and
ScanQA [3, 21, 26]. The fixed OpenEQA subset, denoted
OpenEQA ScanNet, contains 616 questions from 51 obser-
vation histories across 43 scenes. EXPRESS contains 2,044
questions from 777 histories across 174 scenes, while the
ScanQA validation subset contains 4,675 questions from 71
histories and scenes. OpenEQA ScanNet and ScanQA share
the ScanNet [9] visual source but offer complementary eval-
uations through distinct question–answer annotations.
Metrics and protocol. We report LLM-Match for answer
quality, the retained-frame ratio (Ret. Ratio) for memory
size, and the mean number of distinct source frames sup-
plied for answering (Avg.
Frames).
For methods with
explicit frame budgets, input is capped at K = 3 source
frames, while other methods retain their input procedures.
Collage frames are counted before composition. Memory
analyses report the quality-qualified object ratio (Qual. ob-
jects) and relative quality retention (Rel. quality), measur-
ing quality-threshold satisfaction and retained quality rel-
ative to each object’s best historical observation, respec-
tively. Both metrics are computed per history and averaged
equally across histories, with definitions and implementa-
tion details in Appendix A.1.
Baselines. We compare with caption-based scene repre-
sentations (ConceptGraphs Captions [14] and Sparse Voxel
Map Captions [26]), visual memory and retrieval methods
(3D-Mem [40], MemTree3D [18], VLM-Grounder [39],
QCA [29], WFS-SB [6], and ToolMerge [34]), and uniform-
sampling and blind baselines.
All methods in the main
comparison are rerun with Qwen3.8-27B to generate an-
swers, which GPT-6 Luna evaluates under the same proto-
col. CoverMem parses questions with Qwen3.5-35B-A3B
and is also evaluated with Gemini 3.5 Flash-Lite for answer-
ing. Each answering model is paired with uniform sampling
of up to K distinct frames from the original history, while
the blind baseline receives only the question.
The following analyses of coverage constraints, memory
maintenance, frame selection, and computational cost use
the same fixed OpenEQA ScanNet evaluation subset.

the highest LLM-Match scores among the Qwen3.8-27B
configurations on all three benchmarks (Table 1). Its ad-
vantage over caption-based methods supports retaining vi-
sual evidence, while comparisons with visual memory and
retrieval methods highlight the importance of evidence re-
tention and selection. CoverMem addresses these stages
by preserving coverage before questions are known and se-
lecting complementary evidence once a question arrives.
VLM-Grounder uses more frames but scores lower through-
out.
CoverMem retains more frames than 3D-Mem on
OpenEQA ScanNet but fewer on EXPRESS and ScanQA,
while scoring higher on all three. These comparisons sug-
gest that memory size alone does not determine answer
quality. ToolMerge is the strongest competing Qwen3.8-
27B baseline, with CoverMem improving by 4.14, 1.03,
and 6.66 points on OpenEQA ScanNet, EXPRESS, and
ScanQA, respectively. The smaller margin on EXPRESS

5. Conclusion
CoverMem constructs compact full-frame memory for bud-
geted embodied question answering under object-quality
and representative-scene coverage constraints. It preserves
relatively high-quality object observations and scene con-
text before receiving questions. Incremental maintenance
locally reselects affected frames as observations arrive, pre-
serving coverage.
Complementary frame selection com-
bines question relevance, additional requirement support,
and visual redundancy for question-specific evidence un-
der a fixed budget. Experiments on three benchmarks with
two answering models show improved performance using
at most three source frames; component analyses show high
relative quality retention and reduced maintenance time.

Scene groups. A group uses its creating frame’s unit global
feature as a fixed representative. An incoming frame joins
every group with cosine similarity at least η, creating a
group only if none matches. Memberships are fixed and
may overlap. Coverage retains at least one associated frame
per group; the creating frame need not remain. There are no
centroid updates or periodic regrouping.
Construction and local maintenance.
Frames are pro-
cessed in recorded order, one incoming frame per up-
date. Greedy selection first maximizes newly covered con-
straints, then auxiliary retention utility, then source-frame
ID. The utility averages best retained-to-historical ratios
over recorded object and scene entries; scene entries use
unit quality. This bookkeeping differs from the object-only
evaluation in Section A.1.
The local pool includes incoming frames and memory
frames sharing raw object or scene associations with them,
before quality filtering. Other memory frames remain fixed.
Local selection covers every constraint unmet by the fixed
set. Pruning considers locally selected frames only, pre-
ferring smaller utility loss and then source-frame ID, and
preserves complete coverage at every removal. The final
memory is checked against all updated constraints. For the
maintenance comparison, global reselection operates on the
full update pool Mt ∪Bt+1, whereas local maintenance
reselects only affected frames while keeping the remain-
ing memory fixed.
This full-pool baseline differs from
reconstruction over the entire observation history Ht+1.
Equation (3) defines the full-history construction objective,
whereas streaming maintenance operates on Mt ∪Bt+1.
The incremental procedure guarantees coverage feasibility
under updated constraints, rather than global memory-size
optimality over the full history.

A.3. Fair comparison with existing methods
We ensure fair reproduction through fixed evaluation sub-
sets, a shared answering backbone and evaluator, and
preservation of each method’s defining representation and
retrieval mechanism. All compared baselines use their best
verified configurations under the common evaluation proto-
col.
Methods with an explicit frame-budget interface use at
most three source frames. Other methods retain their in-
put procedures and report actual source-frame counts. Cap-
tion methods supply scene text; this does not imply zero
visual preprocessing. VLM-Grounder uses collages whose
constituent source frames determine its visual input count.
The main table’s 100%∗entries denote complete candidate-
pool availability. Uniform sampling takes distinct frames
from the original history without CoverMem filtering or rel-
evance ranking; Blind receives question text only.

A.4. Computational cost, timing, and storage scope
The construction-stage breakdown is reported in main-
paper Table 5.
Construction stages use NVIDIA L20 GPUs, with one
GPU per computational stage; parsing, answering, and eval-
uation use remote APIs. Construction time is cumulative
across the listed stages. Maintenance uses cached inputs
and excludes raw perception and API waiting, with two
runs per history and maintenance rule over 51 histories.
These measurements distinguish reusable preprocessing, in-
cremental maintenance, and question-time operations. Al-
though CoverMem reduces answer-input tokens relative to
uniform sampling, its additional parsing calls make total
question-time API-token usage slightly higher; the token
advantage is instead observed relative to ToolMerge.
The retained-frame ratio measures active source-frame
counts rather than total storage: features, descriptions, as-
sociations, and preprocessing artifacts also occupy space.
Cached maintenance time is not end-to-end query latency,
and cumulative construction time is not simultaneous per-
GPU utilization. History, frame, and region IDs bind caches
to observations; file checksums and fixed configurations
support reuse. Reference answers are excluded from con-
struction and selection.

B.1. Parameter sensitivity and quality design
Unless stated otherwise, supplementary analyses use the
616 OpenEQA ScanNet questions, main answering and
evaluation models, and K = 3. One parameter varies at
a time (Figure B1).
Changing ρ or η rebuilds memory,
whereas changing selection weights or stopping reuses the
default memory. Default hyperparameters were fixed based
on methodological considerations before the main evalua-
tion, without using evaluation-set QA performance for pa-
rameter selection. The same default configuration is applied
across all three benchmarks without benchmark-specific
tuning. The one-factor sensitivity analyses are conducted
post hoc to examine robustness and performance–efficiency
trade-offs, rather than to optimize the default configuration.
Increasing ρ from 0.5 to 0.7 raises answer quality along-
side retention; further increases retain more frames with-
out a corresponding QA improvement. Setting η = 0.85
slightly exceeds the default score but uses more memory.
The defaults balance quality and compactness rather than
maximizing every isolated score.
Moderate α balances question relevance and new sup-
port. Setting α = 1 both changes the relevance scaling and
disables requirement support; therefore, it is not equivalent
to every separately defined support ablation. Setting λ = 0
reproduces the main-paper no-redundancy score of 80.97.

B.2. Statistical significance
We retain the archived main-paper comparisons in Ta-
ble B4. Differences are CoverMem minus the compara-
tor. We use 10,000 paired scene-bootstrap resamples for
95% percentile confidence intervals and 100,000 two-sided
paired permutations that swap method labels jointly within
each physical scene. Holm correction is applied across the
four comparisons. Questions from different histories of the
same scene remain grouped.
All four archived intervals are above zero and adjusted
p-values are at most 0.03, matching the main-paper state-
ment. EXPRESS has a smaller effect than the other bench-
marks. The uncertainty analysis conditions on the existing
answer–judge outputs and sampled scenes; it does not esti-
mate variability from repeated parsing, answering, or eval-
uation API calls. Statistical inference remains tied to these
specific comparisons and resampling units.

E. Limitations
Complex requirements and relational evidence. Cover-
Mem retains reusable visual observations through object-
quality and representative-scene coverage, and allocates a
limited input budget at question time.
For questions in-
volving multiple same-category instances, fine-grained at-
tributes, or complex spatial relations, per-requirement max-
imum support may still inadequately represent joint evi-
dence. Spatial understanding remains the lowest-scoring
category in the main paper, and the remaining failure
cases show that the answering model can produce incorrect
landmark-conditioned answers or substitute queried spa-
tial relations even when relevant visual context is retained.
Finer instance-level support and object-pair relation model-
ing are promising directions.
Upstream information errors.
Construction and selec-
tion use preprocessed object associations, region descrip-
tions, and question requirements. Incorrect associations can
change coverage targets, while omissions in descriptions
or requirements can alter support estimates.
Global and
regional matching provide visual cues at different scales,
and the whole-question fallback handles structurally invalid
parser outputs; semantically incorrect but valid require-
ments require more detailed consistency checking. Incorpo-
rating association and description uncertainty into coverage
and support estimation may reduce error propagation.
Long-term memory growth. Local maintenance reduces
the frames reconsidered per update, but continually arriving
visual content can still increase scene groups and coverage
constraints. Fixed representatives and coverage preserva-
tion prioritize retaining recorded information; they do not
explicitly address stale information or task-dependent for-
getting over long operation. Longer streams motivate hier-
archical memory, stale-information updates, and resource-
constrained coverage management.
Preprocessing and deployment cost. CoverMem’s com-
pact answer inputs depend on detection, association, quality
computation, and feature extraction. The main paper reports
44.29 seconds of construction per history, so deployment
benefit depends on memory reuse and observation-update
frequency. Question-independent processing can be reused
across multiple queries over one history, whereas prepro-
cessing remains a consideration for few-query settings or
rapidly changing observation streams. Incremental feature
updates and on-demand regional processing could further
reduce this cost.
