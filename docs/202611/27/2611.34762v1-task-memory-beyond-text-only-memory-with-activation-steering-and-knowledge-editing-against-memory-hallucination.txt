Abstract 

LLM agents increasingly rely on external memory, yet they still hallucinate about what they remember. Much of this is not a storage error: the correct memory is retrieved and placed in the prompt, but the answer contradicts it, or the memory is applied to the wrong question. We call these use-time memory hallucinations . Across five open models, we find that they come from the conflict between the model’s parametric knowledge and its external memory, and that they take three forms. In memory-ignoring hallucination, the model returns to a stale fact stored in its weights despite the memory, in up to 46% of queries. In memory-misapplying hallucination, it attributes the memory to unrelated neighbour entities, in up to 24% of cases, and in up to 49% once retrieval is combined with weight editing. In version confusion , 53% of answers about revised facts assert the superseded value when both versions remain stored. We propose TASK memory, a memory that is not text alone: each memory combines a Text note with Activation Steering and Knowledge editing, which act inside the model. The three carriers share one in-model address. The text T holds the content. A local, removable knowledge edit E supplies the address through its subject key and supports multi-hop composition through its weight change. A pair of activation-steering vectors S decides, query by query, whether the model should adopt the memory or keep its own answer. S stores no content; it controls how the model uses the text memory, rather than writing new memory into the parameters. On frozen off-the-shelf models, under a pre-registered, test-once protocol, TASK reduces memory-ignoring hallucinations to ≤1.5% in all ten model–dataset cells, and cuts neighbour misuse from 39.2% to 7.5% (+10.8 pp composite on CounterFact). It also improves a 300-memory library over BM25 RAG by 16.4 pp, an advantage that holds at 3,000 memories, resolves fact revisions without fact IDs, and adds 7.5 pp of multi-hop accuracy on MQuAKE. 21 of 23 cross-model comparisons (8B–27B, four families) are significant, and TASK beats three recent context-steering methods in 9 of 10 model–dataset cells. 

# 1 Introduction 

Agents built on large language models (LLMs) keep meeting facts that their weights do not contain, or contain in an outdated form: a person changes jobs, a user replaces a device, an API is deprecated. The dominant way to remember such facts is text memory . The fact is written as a note, stored in a memory store, and retrieved into the prompt when a related question arrives [8, 22, 36, 37, 54, 62]. Agents with memory still hallucinate. HaluMem [6] shows that memory systems introduce hallucinations when they extract and update memories, and that these errors carry into question answering. That diagnosis locates the error in what is stored . Here we study the complementary failure: the stored memory is correct and is even in the prompt, yet the answer contradicts it, or the memory is applied where it does not belong. We call these use-time memory hallucinations . They are a form of context-conflicting (unfaithful) hallucination [16, 57] in which the conflicting context is the agent’s own memory. Use-time memory hallucinations arise because the memory is not read by a blank slate. The model already holds parametric knowledge about the same entities, and the note and the weights compete inside every forward pass. Such knowledge conflicts are known from question answering over retrieved passages [28, 52, 53]. We measure them in the agent-memory setting, on five open models (Qwen3-8B/14B, Llama-3.1-8B, Phi-4, Gemma-3-27B) and three memory settings, and find three types (Figure 2). The first, memory-ignoring hallucination (Type I), is parametric override. When we split queries by whether the no-memory model still states the pre-update fact, text memory turns out to be adopted 14.8–28.6 pp less often on queries whose stale fact is stored in the weights, in five of ten model–dataset cells (Figure 2a). Because Types I and II pull in opposite directions, no single global remedy fixes both, and each existing family of methods addresses at most one of them. Better retrieval decides which note enters the prompt, but not how the model weighs it against its weights. Context-faithfulness methods, such as contrastive decoding [42] and global steering directions [2, 29, 59], push the model towards the context uniformly and thereby trade Type I for Type II; in our experiments an ungated evidence direction raises misuse and lowers the composite score below that of text memory alone (0.780 vs. 0.811). Knowledge editing [11, 32, 33] writes the fact into the weights, which amplifies Type II when it is combined with text memory (Figure 2b), and a joint closed-form patch over accumulating versions collapses (Section 5.2). Memory-native models such as MemT-1.0 [31] go further and move the memory content itself into the model: MemT-1.0 trains native memory blocks on 34B tokens, writes the interaction history into a dynamic memory state, and reads it back through a parallel memory attention. This changes where the memory lives, but not who arbitrates when the stored item and the weights disagree. Its memory modules are trained to imitate the backbone given the full textual history, so they inherit the backbone’s way of using context, and in their own evaluation conflicts with real-world knowledge are handled by an instruction to answer “from the knowledge pool . . . rather than the real facts in real world”. We take a different view: using a memory is a separate, controllable decision, and use-time memory hallucination is a failure of that decision. For each query the model must decide whether a note should override what it already believes. That decision is made inside the network, so it can be read out and steered there. memory, which goes beyond text-only memory by coupling each Text note with Activation Steering and Knowledge editing, two carriers that act inside the model and share one in-model address (Figures 1 and 3). The text T carries the content, a versioned note that tells the model what the fact is. The activation-steering carrier S carries the use policy: a pair of residual-stream vectors, of which v+ makes the model adopt the note when the address fires, countering Type I, and v− makes it keep its parametric answer when the note is present but the query concerns something else, countering Type II. The knowledge-editing carrier E is a closed-form, removable MLP edit keyed on the subject’s internal representation [13, 32]. Its key doubles as the memory’s address, so that one partial forward pass tells whether a query is about this memory, and its weight change supports multi-hop composition. At read time the address gates all three carriers at once, deciding which notes are shown, which patches are loaded and which steering direction is applied. Relevance is thus judged in one place, the model’s own representation, rather than separately by a retriever, an editor and a steering rule. When a fact is revised, the old version’s text, patch and vectors are retired together, which removes Type III. The steering carrier is deliberately not a memory store. Without the text note it answers 1.7% of CounterFact queries, the same as the unmodified model. What it changes is the arbitration: memory-ignoring hallucinations fall to at most 1.5% in all ten model–dataset cells, and neighbour misuse falls from 39.2% to 7.5% (Qwen3-8B, CounterFact). This is the key difference from parametric-memory approaches such as knowledge editing, parametric RAG [43] and MemT-1.0, which put new content into weights or a trained memory state. TASK keeps content in text, where it can be inspected, versioned and deleted, and writes into the model only a bidirectional controller that applies to a single memory and can be removed. We evaluate TASK memory on five frozen models from four families (8B–27B) and six benchmarks under a pre-registered protocol. On single facts it improves over text memory by 10.8 pp on CounterFact and 5.7 pp on zsRE (Qwen3-8B, composite of adoption and locality). For an agent holding 300 memories it improves over BM25 RAG by 16.4 pp and 16.2 pp, mainly by removing Type II hallucinations caused by retrieved distractors, and the advantage holds at 3,000 memories (0.926 for address-verified T +S vs. 0.731). Address-assisted supersession, which needs no fact IDs, raises accuracy on revised facts by 48.7–54.7 pp, and on MQuAKE the weight carrier adds 7.5 pp of multi-hop accuracy. Across models, 21 of 23 comparisons are significant, and TASK beats knowledge-selection steering [29], ContextFocus [2] and CAST [20] in 9 of 10 model–dataset cells. The experiments also reveal a clear division of labour among the carriers: the weight change of E matters for composition but not for single facts, and training the steering vectors on the edited model brings no reliable gain over training them on the base model. 

Contributions. First, we define use-time memory hallucination and its three types, and show on five models that memory-ignoring and memory-misapplying hallucinations arise from the two-way conflict between parametric knowledge and external memory, with weight edits added to retrieval amplifying the latter (Figure 2). Second, we 3propose TASK memory, which combines text, activation steering and knowledge editing in one memory object: text carries the content, a removable edit provides an in-model address and compositional recall, and a paired adopt/restrain steering policy arbitrates each query, with the address gating prompt, weights and activations together across a write, read and revision lifecycle that detects revisions without fact IDs. Third, we provide pre-registered evidence on five models against twelve published baselines, together with an analysis showing that S learns a shared adopt/restrain direction plus a memory-specific residual that is effective only behind the address gate. 

# 2 Related Work 

Hallucination and memory hallucination. Hallucination surveys separate output that conflicts with world facts from output that conflicts with the input or context the model was given [16, 17, 57]. Agent memory adds a new source of context, so it adds new ways to hallucinate. HaluMem [6] evaluates memory systems operation by operation (extraction, updating, question answering). It finds that hallucinations are introduced and accumulate when memories are extracted and updated, and then propagate into answers. Its remedy is to store the right memories. We study what remains when the stored memory is right: the model can still ignore it, misapply it to another entity, or answer from a superseded version. These use-time memory hallucinations are context-conflicting hallucinations caused by the conflict between parametric knowledge and the agent’s own memory. They cannot be fixed by better storage alone, which is why TASK intervenes in how the model reads a memory. 

Text memory for agents. Most agent memories store natural-language records and retrieve them into the prompt. Examples are retrieval-augmented generation [22], operating-system-style paging [36], reflective memory streams [37], forgetting-curve stores [62], and production systems that extract, consolidate and link memories [8, 54]. Long-conversation benchmarks such as LoCoMo [30] and LongMemEval [51] measure whether the right memory is retrieved and answered from. These systems optimise what reaches the context . TASK is complementary: it keeps a text store and controls how the model uses what reaches the context. On LoCoMo we compare against Mem0 and A-Mem with the same answering model. 

Parametric memory: editing, parametric RAG and memory-native models. Knowledge editing writes facts into weights. Locate-then-edit methods treat MLPs as key–value stores [13] and insert closed-form updates: ROME [32], MEMIT [33], and AlphaEdit [11] with null-space constraints. Memory-based editors keep side memories with scope classifiers or codebooks: SERAC [35], GRACE [15], WISE [47], Larimar [9]. IKE [60] edits in context, and RECIPE [7], DeCK [3] and LightEdit [19] combine retrieval with prompts or decoding that suppress the old fact. Sequential editing remains fragile [26, 56]. Our E follows the ROME lineage; what differs is how TASK uses it. The edit’s subject key also serves as the address that gates text and steering. Each memory keeps its own patch, loaded only when its address fires, and a patch is retired when its memory is revised. Parametric RAG turns documents into LoRA weights generated by a hypernetwork and combines them with text RAG [43, 44]. This resembles our T +E,but without per-query arbitration. Memory-native models make memory part of the architecture. MemoryLLM [50] keeps a self-updating memory pool inside the transformer, and Temp-LoRA [49] trains a temporary adapter on the history. MemT-1.0 [31] is the most recent and most scaled example. It adds native memory blocks to selected layers. A dynamic per-trajectory memory state is written token by token with a gated delta rule and read through a parallel memory attention, and Mixture-of-Storage scales its capacity. The memory modules are trained with the backbone frozen, on 34B tokens of continued pre-training and post-training, by distilling the backbone that sees the full textual history. After writing, the history text is no longer needed in context. MemT-1.0 and TASK both bring memory into the model’s computation, but they put different things there (Table 1). MemT-1.0 internalises the content of the history in a trained, fixed-size state; it is evaluated on recall and use of that history, and its training target is the backbone’s own full-context behaviour. TASK leaves the content in an inspectable text store and writes into the model only a per-memory use policy , an address and an adopt/restrain steering pair, which act on a frozen, off-the-shelf model without any pre-training. The two are therefore orthogonal. TASK targets the arbitration failures of Figure 2, which full-context imitation does not address by construction. A memory-native model could also expose its memory readout to the same kind of address-gated steering.

Existing remedies push the model towards the context, through contrastive decoding (CAD) [42], attention-head or SAE-feature interventions [23, 59], adaptive gating of parametric participation [25], or global steering directions that favour the context, such as ContextFocus [2] and the knowledge-selection direction (KSD) of Lou et al. [29], a signed diff-of-means direction that transfers across conflict types and models. These methods treat faithfulness as a global property of a prompt. In an agent memory the same note is relevant to some queries and irrelevant to others, so a global push turns parametric override into memory override. TASK makes the decision per memory and per query: the address selects between an adopt and a restrain vector. We compare directly against CAD, KSD, ContextFocus and CAST on five models. 

Activation steering, and steering as memory. Adding vectors to the residual stream steers behaviour: ActAdd [46], CAA [39], ITI [24], representation engineering [64]. CAST [20] applies a behaviour vector only when the hidden state is similar to a condition vector. We share the idea of gating, but our gate is a per-memory address taken from the edit key. Our steered behaviour is evidence use, not refusal. Several works store knowledge as activations or representation edits: SAKE [41], REACT [61], MEGA [4], RILKE [27]. Neural Procedural Memory [58] stores agent skills as retrieved steering vectors and finds them complementary to textual workflow memory. Jumle [18] show that facts barely survive when stored as steering alone (at most 15% clean use, against 96–98% in context). This negative result is consistent with our design choice: TASK never asks S to carry content ( S alone: 1.7%), only to control how text content is used. Chavira Juárez et al. [5] argue conceptually that memory agents should divide labour among retrieval, steering and weight editing. TASK gives one concrete instance of that division, with experiments.

## 3.3 Reading: one address, three gates 

Given a query x, BM25 [40] first returns candidates: the top two for structured memories, and the union of the BM25 and semantic top five for dialogue facts. One partial forward pass to layer ℓE then yields rm(x) for every candidate. Only memories with gm = 1 are shown as text and have their own single-memory patches loaded (summed; “gated E”), and their steering is applied by Equation (3). A single context manager owns all patch and steering hooks and removes them after generation. Relevance is thus decided once, by the model’s own representation, so the three interventions cannot contradict each other: a note is never shown without its patch, and an adopt vector is never applied to an unrelated query. 

Read rule for composition. v− assumes that a query can be attributed to individual memories. In multi-hop questions the bridge entity does not appear in the question, so v− would suppress evidence that is needed. For multi-hop composition we therefore apply only v+, and paired steering elsewhere. 

## 3.4 Revision and supersession 

When a new observation arrives, BM25 retrieves the top two active records, the observation’s address response is checked against them, and the agent’s own frozen model judges with a fixed prompt whether the observation gives a new value for the same entity and attribute ( UPDATE ) or states a different fact ( DIFFERENT ). On UPDATE , the old record is superseded, and its E and S leave the active set together; no fact IDs, relation IDs or version numbers are involved. Retiring the old E is necessary because two versions have almost identical keys, and a joint closed-form solve over both collapses. Retiring the old S proves equally necessary, since otherwise the adopt vectors of both versions fire and each pushes its own object (Section 5.2). 

# 4 Experimental Setup 

Models. We use five frozen open models from four families: Qwen3-8B (primary) [38], Llama-3.1-8B-Instruct [14], Qwen3-14B, Phi-4 (14B) [1] and Gemma-3-27B [12], all run in BF16 with greedy decoding (non-thinking mode for Qwen3). For each model, ℓE is chosen on training-split worlds by one fixed rule, edit-only paraphrase accuracy over three candidate layers, which gives layers 6/4/9/7/11 in the order above; ℓS is set by relative depth (14/13/16/16/25). All other hyperparameters were chosen once on Qwen3-8B development data and reused unchanged for every model. 7Benchmarks and protocols. The protocols vary along two axes: how the memory arrives (provided, retrieved from a library, or accumulated with revisions) and what form the fact takes (structured or free-form). The provided-evidence 

protocol isolates the use of a memory: CounterFact [32] and zsRE [21] each contribute 300 test worlds with one memory per world, and the note is in the context for both related and unrelated queries. In the library protocol, one agent holds all memories of the split (300, and 1k and 3k with training-split distractors) and must retrieve before reading. The continual-revision protocol inserts 100 facts and then revises 50 of them. Multi-hop composition is evaluated on MQuAKE-CF-3k [63] (200 cases, 600 questions), where only the edited base facts are written. Free-form dialogue memory is evaluated on LoCoMo [30], split by conversation into 2 development and 8 test conversations with 1,230 test questions of categories 1–4. Results on LongMemEval with oracle histories [51] and on AppWorld [45] with a local ReAct agent [55] are in Section D. 

Metrics. Adoption is paraphrase and canonical accuracy on queries about the memory. Restraint is measured by locality preserved, i.e. one minus the damage rate on neighbour queries that the no-memory model answers correctly, and by misuse , the rate at which a neighbour answer asserts the memory’s object. These quantities map directly onto the hallucination types of Section 3. The Type I rate is reversion , the fraction of answers that assert the pre-update object, reported on queries whose stale fact is stored in the weights; the Type II rate is misuse; and the Type III rate is the stale-version rate , the fraction of answers about a revised fact that assert the superseded value. The composite is the harmonic mean of paraphrase accuracy, canonical accuracy and locality preserved, so it is low whenever one of the three is low. Answers are classified by a normalised assertion matcher that ignores negated mentions. On LoCoMo we report LLM-judge accuracy under three judges (Qwen3-8B, Qwen3-14B and GLM-5.3) together with input tokens. 

Baselines. Six context-use methods receive the same note as TASK: IKE [60], CAD [42], CAA [39], KSD [29], ContextFocus [2] and CAST [20], with strengths tuned once on Qwen3-8B development data. The parametric carriers are ROME, MEMIT, AlphaEdit and WISE in their original EasyEdit implementations [48]. For dialogue we compare with Mem0 [8] and A-Mem [54], both ingesting every turn with the same local model, and with the full conversation in context. Control conditions replace S with norm-matched random vectors, vectors at the wrong layer, another memory’s vectors, or an ungated global evidence vector. 

Protocol and statistics. Train/dev/test splits are hashed by subject (or by conversation) and frozen before any model output. Hyperparameters and read rules were selected on train or dev data, the primary test comparisons were registered before their outputs existed, and each test set was run once. Confidence intervals are 95% paired-bootstrap intervals over worlds (or conversations, or subjects in clustered settings) with 2,000 resamples [10]; “significant” ( ∗) means that the interval excludes 0. 

# 5 Results 

We organise the results around three questions. RQ1 asks whether, once a correct memory is in context, TASK prevents memory-ignoring (Type I) and memory-misapplying (Type II) hallucinations. RQ2 asks whether, when one agent holds many memories that keep changing, the shared address reads the right ones and avoids version confusion (Type III). RQ3 asks whether updated facts can be composed with what the model already knows. Table 2 lists the pre-registered test comparisons on the primary model.

## 5.4 Generality across models and against baselines 

Across models. The same frozen protocol holds on all five models (Table 6, top): 21 of 23 cross-model comparisons are significantly positive. The gain is largest where the model resists its context most. Llama-3.1-8B adopts text memory poorly (CF composite 0.518) and gains +43.0 pp. Qwen3-14B already follows context well (0.923) and gains +2.2 pp. This matches the conflict analysis: models with larger parametric override (Figure 2a) leave more room for arbitration. 

Against context-use baselines. With the same note in context, TASK significantly beats the three steering methods closest to it (KSD, ContextFocus, CAST) in 9 of 10 model–dataset cells, and CAA in 9 of 10 (Table 6, bottom). The exception is Gemma-3-27B on zsRE. There S raises paraphrase accuracy (0.907 →0.967) but increases locality damage, and no difference to the steering baselines is significant. IKE, which adds demonstrations and is especially strong on zsRE’s question format, ties with TASK or wins on 14B+ models for zsRE. On CounterFact, IKE’s demonstrations cause heavy misuse, and TASK leads by 2.7–39.4 pp. 

## 5.5 Free-form dialogue memory 

On LoCoMo (Table 7), facts are free-form and the subject key does not apply, so TASK uses the semantic address and 

T +S, without E. At an equal input budget of about 300 tokens, TASK improves over BM25 retrieval, over the same retrieval without S (significant under two of three judges), over Mem0, and over token-matched A-Mem (significant under all three judges). The absolute level stays modest: A-Mem with 4–23 × more tokens and the full conversation (65 ×) remain clearly more accurate. On LongMemEval the literal subject key gates out relevant facts and E/S give no gain (Section D), which is what motivated the semantic address. 

# 6 Discussion and Limitations 

What each carrier contributes. The evidence assigns each carrier a distinct role. Text carries the content: without it, neither S nor single-fact accuracy survives. Steering carries the use policy and is the most consistent source of gains, resolving both directions of the conflict on all five models. The address taken from E’s key controls which memories are read; it turns retrieval into precise reading for libraries of up to 3,000 memories and is what allows weight patches to scale. Memory hallucination beyond storage. Our results suggest that memory approaches should be judged on use as well as on storage : whether a stored item is adopted where it applies and ignored where it does not. Storage-stage benchmarks such as HaluMem [6] and our use-time analysis cover complementary halves of memory hallucination. A memory system can store perfectly and still hallucinate at read time. Writing content into weights (editing) or into a trained state (MemT-1.0) changes where the memory lives. It does not by itself arbitrate between the memory and the model’s prior knowledge. Combined with retrieval, editing even amplifies memory override. An address-gated use policy addresses this arbitration directly; because it acts on a frozen model through one hook and one partial forward pass, it can be combined with either kind of storage. 

Limitations. The gains of TASK memory shrink when a model already follows its context well (Qwen3-14B CounterFact: +2.2 pp), and on Gemma-3-27B zsRE T +S is not better than T (−4.61 pp [-10.25, 0.01] ), while IKE is significantly better. On dialogue memory the gains are small and TASK stays far below full-context reading and token-rich A-Mem; the literal subject key fails on free-form questions (LongMemEval), and the semantic address fixes this only in part. Revision depends on supersession, without which S can amplify version conflicts, and the automatic judge is imperfect: it misses 14% of true updates on Qwen3-8B, and in libraries with many facts per subject the Llama-3.1-8B judge wrongly supersedes 34% of memories, while about 10% of sibling memories remain confused under every carrier. Writing a memory costs about 25 s of steering training and 4 s of editing on one GPU, and our libraries reach 3,000 memories rather than millions; the decomposition in Section 5.1 suggests that a shared direction behind per-memory gates could remove most of this cost. Finally, CounterFact, zsRE and MQuAKE consist of synthetic counterfactual updates, our answer classifier and LLM judges are not the official scorers, and on AppWorld the local 8B agent almost never completes tasks, with S improving only the partial test-pass rate (+2.2 pp, not significant). 

Broader impact. Making agents adopt stored notes more reliably also makes them adopt wrong notes more reliably. TASK should sit behind a writer that verifies sources. Its per-memory, versioned and removable design makes such auditing and deletion straightforward. 

# 7 Conclusion 

Text memory tells a model what a fact is, but not whether the fact should override what the model already believes. We showed that this gap produces use-time memory hallucinations, even when the stored memory is correct. The model ignores the memory in favour of stale weights, misapplies it to other entities, or answers from a superseded version. 13 The first two come from the conflict between parametric knowledge and external memory, which runs in both directions on every model we tested. TASK memory addresses it with a per-memory use policy behind an in-model address: paired adopt/restrain steering vectors, gated by the key of a removable knowledge edit, with content kept in text. Under a pre-registered protocol on five frozen models, this policy resolves both conflict directions and makes memory libraries precise up to 3,000 memories; the edit carrier adds compositional recall. By making each memory more than text, a 

Text note combined with Activation Steering and Knowledge editing, each in the role it is good at, we can reduce memory hallucinations without retraining the model. We hope these results encourage treating memory use , and not only memory storage , as a first-class target for reducing hallucination in LLM agents.

# B Implementation details 

Writer. The writer sees only the update observation (subject, relation prompt and new object for CounterFact/zsRE; the edited base facts for MQuAKE; the dialogue sessions for LoCoMo and LongMemEval). It produces: • T records; • four relation templates mined from the training split; • hard negatives: same relation, other training-split subjects; • generic Wikitext prefixes. 18 Labels enter only after predictions are frozen. Three writer seeds, which resample templates, negatives and prefixes, give consistent S gains on development data (Table 15). 

E. Value optimisation runs 25 Adam steps at lr 0.5 with early stopping at NLL 0.05, plus KL and norm constraints. The covariance comes from about 7 × 10 5 Wikitext tokens at the edit layer. Patches are stored as low-rank factors. The edit layer was scanned on training-split smoke worlds. For Qwen3-8B, edit-only paraphrase accuracy was 12/16 at L4, 15/16 at L6 and 12/16 at L8. The other models used the same rule over three candidate layers. Budget controls (more steps, higher rank) gave no gain on dev. An AlphaEdit-style null-space projection gave identical edits. 

S. 40 Adam steps at lr 0.02 × rms ℓS , zero initialisation, plus a norm penalty. A larger rate (0.05) hurt locality on dev. A residual-weighted variant (fixed a priori) gave identical results. 

Intervention checks. Every intervention changes real activations or effective weights; none is a prompt substitution. In FP32, generation with KV cache under interventions matches full-prefix recomputation (maximum logit difference 

8 × 10 −5), unloading restores weights bit-exactly, and base parameters receive no gradient during S training. 28 unit tests on a miniature Qwen3 with the real tokenizer cover the gradients of S and E, causal masking of decision positions, loading and unloading, and hook cleanup.

# E Data boundary and reproducibility 

• Splits. Splits are hashed by subject (CounterFact, zsRE), by first edited subject (MQuAKE) or by conversation (LoCoMo). Manifests were frozen before any output. 21 • Writer inputs. Writers never read test questions, answers, multi-hop targets or test-time scores. • Pre-registration. Each test set was run once. Primary comparisons, decision rules and their dates were registered in a decision log before the corresponding outputs existed. • Denominators. Failures and runtime errors stay in the denominators. Infrastructure interruptions were resumed, never rerun because of their results. • Regeneration. All tables and the data figures are regenerated from raw predictions and metrics files by scripts. • External API. Only the GLM-5.3 judge, used to re-judge LoCoMo answers, called an external API. 22
