ABSTRACT
LLM agents commonly use the full interaction history as a proxy for state, retain-
ing all past observations and actions regardless of whether they remain relevant.
We instead ask what information an agent actually needs to carry forward. We
define agent state as a compact abstraction of interaction history that preserves
the competence of a fixed reference agent, with the minimal such abstraction as
the ideal. Because matching the reference agent’s behavior is unnecessarily re-
strictive and difficult for black-box policies, we define sufficiency through task
performance rather than behavior matching. We represent state abstractions as
deterministic recursive programs and search over them using an LLM-guided ge-
netic algorithm. Across ALFWorld and ScienceWorld, the learned abstractions
preserve near-reference task success while reducing mean policy input by up to
71% and 57%, respectively. The resulting programs are directly inspectable, pro-
viding an explicit account of what information is retained, updated, and discarded
during interaction.

INTRODUCTION
LLM agents typically select an action by conditioning on the full interaction history. Observations,
actions, and intermediate reasoning are appended to a growing context and passed back to the model
at every step (Yao et al., 2023). This is a natural default because the history is sufficient by construc-
tion: no information from the interaction is intentionally discarded. But it retains all information
indiscriminately, regardless of whether it remains relevant. As context grows, it accumulates ob-
servations and action outcomes whose long-term value may be much smaller than the space they
occupy. The model must repeatedly recover the useful information from an increasingly large his-
tory, which can eventually exceed the model’s finite context window. Most existing approaches treat
this as a context-management problem. They summarize the history, retrieve selected memories,
or compress the context once it becomes too large (Jiang et al., 2023; Wu et al., 2021; Kang et al.,
2025).
We take a different view. The more fundamental question is not how to shorten the context, but
what information the agent actually needs to carry forward. The notion of state is foundational
to sequential decision making, from Markov decision processes and partially observable MDPs
(Bellman, 1957; Sondik, 1971) to reinforcement learning (Sutton, 1988; Watkins & Dayan, 1992;
Williams, 1992). Sequential decision making provides a natural framing for this question through
state abstraction (Li et al., 2006): rather than assuming the full interaction history is the agent’s state,
we ask whether a smaller representation can preserve the competence of the same agent on the task.
A natural answer is to define agent state in terms of what the agent needs to remain competent. We
call a compact abstraction of the interaction history an agent state if the reference agent preserves
its performance when conditioned on that abstraction rather than the full history; the ideal agent
state is the minimal such abstraction. This separates two requirements. Sufficiency asks whether the
abstraction preserves competence, while minimality asks how much information can be removed
without sacrificing it. Because many tasks admit multiple successful trajectories, we measure suffi-
ciency through preserved task performance rather than exact behavioral matching. The full history
trivially satisfies sufficiency, so the problem becomes meaningful only when both sufficiency and

Our contributions are threefold:
• Agent state abstraction. We formulate agent state for black-box LLM agents as a compact
abstraction of interaction history that preserves the competence of a fixed reference agent. This
connects the agentic setting to classical state abstraction (Li et al., 2006), with sufficiency defined
through task performance.
• Programmatic state discovery. We represent agent states as deterministic recursive programs
and develop an LLM-guided genetic search procedure (Romera-Paredes et al., 2024; Guo et al.,
2024) that discovers such abstractions from interaction alone.
• Empirical evaluation and inspectability. We evaluate the approach on ALFWorld (Shridhar
et al., 2021) and ScienceWorld (Wang et al., 2022). Across ten task families, the learned abstrac-
tions reduce mean policy input by up to 71% in ALFWorld and 57% in ScienceWorld. Averaged
over three evaluation runs, we detect no systematic difference in success from full history (+1.7
pp, 95% CI [−1.8, +5.3]), and the agent using the learned state abstraction has the lowest run-
to-run variance of the evaluated methods (Appendix D.1). Because each state is an executable
program, it also provides an inspectable description of the information carried forward during
interaction.

BACKGROUND AND RELATED WORK
2.1
LLM AGENTS AND THE CONTEXT-AS-STATE CONVENTION
LLM agents typically choose each action by conditioning on the accumulated interaction history.
ReAct (Yao et al., 2023) interleaves reasoning traces with actions and appends both to a grow-
ing context, and subsequent agent scaffolds, including reflection over failed attempts (Shinn et al.,
2023), planner–executor decompositions (Prasad et al., 2024), and skill libraries (Wang et al., 2023),
elaborate the control flow while retaining this convention. In effect, the context serves as the agent’s
state.
Retaining the full history is sufficient by construction, since no information from the interaction is
intentionally discarded. It is also maximally non-selective. As an episode progresses, the context
accumulates observations and action outcomes whose durable information may be much smaller
than their textual representation, forcing the model to repeatedly recover the relevant information
from an increasingly large history.
Existing agent-memory systems impose structure on this history through external storage, retrieval,
or hand-designed memory components. MemGPT (Packer et al., 2023) manages a bounded working
context against external storage, while generative agents maintain a retrievable memory stream with
recency and relevance scoring (Park et al., 2023). These approaches improve how information is
stored or accessed, but the structure and contents of the state are still largely specified by the system
designer. Other work learns or prompts explicit memory and state for agents. MCMA (Liang et al.,
2026) trains a memory copilot to abstract past trajectories into reusable cross-episode procedural
memory. StateAct (Rozanov & Rei, 2025) prompts the acting model to describe its own goal and
state at every step, following hand-annotated few-shot examples; this self-reported state is neither
learned nor tested for sufficiency as a replacement for the interaction history. Our focus is instead
on identifying what information the agent actually needs to carry forward.
2.2
STATE ABSTRACTION IN SEQUENTIAL DECISION MAKING
A central question in sequential decision making is what information from the past must be retained
for future control. In partially observable environments, the full interaction history is always a valid
information state, but it grows with the horizon and may contain substantial redundancy. Classi-
cal work therefore seeks smaller representations that preserve only the distinctions that matter for
decision making.

One line of work formalizes this through state abstraction. Li et al. (2006) distinguish several ab-
straction schemes according to what they preserve. Model-irrelevance abstractions preserve im-
mediate rewards and transition dynamics over abstract states. Q-irrelevance abstractions preserve
action values, while π-irrelevance abstractions preserve the action selected by a policy. These form
increasingly weaker notions of equivalence, allowing progressively coarser abstractions as fewer
properties of the original state space must be retained.
Bisimulation provides a closely related notion of state equivalence. Ferns et al. (2012) characterize
states as similar when they induce similar immediate rewards and transition behavior over equivalent
future states, and extend this binary relation to a quantitative metric. In this sense, bisimulation is
closely aligned with model-preserving abstractions, but provides a recursive notion of behavioral
similarity between states. Abel et al. (2016) further study approximate abstractions, showing how
violations of exact abstraction conditions translate into bounded degradation in control performance.
Policy-relative notions are especially relevant to our setting. Castro (2020) introduces a policy-
dependent variant of bisimulation in which state similarity is defined relative to a fixed behavior
policy. This weakens the requirement that the abstraction preserve distinctions that are irrelevant
under the particular policy being executed. Our setting is similarly policy-relative: the LLM agent is
fixed, and we seek an abstraction sufficient for that specific agent rather than for all possible policies.
However, unlike policy-relative bisimulation, we do not assume access to transition dynamics or
state-level reward structure, and we do not require the abstracted process to preserve the environment
model.
A related line of work studies compact representations of history under partial observability. Littman
& Sutton (2001) represent state through predictions of future observable events rather than latent
environment variables, while Singh et al. (2003) develop methods for learning such predictive sum-
maries from experience. Subramanian et al. (2022) study recursively updateable summaries of
history that approximately preserve the information required for planning and control. Our state
representation shares this recursive structure, but our sufficiency criterion is defined relative to the
realized performance of a fixed black-box agent rather than preservation of model-based planning
quantities.
These approaches differ in what an abstraction is required to preserve, including transition dynamics,
rewards, values, policies, or predictive distributions. Our setting differs in both what is available and
what is fixed. The environment and LLM policy are treated as black boxes, the policy is not relearned
after abstraction, and the abstraction itself is the object of optimization. We therefore seek a policy-
relative notion of sufficiency that can be evaluated directly from interaction, based on whether the
fixed agent preserves its task performance under the abstract state.
2.3
CONTEXT COMPRESSION FOR AGENTS
A parallel line of work reduces the amount of context presented to language models. Prompt-
compression methods such as LLMLingua (Jiang et al., 2023) remove low-importance tokens under
a compression budget, while learned compressors such as Chevalier et al. (2023) encode long con-
texts into compact summary vectors that are provided to the model as soft prompts. Recursive
summarization methods (Wu et al., 2021) have also been used to process inputs beyond the model’s
context window by hierarchically summarizing segments and their summaries. More directly re-
lated to our setting, ACON (Kang et al., 2025) learns natural-language compression guidelines from
successful and failed agent trajectories and distills the resulting compressor into a smaller model.
These approaches primarily treat history reduction as a compression or memory-management prob-
lem: given a context budget or compression mechanism, the goal is to retain enough information
for the agent to continue performing well. Our perspective is different. We treat the problem as one
of state identification: rather than asking how much of the history can be compressed, we ask what
information must be carried forward for a fixed agent to preserve its competence. Context reduction
is therefore a consequence of identifying a sufficient state, rather than the primary objective.
A second distinction is when abstraction is applied. Many context-compression methods operate
only after the accumulated history reaches a budget or threshold, compressing an already-grown
context. In our setting, the agent operates on the abstract state from the first step onward: each
new observation is incorporated into the recursively maintained state, and the discarded history is

never carried forward. The agent therefore acts throughout the episode in the learned state space
rather than switching from full-history conditioning to compression once the context becomes large.
Because the state update is a deterministic program, this recurrence also requires no additional
language-model inference at deployment.
2.4
PROGRAM SEARCH WITH LANGUAGE MODELS
Recent work has used language models as proposal operators for search over discrete objects. Fun-
Search (Romera-Paredes et al., 2024) evolves executable programs by repeatedly generating candi-
date modifications and evaluating them with an external objective. EvoPrompt (Guo et al., 2024)
similarly combines evolutionary search with LLM-generated mutations and recombinations, but
over prompt space rather than programs. Other methods, including TextGrad (Yuksekgonul et al.,
2024) and GEPA (Agrawal et al., 2026), use natural-language feedback to iteratively revise prompts
or other textual artifacts based on execution outcomes. ALMA (Xiong et al., 2026) applies LLM-
guided search to memory designs for continual learning, selecting programs that store and retrieve
experience across a stream of tasks. Our search instead targets a policy-relative, within-episode state
that can replace the raw interaction history while preserving a fixed agent’s task success.
Our optimization procedure follows this general pattern but applies it to a different object: a re-
cursive state-update program embedded inside an agent-environment interaction loop. Candidate
abstractions are evaluated through the downstream return of the fixed agent, and LLM-based mu-
tation, crossover, and reflection are used to search over programs that preserve performance while
reducing state complexity.

METHOD
We consider a fixed black-box LLM agent π interacting with an environment E. At time step t, the
agent has received observations o1:t and produced actions a1:t−1. Standard LLM agents condition
on the full interaction history,
ct = (o1, a1, . . . , ot−1, at−1, ot),
which is sufficient by construction but becomes increasingly redundant as the interaction proceeds.
Rather than treating ct as the agent’s state, we seek a compact state st that preserves the agent’s
task performance. The policy π remains fixed throughout; the only learned object is an abstraction
function ϕ that recursively updates the state as
st = ϕ(st−1, ot, at−1),
with s0 = ∅. The task instruction is provided separately to the agent as part of its prompt and is not
stored in the recurrent state. The recursive form is necessary because computing an abstraction di-
rectly from ct would itself require retaining the full history, defeating the purpose of the abstraction.
Our goal is therefore to identify a compact, recursively maintainable representation under which the
fixed agent remains competent. We next formalize this objective, then describe the program class
used to represent ϕ and the search procedure used to optimize it.
3.1
LEARNING A SUFFICIENT COMPACT STATE
An agent state is a compact abstraction of the interaction history
that preserves the performance of a reference agent acting on the
full history. An ideal agent state is the minimal such abstraction.
A natural notion of sufficiency would require the abstracted agent to reproduce the behavior of
the reference agent acting on the full history. In our setting, however, behavioral equivalence is
unnecessarily strong. Many tasks admit multiple successful trajectories, so two agents may take
different actions while achieving the same outcome. Moreover, matching trajectory distributions is
impractical for a black-box language model, since an abstraction can alter the agent’s subsequent
actions and thereby induce a different state distribution from that of the full-history agent.

3.2
RECURSIVE PROGRAM STATES
Optimizing Equation 1 requires choosing a function class for ϕ. We represent ϕ as a deterministic
Python program that maps the previous state, current observation, and preceding action to the next
state,
st = ϕ(st−1, ot, at−1).
(4)
Equation 4 has the form of a recurrent hidden-state update. At each step, the current observation and
preceding action are absorbed into st, after which the raw interaction history need not be retained.
Figure 1 contrasts this recursive state representation with the standard full-context agent. Unlike a
learned recurrent neural network, however, the update function ϕ is an explicit deterministic program
whose state variables and update rules are directly inspectable.
Programs are well suited to this setting because the abstraction primarily requires structured state
updates: parsing observations, maintaining task-relevant records, updating counters or flags, and
discarding text once its relevant information has been extracted. They also allow the abstraction to
be executed without an additional model call at each environment step.
We restrict ϕ to deterministic programs. Since the abstraction is applied recursively throughout the
interaction, stochastic errors introduced at one step could propagate through all subsequent states
after the original history has been discarded. Deterministic execution avoids this source of com-
pounding uncertainty.
Finally, the resulting abstraction is directly inspectable. Rather than representing state as an opaque
latent vector, the learned program explicitly specifies what information is retained, updated, and
discarded during the interaction. This makes the learned abstraction itself a readable hypothesis
about the information required by the agent.

We maintain a population of candidate state-update programs. Each candidate is evaluated by rolling
out the fixed agent while conditioning on its recursively maintained state. Parent programs are se-
lected by tournament selection, and children are generated through mutation or crossover. For muta-
tion, the proposer, implemented as GPT-5.6 Luna (OpenAI, 2026), receives a single parent program;
for crossover, it receives two parents and is asked to combine useful state components from both.
The proposer is additionally given the parent rollouts, corresponding full-history reference rollouts,
and textual feedback from a reflector model, also implemented as GPT-5.6 Luna. Comparing the ab-
stracted and reference rollouts helps identify performance-relevant information that may have been
lost by the current abstraction.
Feasibility.
We treat preservation of task performance as a constraint rather than allowing arbitrary
trade-offs between success and state size. Let J(π ◦ϕ) denote the task success of the fixed policy
under abstraction ϕ, and let T(ϕ) denote its mean policy input token usage. A candidate is feasible

where πfull is the full-history reference and ϕnaive is the initial naive aggregation program. Among
feasible candidates, smaller states are preferred. We use ϵ = 0.10 in all experiments.
Reflection and repair.
Because small edits to a program can induce large changes in agent be-
havior, a newly proposed child is evaluated before being admitted to the population. If the child
is infeasible, the reflector compares its rollout with the relevant parent and full-history reference
rollouts and identifies information that may have been lost or tracked incorrectly. The proposer
then revises the child using this feedback. We repeat this reflect-and-repair procedure until a fea-
sible candidate is found or a maximum of three repair attempts is reached. The original proposal
and all repaired variants are retained during this process, but are not individually inserted into the
population. Only the highest-fitness candidate from the repair process is added.
Each candidate is evaluated only when it is first produced. Its rollout, task success, token usage, and
fitness are cached and reused for subsequent selection, reflection, mutation, crossover, and repair.
After a fixed number of search iterations, we return the highest-fitness abstraction found during
the search. Search hyperparameters and the reflector and proposer prompts are provided in Ap-
pendix B.2 and C respectively. The first generated program is feasible in only 2 of 10 evaluated fam-
ilies, and all later improvements come from evolutionary proposals (Appendix F.1). Appendix F.2
reports the search cost per family. Algorithm 1 provides the complete search procedure.

EXPERIMENTS
4.1
SETUP
We evaluate whether the learned abstractions preserve agent performance while reducing the num-
ber of tokens ingested by the policy across two interactive environments: ALFWorld (Shridhar et al.,
2021) and ScienceWorld (Wang et al., 2022). In each domain, we learn a separate abstraction for
each predefined task family using training instances from that family and evaluate it on held-out
instances. The reference agent uses GPT-5.6 Luna (OpenAI, 2026) in a ReAct (Yao et al., 2023)
scaffold and conditions on the full interaction history throughout the episode. We use GPT-5.6 Luna
because our goal is to study state abstraction for a fixed black-box LLM policy rather than com-
pare language models, and Luna provides a strong agent policy at a tractable cost for the repeated
environment rollouts required by genetic search. Appendix. D.4 evaluates the learned abstractions
unchanged with a different policy model, Qwen-3.5-397B (Qwen Team, 2026).
ALFWorld.
ALFWorld (Shridhar et al., 2021) is a text-based household environment in which
an agent must complete high-level instructions through navigation and object interaction.
We
evaluate on its six task families:
pick and place simple, look at obj in light,
pick clean then place,
pick heat then place,
pick cool then place,
and
pick two obj and place. The benchmark provides held-out environments, allowing us to test
whether an abstraction learned for a task family transfers to new instances rather than memorizing
individual trajectories. We use 12 training instances per task family (drawn from the seen split)
and evaluate on all remaining held-out instances—the unused seen environments together with all
unseen environments—which range from 19 to 47 per family (47, 19, 46, 27, 34, and 29 for the six
families in the order listed above).
ScienceWorld.
ScienceWorld (Wang et al., 2022) contains interactive science tasks requiring an
agent to manipulate objects, inspect environments, and execute multi-step procedures. We evaluate
on four task families: lifespan, forces, classification, and genetics. These tasks
provide a qualitatively different setting from ALFWorld, with state requirements that include exper-
imental progress, object properties, and intermediate scientific observations. We use 24, 24, 32, and
6 training instances for lifespan, forces, classification, and genetics, respectively
(spread-sampled across each family’s variation range), and evaluate on 12, 12, 16, and 12 held-out
instances.
Baselines.
We compare against the full-history reference agent, an LLM Summarizer baseline, and
ACON (Kang et al., 2025). The LLM Summarizer uses the same runtime compression mechanism
as our ACON implementation but with a fixed summarization guideline: once the retained context
exceeds a token threshold, an LLM summarizes the older interaction history while preserving the
most recent turn verbatim. ACON additionally optimizes the summarization guideline using its
utility-maximization and compression-maximization stages before held-out evaluation. Because the
original ACON implementation targets different domains, we faithfully re-implement its UT→CO
optimization procedure for ALFWorld and ScienceWorld.
Evaluation.
We report task success on held-out instances and the mean number of policy input
tokens per step, averaged across evaluation episodes. For the LLM Summarizer and ACON, this
token count reflects only the compressed context provided to the policy and does not include the
additional tokens consumed by the runtime compressor.
4.2
RESULTS
Tables 1 and 2 compare our learned state abstractions against the full-history reference agent, a fixed
LLM Summarizer, and ACON.
ALFWorld.
Our learned abstractions remain close to the full-history reference across all six task
families while substantially reducing policy input for most tasks. The largest reductions occur for
Pick & Place, Heat & Place, and Cool & Place, where mean policy input falls by approximately 69–
71%. Clean & Place is reduced by 53%, while Look in Light and Two Objects admit much smaller
reductions. This variation suggests that the amount of information that must be retained is strongly
task dependent. The abstractions also generalize beyond the environments used during search. On
both seen and unseen environments, the agent using our learned abstraction shows no systematic
difference in success from the full-history agent (Appendix. D.3).

The same pattern appears in ScienceWorld. Our abstractions reduce mean policy

Longer horizons.
The full history grows with every step, while the state produced by ϕ grows far
more slowly. These savings therefore grow with the horizon. On a long-horizon BabyAI (Chevalier-
Boisvert et al., 2019) task, ϕ cuts mean policy input tokens by 95% (Appendix. E). Averaged over
three evaluation runs, the agent using ϕ shows no systematic difference in success from the full-
history agent (Appendix. D.1). The agent using ϕ is also the most consistent across runs, with a
run-to-run standard deviation of 0.7 pp against 1.0 pp for full history.
Comparison to compression baselines.
Relative to ACON, our method attains higher success on
four of six ALFWorld task families and uses fewer policy input tokens on three of six. Relative to
the fixed LLM Summarizer, it attains higher success on all six task families, uses fewer tokens on
three, and ties on one. On ScienceWorld, our method attains higher success than ACON on all four
task families and uses fewer policy input tokens on Lifespan and Classification. Compared with
the fixed LLM Summarizer, it attains higher success on two tasks, ties on Lifespan, and uses fewer
tokens on Lifespan and Classification. Our method also outperforms a token-matched recent-history
baseline by 10.0 percentage points, averaged over three evaluation runs (Appendix. D.2).
Policy input token usage and task success should not be interpreted independently: unsuccessful
trajectories may terminate earlier or make less progress and therefore consume fewer tokens. In
addition, both compression baselines require online LLM inference to generate summaries during
execution, whereas our learned abstraction is a deterministic Python program that does not require
LLM inference.

5
CONCLUSION
We asked what information an LLM agent actually needs to carry forward during interaction, rather
than treating its full history as state by default. We formulated agent state as a compact abstraction
of history that preserves the competence of a fixed reference agent, and instantiated this abstraction
as a deterministic recursive program learned through black-box search. Across ALFWorld and Sci-
enceWorld, the resulting states often preserve reference-level task performance while substantially
reducing mean policy input tokens, although the achievable reduction varies considerably across task
families. These results suggest that agent state is neither uniformly small nor identical across tasks,
but can often be represented by a much more selective recurrent summary than the raw interaction
history.

Summary.
Across task families, the learned programs repeatedly convert raw observations into
persistent structured variables and remove textual evidence once its relevant information has been
incorporated. The particular representation is strongly task dependent: ALFWorld abstractions pri-
marily recover navigation, search, object, and transformation state, while ScienceWorld additionally
requires entity resolution, relational structure, device configuration, and process variables. For the
two task families with little or no context reduction, the selected representations instead remain close
to bounded interaction histories.

B.1
GENETIC SEARCH PROCEDURE
Algorithm 1 gives the complete genetic search procedure described in Section 3.3.
B.2
SEARCH HYPERPARAMETERS
Table 5 reports the configuration used for genetic search. Unless otherwise stated, the same search
procedure is used across task families. We initialize the population with a single naive aggregation
function ϕ, use a state-size coefficient of λ = 5 × 10−4, and define a candidate as feasible if its task
success is within 10% of the full-history reference while using fewer policy input tokens than the
naive aggregation baseline. We run 10 search iterations for ALFWorld and 5 for ScienceWorld.
C
PROMPT TEMPLATES
Our genetic search uses an LLM reflector and proposer, both instantiated with GPT-5.6 Luna. In all
reported runs, the schema S is frozen and only the state-update program ϕ is modified. The reflector
receives the environment description, optimization objective, paired full-history and compact-state
rollouts, and an instruction to diagnose missing state information or compression opportunities. The
proposer then receives the current ϕ, the reflector feedback, example episodes, the frozen schema
fields, and the program contract, and proposes a targeted revision to ϕ.

LONG-HORIZON EVALUATION
E.1
HORIZON SCALING ON ALFWORLD AND SCIENCEWORLD
To measure how the policy input grows over an episode, we record the number of input tokens in
every policy call. At each step t, we average this number over all held-out episodes that are still
running at step t, and drop steps where fewer than three episodes remain. We then fit a least-squares
line to these averages as a function of t; its slope gives the number of tokens added to the policy
input per step.
Under full history, the policy input grows by 24–36 tokens per step in every family. Under ϕ, it
grows far more slowly, except in Two Objects and Forces, where ϕ is itself a bounded recent history
(Figure 3).
E.2
BABYAI SETUP
We evaluate on BabyAI-GoTo-v0 (Chevalier-Boisvert et al., 2019),1 which has 3 × 3 rooms and a
576-step cap. We use 12 training seeds for search and 50 held-out seeds for evaluation, with the same
policy, search settings and naive history aggregator as starting program as in the main experiments.
E.3
BABYAI RESULTS
Using the same procedure as in App. E.1, full history adds 48.5 tokens per step and reaches 27.5k
tokens per call at the step cap. ϕ stays at about 250 tokens per call from step 25 onward (Figure 4,
Table 11). The savings grow with the horizon: averaged over all policy calls, ϕ reduces mean policy
input by 95% relative to full history on BabyAI, compared with up to 71% on ALFWorld and 57% on
ScienceWorld, whose episodes are much shorter. Because full history grows with every step while
ϕ stays bounded, the longer the interaction, the larger the advantage of carrying a compact state
instead of the raw history. These savings come at no detectable cost in task success: the difference
from full history is not statistically significant (exact McNemar test on paired held-out episodes,
p = 0.18).

F.1
SEARCH STATISTICS
To assess how much improvement occurs beyond the initial LLM-generated program, we examine
the search records of all ten task families. A single LLM-generated program is generally insuffi-

from which all improvements arise, and repair turns many otherwise non-improving or infeasible

FIELD MASKING
To test which parts of the state the policy needs, we hide one group of fields at a time from the
policy. The learned ϕ runs unchanged and updates its full state at every step. Before each policy
call, we copy the state, delete one field group from the copy, and give the policy only this copy. The
full state is what ϕ receives at the next step. Field groups follow the categories of Table 13, and
we evaluate all eight task families whose ϕ is a structured program, on the same held-out instances,
policy and prompts as the main evaluation. The reference is the success of the unmasked ϕ, averaged
over the three evaluation runs of Appendix D.1. As a check, running the masking pipeline with no
field hidden reproduces the success of the unmasked ϕ. Table 14 reports the change in success for
each hidden field group.
Hiding seven of the eight field groups lowers success, with every corresponding confidence interval
excluding zero. The largest drops come from progress tracking, recent observations and exploration
memory. Progress tracking and exploration memory hold which sub-goal the agent is on and where it
has already searched, information a recent-history window can discard. Even fields the policy never
explicitly names can be essential. On Clean & Place, hiding the flags that record which objects
are already clean drops success from 0.73 to 0.04, as the agent finds and takes the object but keeps
cleaning it until the step limit. Target / goal is the only group with no measurable effect, consistent
with the task description already stating the goal in the policy prompt.
